`URunEncounterWidget`은 기존 Gameplay RunLayer에서 인카운터 선택·상점 구매 화면을 표시한다. `EncounterChoice`에서 Host가 제시된 후보 3개 중 하나를 선택한다. 기존 10전투 저장은 스킬상점·아이템상점·상점3 구성을 유지한다. 기존 Run·명시적 prototype·개발 협동의 스킬상점·상점3은 본인 캐릭터·개인 골드·현재/최대 HP, 근접 공격·신규 VFX 60종의 61후보에서 최대 5개 상품과 **리롤 1G**·1G HP 전체 회복 버튼을 표시한다. 상품 수는 가용 후보와 최대 5칸 중 작은 값이다. 상품 표시명은 스킬 에셋의 현재 이름을 우선하고 읽을 수 없으면 저장된 이름을 사용한다. 삭제 스킬은 기존 진열·카탈로그에서 제외하고 남은 상품의 가격·태그·가중치·리롤비를 유지한다. 현재 후보가 없는 사용자 지정 상점은 회복만 제공하고 리롤을 비활성화한다. 리롤은 전체 진열을 새로 구성하고 이전 상품의 재등장을 허용한다. 입장 때 비용은 1G로 초기화하고 성공할 때마다 버튼 비용을 1G씩 높이며 이어하기는 진열·현재 비용을 복원한다. 기존 저장의 확정 카탈로그·진열·가격은 유지한다. 카탈로그 없는 기존 schema 1은 고정 상품에서 삭제 스킬을 제외하며 새 리롤 기능을 소급하지 않는다. NPC 무대가 없는 기존 맵은 중앙 투명 공간을 줄이고 같은 장비·가방·상품 순서를 사용한다. 긴 상품명은 줄바꿈하고 각 목록은 스크롤한다. 상품 카드는 분류/스킬 아이콘·이름·가격·구매 버튼으로 구성한다. 조회 캐릭터는 `GetInventoryCharacterId`로 가져와 사망 후에도 장비·인벤토리를 표시하고 구매와 장비 드래그는 서버의 생존 Human 검증을 따른다. 패널 내용은 [8-2절](#8-2-gameplay-인벤토리와-설정-단축키), 지하 연출의 현재 검증 상태는 [HISTORY 9-36](HISTORY.md#9-36-2026-10-09-시드별-미로-계획과-구간-재사용)를 따른다.

아이템상점의 카드 전체에 `UShopItemTooltipWidget`을 연결한다. DemonicUI 테마의 설명 패널은 분류 아이콘·등급별 이름/색·가격/구매 상태·장착 위치/양손 여부·부여 스킬별 효과와 수치·인벤토리 장착 안내를 표시한다. 구매 버튼의 기본 텍스트 툴팁을 비워 골드 부족·판매 완료 버튼에서도 같은 카드 설명을 사용한다. 카드별 위젯을 재사용하고 구매·리롤 갱신에는 표시값을 새로 복사하며 숨김·서비스 전환 때 연결을 해제한다. 팝업 위치·DPI·마우스 이탈 종료는 Unreal 표준 툴팁이 담당한다.

툴팁의 아이템·등급은 복제된 상품과 `ItemRarities`, 새 스킬 수치는 사본의 `GrantedSkillBalances`를 사용한다. 현재 CSV나 원본 설명에 박힌 기본 위력으로 확정 수치를 대체하지 않는다. 효과 설명은 실제 스킬 실행 정의에서 구성하며 스킬 없는 장비에는 부여 스킬 없음으로 안내한다. 최초 설명 구성은 상점 갱신 시점에 수행하고 hover마다 에셋을 로드하지 않는다. 기본 상품의 스킬은 1개이며 사용자 지정 다수 스킬의 내용은 생략하지 않는다. [구현·컴파일 근거와 사용자 확인](HISTORY.md#9-43-2026-10-09-상점-아이템-설명-ui)

같은 상세 위젯의 `ConfigureInventory`·`ConfigureReward`는 가격과 구매 문구를 제외하고 장착/보관 상태 또는 보상 선택/수령 상태에 맞는 안내를 표시한다. 장비·가방·보상 카드는 비활성 상태에서도 설명을 조회하며 빈 슬롯에서는 연결을 해제한다. 상점·보상 목록은 스킬 이름/등급만 표시하고 상세 수치는 툴팁으로 확인한다. 보상 제목·카드는 지급 처리 중/수령 완료/미선택을 구분하고 남은 캐릭터의 수령 진행을 표시한다. 난이도 배율은 해당 구간 기본값을 100%로 안내하고 적 HP·적 속도·승리 골드임을 명시한다.

Development Editor / Win64 빌드 후 프로젝트 루트 PowerShell에서 실행한다. 빌드·프로젝트 파일 재생성 명령은 [README](../README.md#개발-환경)를 따른다.

```powershell
$editor = 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe'
$project = Join-Path (Get-Location) 'ProjectA.uproject'
$spec = 'Source/ProjectAEditor/UiScaffoldSpecs/MainMenuScreenWidget.json'
& $editor $project -run=GenerateUiScaffold -nop4 -unattended -NullRHI -DryRun "-Spec=$spec"
```

| 옵션 | 동작 |
|---|---|
| `-Spec=...` | 명세 경로. 생략 시 MainMenuRootWidget.json |
| `-DryRun` | JSON 구조 검사만 수행. Native 클래스 로드·Blueprint 컴파일·저장 검증은 제외 |
| 변경 옵션 없음 | 신규 WBP 생성. 기존 WBP는 수정하지 않음 |
| `-AddMissing` | 기존 속성·계층 유지, 누락 위젯만 추가 후 컴파일·저장. 기존 위젯 타입 불일치 시 거절 |
| `-Overwrite` | 기존 WidgetTree를 JSON 기준으로 재생성. Native 생성 모드에서는 소스 재작성도 허용 |

실제 생성은 위 명령에서 `-DryRun`을 제거한다. 누락 보완은 `-AddMissing`, 전체 재생성은 `-Overwrite`를 지정한다. 두 옵션은 병용할 수 없다. 기존 WBP의 부모가 nativeClass와 다르면 자동 변경하지 않고 중단한다. Overwrite 전에는 원본을 보존하고 Designer 수정 내용을 확인한다.

## 3 JSON 명세

최소 구조 예시:

```json
{
  "nativeClass": "UMainMenuScreenWidget",
  "nativeHeaderPath": "Source/ProjectA/UI/MainMenu/MainMenuScreenWidget.h",
  "nativeSourcePath": "Source/ProjectA/UI/MainMenu/MainMenuScreenWidget.cpp",
  "blueprintName": "WBP_MainMenuScreenWidget",
  "assetPath": "/Game/User_JeHoon/UI/MainMenu",
  "parentClass": "UCommonActivatableWidget",
  "generateNativeSource": false,
  "widgets": [{ "name": "RootOverlay", "type": "Overlay", "parent": "" }]
}
```

실제 화면 생성에는 저장소의 전체 명세를 사용한다. 위 예시는 루트만 포함한다.

| 최상위 필드 | 규칙 |
|---|---|
| `nativeClass` | 필수. U 접두사의 Native 클래스명, Reflection 검색에서는 U 제외 |
| `nativeHeaderPath`, `nativeSourcePath` | 필수. 기존 클래스 재사용 모드에서도 지정 |
| `blueprintName` | 필수. 생성·갱신 WBP 이름 |
| `assetPath` | 필수. `/Game/User_JeHoon` 또는 그 하위 경로 |
| `parentClass` | 필수. UUserWidget / UCommonUserWidget / UCommonActivatableWidget |
| `generateNativeSource` | 생략 시 true. 현재 프로젝트 명세는 false로 기존 클래스 재사용 |
| `widgets` | 필수. 1개 이상, 루트는 정확히 1개 |

기존 클래스는 Editor 빌드에 포함된 UUserWidget 계열이어야 한다. Native 생성은 UUserWidget 부모·PROJECTA_API만 지원하며 bind=true 항목의 BindWidget 속성을 생성한다. NativeConstruct는 로그만 추가하고 레이아웃을 생성하지 않는다. 신규 클래스는 소스 생성 → 프로젝트 파일 재생성 → Editor 빌드 → 도구 재실행 순서로 WBP에 연결한다.

### 3-1 위젯 필드

| 필드 | 규칙·기본값 |
|---|---|
| `name`, `type` | 필수. 이름 중복 금지, 지원 타입만 허용 |
| `parent` | 부모 name. 루트는 빈 문자열 또는 생략 |
| `bind` | 기본 false. true면 Designer 변수 등록. Native 생성 시 BindWidget 속성 생성 |
| `text` | TextBlock 초기 문자열 |
| `horizontalAlignment` | Fill / Left / Center / Right, 기본 Center |
| `verticalAlignment` | Fill / Top / Center / Bottom, 기본 Center |
| `padding` | 숫자 4개: Left·Top·Right·Bottom. Overlay/HorizontalBox/VerticalBox/Button/SizeBox 슬롯 또는 Border 콘텐츠에 적용 |
| `sizeRule`, `fill` | HorizontalBox 자식: Auto(기본) / Fill. Fill 비율은 양수, 기본 1 |
| `color` | 숫자 4개: RGBA. TextBlock·Image의 ColorAndOpacity, Border의 BrushColor에 적용 |
| `widthOverride`, `heightOverride` | SizeBox 크기. 지정 시 양수 |

### 3-2 타입·계층·바인딩

| 자식 허용 | 지원 타입 |
|---|---|
| 여러 개 | CanvasPanel, Overlay, HorizontalBox, VerticalBox |
| 최대 1개 | Button, Border, SizeBox |
| 없음 | TextBlock, EditableTextBox, Image, CommonActivatableWidgetStack |

C++ 타입은 각 이름에 U 접두사를 붙인다. 부모 누락·순환 참조·복수 루트·자식 수 위반·미지원 타입/sizeRule·잘못된 숫자 배열·양수가 아닌 Fill/크기는 생성 전에 거절한다.

바인딩 대상은 JSON name과 C++의 BindWidget/BindWidgetOptional 이름·타입이 일치해야 한다. bind=true는 Designer 변수 등록이며 런타임 버튼 동작을 자동 구현하지 않는다.

프리뷰 설정은 MainMenu에 PreviewStage 1개 배치 → PreviewActorClasses의 Warrior/Mage/Archer/Rogue 연결 → PreviewCamera·Slot0~3Anchor 조정 순서다. 메뉴 전용 Actor를 사용하며 전투 입력·AI·충돌 로직은 제외한다. Stage·클래스 누락 시 경고를 기록하고 카드 UI는 유지한다.

기준 거리·방향·간격은 `/Game/User_JeHoon/LEVEL/Core/MainMenu`의 Outliner에서 `MainMenuPreviewStage`를 선택하여 Details에서 수정하고 레벨을 저장한다. 전체 보기의 최종 거리는 실제 뷰포트와 몸체 경계에 맞춰 자동 보정하며 Edit 상세 카메라는 별도 거리 배율을 사용한다.

| 조절 대상 | Details 위치 | 현재값·조절 방향 |
|---|---|---|
| 전체 캐릭터 기준 거리 | `PreviewCamera` 컴포넌트 → Transform → Location X | 작성 기준 `-500`. 실제 전체 보기 거리는 몸체 투영·화면 폭에 맞춰 보정 |
| 캐릭터 기본 방향 | `Slot0Anchor`~`Slot3Anchor` → Transform → Rotation Z(Yaw) | 모두 `90°`. 각 슬롯의 기본 정면 방향 |
| 캐릭터 사이 간격 | `Slot0Anchor`~`Slot3Anchor` → Transform → Location Y | `-450 / -150 / 150 / 450`. 절댓값을 줄이면 가운데로 모임 |
| Edit 편집 확대 크기 | Actor의 MainMenu → Preview → Camera → `Focused Camera Distance Scale` | `1.15`. `1.05`는 더 가깝게, `1.3`은 더 멀게 표시. `1.0` 미만은 전신이 잘릴 수 있음 |

Stage는 BeginPlay에서 BP·레벨의 실제 카메라 world transform·FOV를 기준으로 보관한다. 전체 보기에서는 네 실제 메시 경계의 8개 꼭짓점을 투영하여 화면 좌우 10% 여백에 맞도록 기준 거리에서 줌아웃한다. 화면 크기·슬롯 생성/삭제·외형 변경 시 기준 카메라로 돌아가 실제 camera cache가 수렴한 뒤 다시 맞추므로 창 확대나 파티 초기화 후 이전 줌아웃이 누적되지 않는다. Focus는 보정된 전체 보기 시점을 저장하고 닫기/취소 시 복원하며 편집 중 창 크기 변경은 상세 카메라에 반영한다.

기준 카메라 X와 앵커 Yaw는 C++ 생성 기본값·작성 스크립트·저장된 MainMenu에 동일하게 적용한다. 네 직업 프리뷰 Blueprint와 현재 남녀 몸체의 `PreviewMeshTransform` 회전은 `0°`로 맞추고 앵커가 정면 방향을 결정한다. Stage는 몸체의 원래 회전에 임시 드래그 회전을 더하며, 편집 종료 시 원래 방향을 복원한다. 몸체 선택을 반복해도 회전 보정이 누적되지 않는다.

전사 `BP_WarriorMenuPreview`·마법사 `BP_MageMenuPreview`·도적 `BP_RogueMenuPreview`·궁수 `BP_PartyMenuPreview`는 선택한 Primitive 몸체와 원본 재질·공통 Idle을 사용한다. 남자는 `SKM_Primitive_Charater_01_Body`, 여자는 실제 원본 이름 `SKM_Primitive_02_Body`다. 마법사의 기본 스태프는 표시하지 않는다. ROG 의상 UI·착용은 중지하고 기존 103개 항목·스태프 원본 에셋은 향후 아이템용으로 보존한다.

생성된 캐릭터의 **Edit**로 연 오른쪽 편집창에서 ◀·▶ 버튼으로 남자·여자 몸체를 순환 선택한다. 순서는 카탈로그 `BodyVariants` 배열을 따르며 기본값은 남자다. 선택 즉시 같은 월드 프리뷰에 반영한다. 회전 버튼은 제거하고 미리보기 영역을 **우클릭한 채 좌우로 드래그**하여 캐릭터를 돌린다. 우클릭 해제·화면 닫기·마우스 캡처 상실 시 회전을 중지하며 편집 패널에서는 회전을 시작하지 않는다. **저장**은 초안에 반영하고 **취소**는 이전 선택을 복원한다. 편집 취소는 생성된 캐릭터를 유지하며 편집 전 이름·직업·몸체와 해당 몸체의 원래 방향을 복원한다. 기존 Designer WBP에도 C++ 공통 편집창을 적용한다. `BodyId`가 없는 이전 저장은 기본 남자로 해석한다. 2026-10-01 idle 루프 경계 4건 실패는 당시 이력이다. 최신 전체 메뉴에서 즉시 생성·3종 비율의 몸체 투영/idle·몸체 선택·실제 Slate RMB 회전/캡처 해제·Cancel의 여자 원래 방향과 저장/닫기·직접 조작/Start를 통과했다. 실제 이미지에서도 몸체·버튼·상세 화면의 가시성과 겹침 없음을 확인했다. [검증 이력](HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)

GameplayPlayerController는 화면별 SetInputMode를 추가하지 않으며 메뉴 travel의 잔여 IgnoreInput·초기 포커스만 복구한다. CharacterCreation의 Text_StartGameStatus는 선택 바인딩이며 누락 시 Native 표시 영역을 추가한다. 상세 배치·바인딩은 [PROJECT_PLAN](PROJECT_PLAN.md#6-gameplay-에셋과-배치)을 따른다.

## 7 기본 라운드 전투 UI

스킬 버튼은 현재 실행 정의의 AP/SAP 비용을 표시한다. 대상 패널의 현재 지정 유닛/타일과 예약 요약의 서버 확정 대상은 구분하고 타일은 좌표를 표시한다. 이동 포함 SAP 합계·내 스킬/이동/무행동 계획 수·준비 대기를 안내하며 버튼 문구는 무행동 준비·이동만 준비·서버 확인·관전·실행 상태를 따른다. 준비·준비 취소 버튼은 긴 안내를 스크롤해도 패널 하단에 유지한다. 표시 보완은 명령·GAS·준비 해제·서버 거절 조건을 변경하지 않는다. [구현·컴파일 및 미확인 범위](HISTORY.md#9-44-2026-10-09-전체-ui-가독성과-조작-피드백-폴리싱)

`UGameplayRootWidget`의 CombatLayer는 `UCombatRoundPlanningWidget`을 사용한다. 기존 `CombatHUDWidgetClass`와 `UCombatHUDWidget`은 Blueprint 참조를 위한 외형이며 순차 명령 버튼을 실행하지 않는다. 새 화면은 native 생성으로 동작하므로 WBP/JSON 재생성·기존 맵 재배치·Config 변경이 필요 없다. C++ 빌드 후 UE 재시작으로 리플렉션 변경을 반영한다.

전장에서 **적 또는 스킬이 요구하는 타일 한 번 클릭 → 실제 장착 스킬 버튼 클릭 → 준비 완료** 순서로 행동한다. 스킬 버튼을 누르면 자원·대상·좌표를 검사하고 바로 계획 적용을 요청한다. 상단 중앙은 라운드·생존 수·준비 유닛 수, 우측 상단은 선택 대상·적 HP와 계획을 표시한다. 좌하단 파티 카드는 이름·조작 주체·HP/AP/SAP·계획·준비 상태를 표시하고 현재 조작 유닛을 금색 테두리로 구분한다. 하단 중앙은 조작 캐릭터·장착 스킬·적용된 행동·오류, 우하단은 이동 예약과 준비 버튼을 배치한다. 인간 조작 가능한 캐릭터가 여럿인 기존 파티는 아군 클릭 또는 조작 캐릭터 목록으로 전환한다. 카드는 정보 표시용이며 초상화·확정 턴 순서는 추가하지 않는다.

스킬 버튼은 선택한 캐릭터의 실제 장착 DA와 태그가 지정된 소모품 재고의 정식 DA를 사용한다. 새 일반 Run은 비무장 기본 공격과 현재 장착 무기의 확정 스킬을 표시한다. 기존 Run·prototype·개발 협동은 당시 습득 목록을 유지한다. 기존 Blueprint·Snapshot·저장 fallback도 삭제 VFX 스킬을 제외하며 두 기본 공격·몬스터 전용 공격은 유지한다. 비무장 공격은 기존 기본공격의 표시명만 변경한 것이다. 무장착 자동 공격과 Encounter 진입 시 추가 스킬 추첨은 사용하지 않는다. `CanPlanCommand`가 거절하는 버튼은 비활성화하고 사유를 제공한다. 인간 조작이 허용된 모든 생존 유닛의 계획을 검사하며 스킬 미선택은 비용 없는 턴 넘기기로 허용한다. 선택한 스킬은 `스킬 선택 취소`로 해제할 수 있고 이동 예약은 유지된다. 미선택 상태와 파티 카드에는 턴 넘기기를 표시하며 이동만 예약했다면 SAP 1만 차감한다. 준비·저장 규칙의 회귀 범위는 [재검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)에 기록했으며 스킬별 표현 실행은 제외했다.

**이동 예약 · SAP 1**을 누른 뒤 강조된 아군 빈칸을 한 번 클릭하면 목적지를 예약한다. 계획 중에는 위치·자원 소모가 없으며 예약 좌표를 표시한다. `이동 예약 변경`으로 목적지를 바꾸고 `이동 예약 취소`로 제거한다. `목적지 선택 닫기`는 클릭 선택 모드만 닫고 기존 예약은 유지한다. 전원 준비 후 SAP 이동을 먼저 끝내고 AP 공격을 실행하며 도착 위치를 새 복귀 칸으로 사용한다. 상단에 SAP 이동 실행/AP 행동 실행 단계를 구분한다. 실행·서버 응답 대기 중 입력 잠금, 실패·중단 시 출발점 복원과 잠금 이후 자원 미환불은 유지한다.

입력은 `All / CaptureDuringMouseDown`을 사용하고 화면/빈 루트는 `SelfHitTestInvisible`, 조작 패널은 hit-test를 유지한다. Controller는 실제 뷰포트의 클릭만 전달하므로 패널 뒤 유닛·타일을 함께 선택하지 않는다. 현재 전투에 등록된 유닛과 Grid만 허용하며 이전 순차 타일 행동 API는 재활성화하지 않는다.

전투 타일의 기본 불투명도는 빈칸 0.24·점유 0.42·이동 가능 0.65·스킬 대상 0.78이며 원본 스프라이트 알파에 곱한다. 마우스 오버는 현재 값에 0.12를 더하고 최대 0.9로 제한한다. 전열 보호 색상은 기존 색을 25%만 혼합하며 선택·hover·보호가 바뀔 때 같은 갱신 경로로 복원한다. 원본 스프라이트·타일 좌표·클릭 판정은 유지한다. 수치는 `CombatGridTile|Presentation`에서 조절한다. ### 7-2 전투 디버그 도구

**스킬 구입**에는 **속성: 전체 / 물리 / 화염 / 냉기 / 번개 / 카오스 / 복합 / 미분류**, **방식: 전체 / 투사체 / 범위형 / 체인 / 근접공격 / 지원형 / 미분류**를 두 줄로 표시한다. 속성·방식·이름/에셋명 검색을 모두 만족하는 미보유 후보만 나열한다. 각 탭의 개수에는 다른 분류의 선택과 검색·보유 제외를 반영하며 선택 탭과 현재 조건을 강조한다. 좁은 창에서는 각 줄의 탭을 줄바꿈한다. 분류·안내와 목록은 바깥 스크롤에 포함하고 보유·구입 목록은 화면 높이에 따라 220 UI 단위 이상의 독립 스크롤 영역을 확보하여 줄바꿈이 목록을 가리지 않게 한다. 복합 속성은 각 속성과 복합 탭에 표시한다. 치유·보호막은 지원형을 우선하고 `Skill.Shape.Chain` 공격은 체인에 포함하며 체인 태그가 없는 빔은 범위형에 포함한다. 신규 `link` 5종은 기존 Beam에 Chain을 추가하여 체인에 표시하고 범위형에서 제외한다. 기본 두 공격은 방식 태그가 없어 미분류에 유지하고 신규 60종은 저장된 속성·효과·형태 태그로 분류한다. 개발용 일반 카탈로그는 유효 DA 76종(기본 2·몬스터 12·기존 VFX 60·무기 전용 2)을 읽는다. `Skill.Shape.Chain`과 `MaxTargets>1` 설정은 최근접 생존 미타격 적의 서버 연쇄에 연결한다. 현재 개발 시험값은 첫 대상을 포함한 `MaxTargets=4`, `JumpDistance=600cm`, `JumpIntervalSeconds=0.4`, `DamageMultiplierPerJump=0.8`이다. 점프 간격은 2026-10-06 연결 가시성 조정으로 기존 0.15초에서 늘렸다. 링크 5종의 저장 DA에 적용하며 최초 시전자·GAS 태그를 유지한 채 직전 피격 적에서 최근접 생존 미타격 적으로 연쇄한다. 원본 VFX·SFX 참조와 다른 스킬 속성은 유지하며 실제 검수 상태는 [TODO 23절](TODO.md#23-다중-체인-공격-확인)을 따른다. 삭제 스킬과 CSV 보류 에셋은 목록에 제공하지 않는다. 보유 목록은 필터와 관계없이 유지하고 필터 전환 시 후보 목록을 처음으로 스크롤한다. **장비 / 캐릭터·체력 / 스킬 타이밍** 화면에서는 분류 탭을 숨긴다.

네 번째 **스킬 타이밍** 탭에서 보유 스킬 선택 목록을 사용하며 독립 스크롤 영역에 선택한 스킬과 다음 수치를 표시한다. **임시 적용 / 원본 복원 / 설정값 복사**를 제공하며 정지된 계획 단계에서 같은 스킬 ID를 사용하는 아군·적군 전체에 적용한다. 해당 스킬을 사용하는 인간 아군의 계획·준비만 해제하고 적의 고정 행동은 새 수치로 실행한다. 장착·생성 이후에도 임시값을 유지하고 원본 DataAsset·Run 저장에는 쓰지 않으며 전투 초기화 시 원본으로 복원한다.

| 항목 | 의미 |
|---|---|
| 시전 대기 `WindupSeconds` | 시전 시작 후 효과·발사·타격이 발동할 때까지의 시간(초) |
| 효과 피격 대기 `EffectHitDelaySeconds` | 효과 VFX 활성화 후 효과 충돌·이동 시작까지의 시간(0~10초, 기본 0) |
| 효과 판정 기간 `EffectDuration` | 피격 대기 이후 효과 충돌을 검사하는 활성 기간(초) |
| 투사체 속도 `ProjectileSpeed` | 공통 속도 배율 적용 전 작성 속도(cm/s). 기본 배율 0.5 적용값과 작성 속도 변경에 따른 사거리 영향을 함께 안내 |
| 검 타격 기간 `WeaponTraceDuration` | 검 궤적을 검사하는 활성 기간(초) |

각 수치는 해당 스킬의 실행 경로에 적용하며 투사체 수명은 이 편집 영역에서 변경하지 않는다. 효과 내부의 실제 접촉 프레임을 자동 분석하지 않으므로 재생 화면·피해 시점을 확인하며 직접 조정한다. 설정값 복사는 값 전달용이며 원본 에셋 반영이나 모든 스킬의 타이밍 검증을 의미하지 않는다. 기존 카탈로그 생성은 폐기했으며 새로운 VFX 스킬의 데이터 작성은 [도입 기준](TODO.md#6-신규-에셋-선정과-도입)을 따른다.

대상 목록은 아군·적군·사망 여부를 표시하고 이름이 없으면 클래스 이름으로 구분한다. **캐릭터·체력**의 최대/현재 HP 입력과 전부 회복은 계획 단계의 생존 캐릭터만 허용하며 `1 ≤ 현재 HP ≤ 최대 HP ≤ 1,000,000`을 검증한다. 입력 초안은 주기적 갱신에서 유지하고 대상 변경·적용 후에 실제 수치로 갱신한다. 적용 시 스킬·장비·행동 계획은 유지하고 아군 준비 완료를 해제한다.

같은 탭에서 아군 직업·적 종류별 생성 버튼, 총 8명 제한과 비활성 사유를 표시하고 생성한 양 진영 캐릭터를 즉시 선택한다. **아군 부활 창 열기**는 사망 아군의 현재 스킬·장비를 유지하여 부활하며 **전투 초기화**는 추가 캐릭터까지 처음 구성으로 복원한다. 캐릭터 조작 영역은 별도로 스크롤한다. 기존 계획 화면은 CommonUI의 Slate 스위처가 준비된 `NativeConstruct`에서 스택에 추가하며 패널 배경은 뒤쪽 전장 클릭을 차단한다.

## 8 시작 메뉴 설정

MainMenu의 Options는 native `UOptionsWidget`으로 언어·화면·그래픽 설정을 표시한다. 기존 메뉴의 CommonUI 입력·뒤로 가기·포커스를 사용한다. 화면은 Unreal `UGameUserSettings`, 언어는 엔진 Internationalization과 같은 사용자 설정 파일을 사용한다.

| 항목 | 표시·동작 |
|---|---|
| 언어 | 한국어(기본)·English. 적용 및 저장 후 표시 문구를 갱신하고 다음 실행에 유지한다 |
| 화면 모드 | 전체 화면·테두리 없는 전체 화면·창 모드 |
| 해상도 | 전체 화면은 엔진이 반환한 지원 목록, 창 모드는 엔진의 창 크기 목록을 사용한다. 중복을 제거하고 현재의 유효한 해상도도 보존한다 |
| 테두리 없는 전체 화면 | 게임 창이 위치한 모니터 또는 가장 가까운 모니터의 바탕 화면 해상도로 고정한다. 해상도 선택을 비활성화하고 사유를 표시한다 |
| 그래픽 품질 | 낮음·중간·높음·최고·시네마틱의 5단계(0~4). Landscape·렌더 배율을 포함한 전체 세부 품질을 비교하고 프리셋과 다른 사용자 설정은 프리셋을 고르기 전까지 유지한다 |
| 수직 동기화 | VSync 켜기·끄기 |

### 8-1 적용과 복원

- 화면을 열면 현재 설정을 읽는다. 항목 선택은 초안만 변경하며 적용 전 닫기는 초안을 버린다.
- 언어·품질·VSync만 변경하면 적용 시 바로 반영·저장한다. 기존 사용자 품질은 프리셋을 명시적으로 선택한 경우에만 일괄 변경한다.
- 해상도·화면 모드가 바뀌면 `RequestResolutionChange`로 전체 변경을 저장하지 않고 미리 적용한다. 확인 전에는 `Alt+Enter` 전환용 기본 전체 화면 모드도 변경하지 않는다. 15초 동안 **유지 및 저장**·**이전 설정으로 복구**와 남은 시간을 표시하고 설정 편집을 잠근다.
- 제한 시간 안에 **유지 및 저장**을 선택하면 현재 해상도·화면 모드·품질·VSync와 선택 언어를 확정·저장한다. 언어는 화면 확인 중에는 바꾸지 않으며 취소·시간 초과 시 기존 언어를 유지한다.
- 복구·시간 초과·뒤로 가기·닫기·위젯 비활성화/제거는 미리 적용한 화면·세부 품질·VSync를 모두 이전 값으로 복원한다. 정상 게임 창 종료 요청도 종료 전에 복원한다. 복원값을 다시 저장하여 미확인 변경이 다음 실행에 남지 않게 한다.
- 확인 중 뒤로 가기는 복원 후 설정 화면으로 돌아오며 다시 뒤로 가기를 누르면 메뉴로 나간다. 첫 확인 포커스는 **이전 설정으로 복구**에 둔다.
- 확인 중에는 미확인 설정을 저장할 수 있는 엔진의 `Alt+Enter`·`F11` 전체 화면 전환을 잠시 비활성화한다. 확정·복원 후 두 단축키의 이전 활성 상태를 복구한다.
- 확인 시간은 게임 시간 배율과 무관한 실제 경과 시간으로 계산한다. 확인·복원 후 선택값과 포커스를 현재 설정에 맞춰 갱신한다.

해상도와 전체 화면 전환의 시각 평가는 아직 확인되지 않았다. 독립 게임 창의 옵션 저장·복원 자동화 결과는 [재검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)에 기록했다. 해상도별 시각 품질은 해당 검사에 포함되지 않았다.

### 8-2 Gameplay 인벤토리와 설정 단축키

스킬 탭·선택 상세·장비/가방 툴팁은 같은 `SkillDetails`로 저장 사본의 확정 수치와 효과를 표시한다. 선택 상세 영역은 높이 220 UI 단위 안에서 스크롤하고 캐릭터·분류·아이템 선택이 바뀌면 처음으로 이동한다. 가방 행은 선택 또는 장착 미지원 상태를 글자로 함께 표시한다. 빈 슬롯·사망 캐릭터는 장착 안내를 구분하며 실제 드래그 권한은 기존 서버 판정을 유지한다.

상점·인벤토리·장비는 `RunItemPresentation`으로 저장된 등급 색과 흰색·초록색·파란색·보라색·주황색 이름을 함께 표시한다. 새 일반 Run의 시작 무기·무기 상품은 CSV에서 고정한 에셋별 장비 등급과 무기 태그·장비별 스킬 등급 가중치에서 추첨한 스킬 1개를 표시하며 새 판매 목록의 방패는 등급만 표시하며 기존 보유 탄약·기타의 저장된 표시도 유지한다. 상점 카드와 아이템 상세/툴팁은 저장된 사본 결과를 사용하며 구매·재장착·Continue로 다시 추첨하지 않는다. `SkillBalanceVersion=1`의 사본은 `GrantedSkillBalances`에서 스킬 고유 등급·위력·AP/SAP를 읽어 확정 스킬명과 함께 표시한다. 장비 등급과 스킬 등급은 별개이며 UI가 현재 CSV를 다시 읽어 수치나 확률을 만들지 않는다. 버전 0은 기존 표시를 유지한다. 기존 저장의 등급·스킬은 현재 CSV로 재분류하지 않는다. 스킬 탭은 같은 스킬을 한 번만 표시하고 현재 장착 출처의 무기 이름·슬롯을 함께 보여준다. 출처는 개별 `ItemIndex`로 구분하고 양손의 같은 사본은 한 번만 센다. 클라이언트에는 `FGameplayViewState.ItemRarities`로 공통 표시 메타데이터를 전달하며 로컬 기본 후보로 대체하지 않는다. 버전 0 아이템은 기존 표시를 유지한다. 최신 실제 화면·다수 스킬 스크롤·선택·Continue는 [TODO 29절](TODO.md#29-무기-랜덤-스킬과-아이템-등급-기획)의 사용자 확인이 남아 있다.

Gameplay의 전투·지도·결과 화면에서 `I`로 인벤토리를 열고 다시 누르면 닫는다. 상점에서는 이미 표시된 가방으로 포커스를 이동하며 별도 인벤토리 창을 열지 않는다. 상점 진입 시 이전 인벤토리 창도 닫는다. `Esc` 또는 `O`는 기존 CommonUI 설정 경로를 실행하며 인벤토리가 열려 있으면 설정으로 전환한다. 설정에서 `Esc` 또는 `O`를 다시 누르면 닫고, 화면 변경 확인 중에는 먼저 이전 설정을 복구한다. 펼쳐진 선택 목록은 첫 `Esc`로 닫힌다. 설정 중 `I`는 설정을 닫거나 초안을 변경하지 않는다.

`UGameplayRootWidget`의 CommonUI 지속 액션과 별도 `UtilityLayer`를 사용한다. 창이 열리면 배경 UI와 전장 입력을 잠그고 닫으면 기존 화면으로 복귀한다. 창은 로컬 표시이며 진행 중인 전투·협동 세션을 일시정지하지 않는다. MainMenu의 기존 버튼·뒤로 가기는 유지한다.

`UInventoryWidget`은 상점과 같은 `UCharacterEquipmentPanel`·`UCharacterInventoryPanel`을 나란히 표시한다. 현재 참가자 캐릭터의 이름·직업·개인 골드·보유/장착 스킬과 아이템의 표시 이름·장착 상태를 조회한다. 새 Run은 시작 장비부터 CSV의 `게임 내 이름`을 사용하고 기존 저장은 저장 당시 이름을 유지한다. 같은 종류도 개별 사본으로 드래그하며 장착 사본과 가방 사본을 구분한다. 사망 후에도 조회할 수 있다. 명시 스킬 목록이 없는 이전 저장은 권위 Run의 실제 파티 목록으로만 해석하고, 협동 클라이언트는 확인 불가 안내를 표시한다.

`UCharacterInventoryPanel`의 가방은 포더킹 참고 이미지의 목록 구성으로 표시한다. 가로 **전체 / 무기 / 방패 / 탄약 / 기타 / 스킬** 탭에 아이콘과 개수를 표시하며 아이템 분류는 기존 `Item.Weapon` 계층의 GameplayTag 조건을 사용한다. 장착 사본을 제외한 가방 아이템마다 분류 아이콘·저장된 표시명·`(1)`을 가진 행을 만들고 가리킴·선택 상태를 강조한다. 같은 에셋의 사본을 합치지 않으며 원래 `ItemIndex`와 현재 장비 `Revision`을 드래그 요청에 유지한다. 빈 목록도 장비 해제 Drop을 받는다.

아이템 행을 클릭하면 실제 이름·분류·저장 카탈로그의 참고 가격·장착 지원 여부·허용 슬롯을 표시한다. 아이템 상점에서는 별도의 판매 금액과 판매/확정/취소 버튼을 표시한다. 긴 상세는 위에서 스크롤하며 판매 버튼은 상세 하단에 고정한다. 선택·분류·표시 갱신으로 확인을 취소하고 판매 요청 전에 선택을 비워 삭제 인덱스의 다음 아이템이 자동 선택되지 않게 한다. 판매 대상·가격·저장은 [상점 계약](PROJECT_PLAN.md#3-2-상점-인카운터)을 따른다. 새 일반 Run의 확정 장비/스킬 등급과 서버가 저장한 스킬 위력·비용을 표시하며 UI에서 추가 피해 수치나 추첨 결과를 만들지 않는다. 스킬 목록은 스킬 탭으로 이동하고 실제 장착 DA·기존 저장의 권위 fallback을 유지한다. 장비창은 기존 슬롯 구성을 유지하고 원본 DemonicUI 아이콘을 직접 참조한다. native 구성으로 반영하므로 WBP 재생성은 필요 없다. 새 목록의 작동·가독성 확인 결과는 [검증 이력](HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)을 따른다.

장비창의 무기 2칸·투구·장갑·신발·갑옷·목걸이 각 1칸·반지 2칸은 실제 Run 장착 상태를 표시한다. 새 Run은 직업별 시작 장비를 장착하며 양손 장비는 두 슬롯에서 같은 사본으로 표시한다. 현재 판매 CSV의 49개는 모두 장착 프로필을 지원한다. 미지원 240개는 판매 목록에서 제거했으며 기존 보유 사본은 보존한다. 본인 생존 Human은 **상점 페이즈에서만** 아이템→장비 슬롯 장착·장비→가방 해제·호환 장비끼리 교체할 수 있다. 단계·권한·Revision·태그 조건을 서버가 재검사하며 저장 실패·잘못된 대상·취소 시 상태를 유지한다. 기존 보유 미지원 아이템은 장착 불가 안내를 유지한다. 새 일반 Run은 장착 무기 사본의 사용 스킬을 갱신한다. 장비 속도 보정·아이템 소비는 미구현이다. 힘·민첩·지능 등 추가 능력치 보정은 도입하지 않는다. 목표 Run의 회복 소모품은 별도 태그 재고와 전투 버튼으로 제공하며 기존 CommonUI 입력·DPI·테마를 유지한다. 2026-10-01 실행에서 제외한 장비 조작과 최신 목록 UI 후속 검수의 상태는 [검증 이력](HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)을 따른다. 이전 구현·저장 회귀는 [당시 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)으로 구분한다.

### 8-3 개인 골드 상시 표시

Gameplay 좌측 상단에 `보유 골드 10G` 형식의 작은 패널을 표시한다. 지도·상점·전투·결과에서 인벤토리와 같은 소유 캐릭터의 확정 잔액을 사용하며 구매·회복·리롤 저장 성공 또는 복제 뷰 도착 시 갱신한다. 실제 0G는 표시하고 캐릭터 미확정·Run 없음·협동 대기실에서는 숨긴다. 패널은 마우스 입력을 통과시키고 인벤토리·설정 레이어 아래에 배치한다. 골드 값·보상 저장 회귀는 [재검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)에 기록했으며 패널 가독성 평가는 포함되지 않았다.

## 9 DemonicUI 공통 테마

공통 스크롤바는 두께 10 UI 단위·부드러운 휠 이동·포커스 이동 시 자동 스크롤을 사용하며 끝의 과도한 빈 공간 이동을 막는다. 기존 휠 입력 소비 정책과 명시적인 즉시 포커스 스크롤은 유지한다. 메뉴의 설정·종료 표시는 한국어로 통일하고 이어하기 비활성 사유를 제공한다. Gameplay 개인 골드 패널 아래에는 `I` 인벤토리·`Esc/O` 설정 단축키를 표시한다.

기존 DemonicUI의 암갈색 패널·청동 장식·붉은 활성 버튼·청회색 성 배경을 현재 사용 중인 화면에 적용한다. 기준 구현은 [DemonicUITheme.h](../Source/ProjectA/UI/Theme/DemonicUITheme.h)·[DemonicUITheme.cpp](../Source/ProjectA/UI/Theme/DemonicUITheme.cpp)다. 원본 `/Game/DemonicUI` 에셋은 참조만 하며 수정·이동·복제하지 않는다. WBP·JSON·맵·Config 재생성은 필요하지 않다.

### 9-1 적용 구조

- `UDemonicUITheme`의 클래스 기본 객체가 `FObjectFinder`로 텍스처를 읽고 `UPROPERTY` 참조를 유지한다. 브러시가 사용하는 텍스처의 가비지 수집 방지와 쿠킹 의존성 연결을 위한 구조이며 패키지에서의 실제 표시 확인은 별도 수행한다.
- `ApplyControls`가 기존 WidgetTree의 버튼·콤보박스·체크박스·입력창·스크롤바·일반 글자에 공통 외형을 적용한다. 화면별 배경·패널·제목·주요 버튼은 명시적으로 지정한다. 콜백·바인딩·활성화 조건은 기존 화면이 관리한다.
- 긴 버튼은 `Button_A_Long_Ready/aimed/active`, 짧은 기호 버튼은 `Button_A_Lil_Ready/aimed/active`를 사용한다. 일반·가리킴·누름·비활성 외형을 구분하고 주요 실행 버튼은 붉은 배경을 사용한다.
- 패널은 `GUI_Elements/pop_up_window_B`, 배경은 `Backgrounds/Background`, 구분 장식은 `GUI_Elements/Top_frame_m`을 사용한다. VSync 체크는 `Red_buttons/Button_tiny_ready`·`Button_tiny_ok`로 표시한다.
- 장비창은 원본 `Widgets/WB_Equipment`의 슬롯·제목 구성을 사용하고 인벤토리 가방은 [8-2절](#8-2-gameplay-인벤토리와-설정-단축키)의 분류 탭·목록 행·선택 상세를 사용한다. `GUI_Elements/Icon_frame`·`bar_button_mid`·`equipment_male`과 부위별 아이콘을 원본 경로에서 참조한다. 실루엣은 표시용 배경이며 선택한 몸체의 실제 모델이 아니다. 아이템 분류 아이콘은 카탈로그의 GameplayTag로 결정하고 내부 영역·빈 슬롯·보유 아이템의 공통 스타일을 분리한다.
- native 콤보박스는 `UDemonicComboBoxString`으로 생성하여 Slate가 선택값과 펼침 목록을 만들기 전에 밝은 글자색을 설정한다. 목록 행·선택·가리킴·스크롤바도 공통 색상으로 표시한다.
- 명시적인 경고·직업 색상은 보존한다. 장식 이미지는 입력을 받지 않으며 프리뷰용 투명 영역과 전투 중앙의 월드 입력 영역에는 불투명 전체 배경을 추가하지 않는다.
- 중앙 패널은 [10절](#10-공통-dpi와-전투-화면-배치)의 프로젝트 공통 DPI를 사용한다. MainMenu의 메뉴와 명시적인 관리 이어가기 패널은 같은 가로 배치를 유지하며 기존 관리 이어가기 표시 조건을 유지한다. 상점·인벤토리·시작 메뉴·모드 선택·항복 확인·설정/화면 유지 확인 패널은 공간이 부족할 때만 `ScaleBox`의 `DownOnly`로 추가 축소한다.
- 기존 `WBP_RunMapWidget`·`WBP_EncounterResultWidget`은 알려진 `ContentBox`·`Overlay` 구조에서 현재 컨트롤을 유지한 채 배경·중앙 프레임을 적용한다. 다른 Designer 계층은 재작성하지 않으며 컨트롤 스타일만 적용한다.

### 9-3 반영과 검증

C++ 파일 추가에 따른 프로젝트 파일 재생성·Development Editor / Win64 빌드 후 UE를 재시작한다. 명령은 [README](../README.md#개발-환경), 2026-10-01 실행 범위는 [재검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 이전 설정·전투 실행 결과를 새 테마의 가독성·입력·쿠킹 성공 근거로 사용하지 않는다.

에셋 선정 시 패키지 내부 썸네일과 직렬화된 `SizeX`·`SizeY`를 정적으로 조사했다. Unreal의 PNG 썸네일 저장 방식에 맞춰 조사 이미지의 R/B 채널을 보정했으며 게임 텍스처는 변환하지 않았다. 조사 산출물은 `Saved/Automation/DemonicUI`에 있고 실제 UI 실행 화면은 포함하지 않는다.

## 10 공통 DPI와 전투 화면 배치

### 10-1 공통 배율

프로젝트 전체 UI는 [DefaultEngine.ini](../Config/DefaultEngine.ini)의 `/Script/Engine.UserInterfaceSettings`에서 `UIScaleRule=ScaleToFit`, `DesignScreenSize=(X=1920,Y=1080)`, `ApplicationScale=1`을 사용한다. DPI는 뷰포트 크기에 따라 UI의 글자·버튼·간격을 함께 조절하는 배율이다. 가로·세로를 다른 비율로 늘리지 않으며 기기 종류나 특정 해상도에 따른 별도 배치 규칙은 두지 않는다.

뷰포트 너비를 `W`, 높이를 `H`라고 할 때 공통 배율은 `min(W / 1920, H / 1080)`이다. 뷰포트 픽셀 기준이며 모니터의 물리적 크기와는 구분한다.

| 16:9 뷰포트 | 공통 배율 | 1920×1080 대비 UI 크기 |
|---|---|---|
| 1280×720 | 2/3 | 약 66.7% |
| 1920×1080 | 1 | 100% |
| 2560×1440 | 4/3 | 약 133.3% |
| 3840×2160 | 2 | 200% |

모든 화면에 같은 공통 DPI 공식을 적용하고 각 화면의 정렬·스크롤·바인딩을 유지한다. 메뉴·설정·개발용 협동·RunMap·결과는 개별 배율을 추가하지 않는다. 상점 3열·인벤토리 2열은 화면 공간이 부족할 때에만 `ScaleBox`의 `DownOnly`로 축소하고 긴 목록은 내부 스크롤로 표시한다.

### 10-2 전투 배치와 카메라

### 10-3 반영과 검증

최신 C++ 빌드와 Config 변경을 반영한 뒤 UE를 재시작한다. 기존 WBP·맵을 유지한다. 2026-10-01 설정 복원은 당시 이력이며 화면 비율·카메라 배치 품질을 포함하지 않았다. 2026-10-04 실제 Windows 인벤토리 4/4에서 3종 비율의 목록·구매·Slate 장착·조회/거절·O/Esc 창/설정 정확 복귀와 27장 가시성을 확인했다. 게임 창의 적용/취소/15초 만료/설정 재로드와 메뉴 전체 검수도 통과했다. 환경 14맵의 실제 타일 입력·HP 좌표 보완과 프레임 측정 범위는 [최신 이력](HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)을 따른다.

## 11 네 직업 선택과 기본 능력치

`FCharacterPartyDraft`가 직업 목록과 독립적인 4슬롯·생성·삭제·직접 조작 선택을 관리한다. 슬롯별 위젯 참조를 묶으며 기존 WBP 이름·이벤트·Blueprint 읽기 전용 배열은 호환 표시로 유지한다. 라운드 UI는 `FCombatPlanningRefreshState`로 계획·스킬·소유권·연결·AP/SAP·이동 범위·ASC 태그·타일 변화를 관찰하고, 동일 상태에서는 검증과 위젯 갱신을 생략한다. 타일 강조는 변경분만 반영한다. [구현·검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)

캐릭터 생성의 선택 순서는 전사 `Warrior` → 마법사 `Mage` → 궁수 `Archer` → 도적 `Rogue`다. 이전 테스트 직업은 선택 목록에서 제거한다. 이름 편집·취소·1~4명 생성과 원래 소유권은 유지한다. ClassInfo는 직업 정의의 HP 100·속도 10과 기존 전투 클래스에서 해석한 AP/SubAP·시작 스킬을 표시한다. 이 수치는 현재 시작값이며 최종 직업 밸런스가 아니다.

표시 정보의 기준은 `UProfessionBase`와 네 C++ 자식 클래스다. 실사용 및 `Validation/T12` WBP의 기존 WidgetTree·배치·스타일·바인딩을 유지한다. MainMenu 프리뷰 맵은 Warrior/Mage/Rogue를 각각 직업별 MenuPreview에, Archer를 기존 `BP_PartyMenuPreview`에 연결한다. 네 직업의 몸체 선택은 같은 카탈로그를 사용한다. 개발용 협동은 참가자마다 궁수 한 명을 생성한다.

지원하지 않는 이전 직업의 Continue는 해당 ID와 오류를 표시하고 저장 원본·현재 Run을 유지한다. 새 직업으로 자동 변환하지 않는다. Editor 빌드와 저장 후 에셋 재로드에서 새 직업 맵·16개 라벨을 확인했으며 직업 기준은 [기획](GAME_DESIGN.md#6-2-네-직업과-공통-시작-능력치)을 따른다. 구직업 오류 화면의 실제 조작은 위 에셋 재로드 검사에 포함되지 않았다.

## 12 시작 모드 선택과 항복 확인

일반 싱글 새 게임의 CharacterCreation은 첫 진입에 직접 조작 선택이 없으며 안내를 표시하고 시작 버튼을 비활성화한다. 생성 카드의 Edit/X 행에 네이티브 `직접 조작` 버튼을 추가한다. 한 명을 선택하면 해당 버튼은 `선택됨`, 직업명 옆은 `직접 조작`으로 표시하며 다른 생성 카드는 `AI`로 표시한다. 선택 카드 삭제 시 선택을 해제하고 시작을 다시 막는다. 직업·이름 편집은 선택을 유지하고 화면을 나갔다가 다시 들어오면 초안·선택을 초기화한다.

Designer와 native 경로 모두 기존 `SlotActionBox` 행을 사용하므로 WBP·생성 명세 재생성은 필요하지 않다. 선택 저장·AI 전투와 기존 저장 호환은 [PROJECT_PLAN](PROJECT_PLAN.md#5-저장과-멀티플레이-연결-경계), 직접 조작 선택·AI 진행의 이전 실행 결과는 [이전 검증](HISTORY.md#9-10-싱글플레이-직접-조작-캐릭터-선택)을 따른다.

게임 시작은 `UGameModeSelectionWidget`의 싱글플레이/멀티플레이 선택을 거친다. 첫 포커스는 싱글플레이이며 멀티는 기존 지원 조건에 맞을 때만 활성화한다. 같은 PC·LAN의 2~4인 개발용 방과 Steam 미지원 안내를 표시한다. 모드 선택·하위 화면 전환 중 첫 화면이 중복 노출되지 않아야 하며 뒤로가기 후 다시 진입할 수 있어야 한다. 멀티 접속을 시작한 뒤 취소/나가기는 기존 세션 정리·MainMenu 복귀를 따른다.

2026-10-04 최신 HP/VFX 보완을 포함한 동일 cooked 바이너리의 289개 CSV/61스킬/세 DA 로드·격리 저장 작성/Continue → 보상 → `Shop_02` → `Combat_02`와 실제 Quit 버튼의 자연 종료·종료 코드 0을 통과했다. Editor writer의 cooked 재개는 FText 속성 크기 차이로 실패한 별도 이력이며 기존 사용자 저장은 이 패키지 검수에 사용하지 않았다. [실행 근거](HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)

별도 Editor 검수에서는 기존 Version 5 사용자 저장의 바이트 동일 UUID 사본을 실제 메뉴 Continue로 복원했다. 원래 파티 4명·전투 8유닛의 HP/AP/SAP·소유권·명령과 카탈로그를 공개 복원 결과와 비교하고 새 PNG의 머리 위 HP/몸체/UI를 확인했다. 퇴역 스킬 후보의 177→1 이행은 메모리에서 수행하며 원본 49파일/설정 1파일과 사본 바이트를 보존하고 소유 사본을 정리했다. 원본 슬롯 덮어쓰기·Editor 저장의 cooked 호환은 이 결과에 포함하지 않는다.

이어하기 옆 항복 버튼은 104×40 UI 단위이며 공통 DPI를 따른다. `URunSurrenderWidget`은 현재 싱글 여정을 포기하면 이어갈 수 없음을 알리고, 돌아가기에 기본 포커스를 둔다. 취소·CommonUI 뒤로가기는 저장을 변경하지 않는다. 모달 배경은 아래 메뉴의 클릭을 막고 제출 중 중복 확인을 차단한다. 오류는 확인창에 표시하며 저장이 바뀐 경우 창을 닫고 최신 대상으로 다시 확인해야 한다. 삭제 성공 후에는 창을 닫고 이어하기/항복을 비활성화한다. 저장 범위와 기본안의 근거는 [PROJECT_PLAN](PROJECT_PLAN.md#5-저장과-멀티플레이-연결-경계), 검증은 [이전 검증](HISTORY.md#9-8-시작-모드-선택과-싱글-여정-항복)을 따른다.

## 13 전투 승리 보상

`UEncounterResultWidget`은 무기 스킬 획득 버전 1의 일반 Target PvE에서 아이템 카드 3개·등급·저장된 스킬·선택과 무관한 공통 골드·개인 잔액을 표시한다. 보상 스키마 2는 다음 PvE 승리부터 적용하며 하나를 선택하면 아이템 1개와 표시된 골드를 함께 수령한다. 아이템은 가방에 추가하고 자동 장착하지 않는다. 공통 골드는 해당 묶음의 저장된 최소~최대값 사이 정수이며 새 기본 난이도의 범위는 [PROJECT_PLAN 5-1절](PROJECT_PLAN.md#5-1-목표-run과-회복-시험-데이터)을 따른다. 아이템과 골드 추첨은 결과에 저장하여 화면을 열거나 Continue할 때 바꾸지 않는다.

새 기본 난이도는 결과 뷰의 `VictoryRestHP`로 생존 파티에 휴식 회복이 적용되었음을 별도로 표시한다. 표시량은 구간별 최대 회복량이며 성장 후 최대 HP에서 제한되고 사망자를 부활시키지 않는다. 회복은 결과 저장 시 이미 반영되므로 아이템 선택에 종속되지 않는다. Snapshot·패배·이전 난이도·맞춤 정의에는 이 안내를 추가하지 않는다. 지도 노드 이름은 저장된 구간 이름·묶음 번호·PvE/로컬 Snapshot을 사용하며 노드 ID·순서와 80단계 진행은 유지한다.

이미 저장된 보상 스키마 1과 무기 스킬 획득 버전 0의 Target·prototype·개발 협동은 기존 골드 카드 3개를 표시한다. Target의 묶음별 값과 기존 10전투 경로의 각 5~15G 독립 추첨을 보존한다. 제출 중에는 카드를 비활성화하고 저장·복제 반영 후 선택한 카드에 `획득 완료`를 표시한다. 실패 시 오류와 재선택을 제공하며 본인 미수령 캐릭터가 여러 명이면 다음 캐릭터로 전환한다. 현재 Human이 모두 수령해야 Host의 Continue가 활성화되고 다른 참가자는 수령·Host 진행 대기 안내를 받는다.

기존 10전투 저장의 1~9번째 승리는 보상 뒤 상점, 10번째 승리는 보상 뒤 Run 완료로 연결한다. 목표 Run은 전투마다 앞선 인카운터 선택 3회를 제공하고 PvE에만 성장·보상을 지급한다. 마지막 20번째 Snapshot 승리 뒤 Continue로 완료하며 Snapshot·패배에는 보상 카드가 없다. 기존 두 전투 저장과 보상 스키마 0의 과거 Result는 원래 흐름을 유지한다. 보상 후보·공통 골드·수령 기록은 이어하기에서 복원하고 소급 지급하지 않는다.

기존 `Text_Result`·`Button_Continue` 바인딩과 생성 `ContentBox`를 유지하므로 WBP 재생성은 필요하지 않다. 공통 테마·DPI·인벤토리/설정 UtilityLayer 입력 차단을 따른다. 저장·소유권 기준은 [PROJECT_PLAN](PROJECT_PLAN.md#3-파티와-전투-규약), 새 보상 구현과 미완료 실행 확인은 [HISTORY 9-29](HISTORY.md#9-29-2026-10-08-전투-아이템-선택과-공통-골드-보상)·[TODO 26절](TODO.md#26-재개-후-로컬-검수와-저장-보완)을 따른다. 이전 골드 보상의 실행 결과는 [당시 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)으로 보존한다.

## 14 로딩 화면

`Async Loading Screen` 플러그인의 Classic 레이아웃을 사용한다. 기존 DemonicUI 성 배경을 비율 유지·화면 채우기로 표시하고 짙은 하단 밴드에 청동색 회전 표시·선택 언어의 안내·팁을 배치한다. 한국어 시작 안내는 `PROJECT A · 시작 준비 중`, 이후 맵 전환은 `불러오는 중`이다. 원형 표시의 반지름은 22, 8조각·회전 주기 1.2초이며 본문/팁 글자 크기는 26/20이다. 배경·폰트는 원본을 참조하고 별도 로딩바·동영상·이미지 사본을 만들지 않는다.

장착·행동 계획·PvE 보상·상세 툴팁·난이도·단축키 팁 6개 중 하나를 로딩마다 표시하며 화면 도중 팁을 교체하지 않는다. 실제 맵 전체 진행률을 제공하지 않으므로 퍼센트나 가상 진행 막대는 표시하지 않는다. 로딩 완료 즉시 자동 종료하며 읽기를 위한 강제 대기나 추가 확인 키는 없다. 설정은 [DefaultGame.ini](../Config/DefaultGame.ini), 설치 버전·cook·라이선스는 [구현 구조 1-1절](PROJECT_PLAN.md#1-1-로딩-화면-플러그인)을 따른다.

## 15 언어와 번역 리소스

설정의 언어는 **한국어 / English**로 표시한다. 기본값은 한국어이며 **적용 및 저장**으로 즉시 갱신·저장한다. 화면 모드/해상도를 함께 바꾸면 **유지 및 저장** 시점에 언어를 적용한다. 적용 전 취소·화면 복구·시간 초과는 기존 언어를 유지한다. PIE에서는 게임 리소스 미리보기만 변경하며 같은 에디터 프로세스의 PIE 창은 언어를 공유한다. 독립 클라이언트의 선택은 각 클라이언트 설정에 저장한다.

메뉴·캐릭터 생성·설정·전투 계획·인벤토리·장비/스킬 툴팁·인카운터·PvE 난이도·보상·로딩 안내에 Unreal `FText`와 키가 있는 번역 리소스를 사용한다. 아이템 49종·스킬 77종과 현재 인카운터·노드·몬스터·직업/몸체 이름은 고정 ID 또는 원본 에셋 경로로 현지화한다. 저장된 이름·수치·태그·획득 확률·Snapshot·명령 ID를 변경하지 않으며 사용자 캐릭터명은 번역하지 않는다. 기존 개발 진단의 고정 문자열과 미등록/사용자 수정 콘텐츠는 원문을 유지한다. 전체 게임의 모든 로그·예외 문구가 영어라는 의미는 아니다.

`Config/Localization`의 6개 JSON에 namespace·key·한국어 원문·영어 번역을 관리한다. 정적 문자열은 `NSLOCTEXT`, 데이터 표시 문자열은 `ProjectALocalization`의 명시적인 키를 사용한다. 번역이 없거나 원문 해시가 다르면 원문을 표시한다. 원문 변경 시 같은 키의 source/translation을 함께 갱신하며 서식 인자의 이름을 보존한다. `python Source/ProjectAEditor/Scripts/BuildLocalization.py`로 ko/en 리소스를 생성하고 `--check`로 수집 누락·키 충돌·원문/인자·생성물 일치를 검사한다. 생성기는 UE Compact locres 1·locmeta 1을 작성하며 엔진 기본 로더가 읽는다. 번역 배포에는 런타임 JSON 파싱이나 외부 API가 필요 없다.
