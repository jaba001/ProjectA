# 해로운 상태이상 기획과 구현 검토

최초 검토: 2026-09-14·`c42dc90`. 대상은 화상·중독·출혈·냉각·빙결·스턴·혼란·감전 8종이다. 2026-09-18 전투 확정 규칙만 동기화했으며 상태이상 구현은 후순위로 보류한다. 상태별 규칙과 아래 코드 분석은 최초 검토 당시 기준이며 최신 구현 완료나 작동 검증을 의미하지 않는다.

## 1 범위와 판정 기준

| 표시 | 의미 |
|---|---|
| 확정 | 이번 사용자 지시 또는 기존 전투 기획에서 결정한 규칙 |
| 잠정 | 우선 검토할 안 또는 현재 프로토타입의 임시 처리. 최종 채택 아님 |
| 미정 | 검토한 문서·코드에 채택 근거가 없어 결정이 필요한 항목 |
| 미구현 | 기본 라운드 C++ 실행 경로에 해당 처리가 연결되지 않은 상태 |

현재 전투 기준은 [GAME_DESIGN 8절](GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)이다. [아이템 클론 기획](GAME_DESIGN.md#7-아이템-클론-기획)의 원작 상태 효과, 정화·면역 항목, `DurationUnit`·`StackRule` 등의 변환 후보는 ProjectA의 채택된 상태이상 규칙으로 간주하지 않는다.

냉각과 기능이 중복되는 별도 둔화는 만들지 않는다. 가속·재생·보호막 등 이로운 효과와 방어 자원 설계는 범위 밖이다. 기존 피해 경로의 방어 처리는 연동 검토에만 언급하며, 관통·방어 무시·새 방어 체계를 추가하지 않는다.

## 2 재사용하는 전투 결정

### 2-1 시간과 라운드

| 항목 | 재사용할 결정과 현재 구현 | 상태 |
|---|---|---|

| 행동 시작 지연 | `StartDelay = (MaxSpeed - UnitSpeed) × 0.1초`. 양 진영 생존 유닛의 최고 속도는 0초에 시작하며 동률은 같은 시작 시각을 갖는다 | 확정 |
| 시작과 적중 | 시작 시각과 실제 적중 시각은 다르다. 접근·선딜·비행 시간을 거치므로 빠른 유닛의 상태이상이 반드시 먼저 적중하는 것은 아니다 | 확정 |
| 시각표 고정 | 현재 코드는 계획 시작에 속도와 시작 지연을 읽고 고정한다. 실행 중 사망·속도 변경으로 이번 시각표를 재계산하지 않는다 | 기존 초기 구현. 냉각 적용 방식은 별도 미정 |
| 속도 상세 보정 | SAP 고정 350cm/s와 근접 민첩 튜닝은 유지한다. 비근접 시전·이동·투사체 속도의 추가 구현은 별도 작업으로 보류한다 | 2026-09-18 확정 |
| 행동 수와 비용 | 유닛당 주요 명령 하나. AP/SAP는 계획 시작에 초기화하고 Ready Phase 종료 시 즉시 차감하며 불발에도 환불하지 않는다 | 2026-09-18 확정 |
| 이동 | 적 진영 접근·유닛 간 통과·일반 공격 후 복귀. 다른 유닛의 복귀·예약 칸 이동과 자리 교환 금지, 실패 시 출발점 복원. 최종 잔류는 자기 진영만 가능 | 확정 |
| 사망과 공격 | 행동·공격 발동 전 사망하면 취소. 발사된 투사체는 시전자 사망 뒤에도 계속 처리한다 | 확정 |
| 피격 | 근접·지점·투사체는 [서버 공격 충돌](GAME_DESIGN.md#8-5-발동과-피격)로 판정하며 별도 명중 확률·성공 슬롯을 사용하지 않는다. 목표 사망 대응은 스킬별 정책을 따른다 | 확정. 최신 충돌 구현의 작동 확인은 미실행 |
| 권위와 적 계획 | 서버가 요청·피격·HP·사망·결과를 결정한다. 적은 인간 초안을 보고 새 계획을 세우지 않는다 | 확정 |
| 종료 경계 | 모든 예약 행동의 완료·취소, 필요한 복귀, 유효 투사체와 지연 피해 정리 후 라운드를 종료한다 | 확정. 범용 상태이상 지연 피해는 미구현 |
| 같은 시각 | 서버 처리 순서대로 피해·사망을 즉시 반영하고 먼저 사망한 유닛의 미발동 공격을 취소한다 | 2026-09-18 확정. 상태이상의 세부 순서는 별도 |
| 양 팀 전멸 | 잔여 공격 정리 후 패배로 표시하고 Run 종료. 승리 보상 없음 | 2026-09-18 확정 |

이 문서의 **현재 턴·다음 턴**은 대상 유닛의 **현재 전투 라운드·다음 전투 라운드의 행동 기회**를 뜻한다. 순차 턴 시스템을 다시 도입하지 않는다. 빙결·스턴의 턴 종료는 해당 유닛의 행동 차단이며, 다른 유닛과 잔여 효과를 포함한 전체 라운드의 즉시 종료가 아니다.

### 2-2 남은 행동과 정리 중인 작업

남은 행동은 AP 잔량이 아니라 아직 실행하지 않은 유효 행동으로 판단한다. 현재는 명령 하나를 실행하므로 AP가 남았다는 이유로 추가 명령을 생성하지 않는다.

| 현재 상태 | 남은 행동 판단 | 상태이상 검토상 의미 |
|---|---|---|
| `Waiting` | 유효한 미실행 행동이 있으면 남은 행동 있음 | AP가 이미 0이어도 현재 행동 차단 대상 |
| `Approaching`·`Casting`, 공격 미발동 | 발동 전 행동은 있으나 이미 시작된 실행 단계 | 빙결·스턴이 진행 중 행동까지 취소하는지는 미정 |
| 공격 발동 후 `Returning` | 복귀가 남았다는 이유만으로 미실행 공격이 있다고 보지 않음 | 라운드 종료 대기와 제어 효과의 차단 대상을 구분 |
| 공격 불발 후 `Returning` | 불발된 공격은 다시 실행할 유효 행동이 아님 | `bReleased == false`만으로 잔여 행동을 판정할 수 없음 |
| `Complete`·`Cancelled` | 남은 유효 행동 없음 | 빙결은 다음 라운드, 스턴은 이월 없음 |
| 이미 발사된 투사체 | 발사된 공격의 후속 처리 | 발사자의 새 미실행 행동으로 세거나 소급 취소하지 않음 |

`IsTerminal()`은 라운드 정리 여부, `IsBusy()`는 현재 전투 단계까지 포함하는 값이므로 단독으로 잔여 행동 판정에 사용하기 어렵다. 취소 가능 단계·유효 명령·이미 발동하거나 불발했는지를 함께 구분해야 한다.

사용자의 ‘일부 행동 완료, 일부 행동 남음’ 사례는 **완료분 보존·잔여분 차단**이라는 확정 규칙으로 유지한다. 현재 한 명령 구조에서 별도 다중 행동을 구현했다는 뜻은 아니다. 다단계 스킬에 이를 적용할 때 어느 단계를 독립된 유효 행동으로 보는지는 기존 스킬 정의와 취소 경계를 확인해야 한다.

## 3 상태이상 8종 규칙표

### 3-1 부여와 효과 발동

아래 ‘부여 시점’은 상태가 생기는 시점이고 ‘발동 시점’은 피해·차단 등이 실제로 작동하는 시점이다. 부여 스킬·아이템의 상세 연결이 없는 항목은 임의로 직접 타격 전용 효과로 한정하지 않는다. 모든 피해량은 방어 처리 전 **기본 피해량**이다.

| 상태 | 부여 시점 | 실제 효과 발동 시점 | 수치와 피해·제어의 관계 |
|---|---|---|---|
| 화상 Burn | **미정:** 부여원과 스킬 판정 연결 | **미정:** 피해 발동 주기·최초 발동 시각. **확정:** 발동하면 현재 수치 피해를 먼저 적용 | **확정:** `B > 0`이면 B 피해. 이후 감소. **미정:** A안 `floor(B / 2)`. **잠정:** B안 `max(0, floor(B / 2) - 1)` |
| 중독 Poison | **미정:** 부여원과 스킬 판정 연결 | **미정:** 피해 발동 주기·최초 발동 시각 | **확정:** `P > 0`이면 P 피해 후 `max(0, P - 1)` |
| 출혈 Bleeding | **미정:** 부여원과 스킬 판정 연결 | **확정:** 실제 전술 그리드 한 칸 이동 완료마다 1회. 자발·강제 이동, 밀치기·당기기 포함 | **미정:** 칸당 피해와 출혈 수치의 관계·발동 시 수치 소비 |
| 냉각 Chill | **미정:** 부여원과 적용 경계 | **확정:** 현재 시간·속도 전투의 행동 시점에 영향을 주는 효과. **미정:** 구체적인 반영 시각 | **미정:** 속도 감소·준비 진행 감속·다른 시간 보정 중 어떤 처리인지와 수치. 별도 둔화 없음 |
| 빙결 Freeze | **확정:** 실제 상태 적중 시점에 적용 대상 라운드를 결정. 부여 스킬 상세는 미정 | **확정:** 현재 유효 행동이 남으면 현재 라운드 차단, 없으면 다음 라운드 차단 | **확정:** 한 번의 적용은 현재·다음 중 한쪽만 차단. 완료된 행동은 보존. 별도 피해 수치 없음 |
| 스턴 Stun | **확정:** 실제 상태 적중 시점의 잔여 행동 확인. 부여 스킬 상세는 미정 | **확정:** 현재 라운드의 남은 행동만 차단. 없으면 행동 차단 효과 없음 | **확정:** 다음 라운드로 이월하지 않으며 완료된 행동은 보존. 별도 피해 수치 없음 |
| 혼란 Confusion | **미정:** 부여원 연결. **확정:** 부여받은 현재 라운드의 완료된 행동은 변경하지 않음 | **확정:** 다음 라운드의 정상 선택을 합법적인 무작위 행동으로 대체. **미정:** 무작위 명령을 결정하는 시각 | **확정:** 실제 사용 가능한 스킬·대상·목적지로 구성. 별도 피해 수치나 랜덤 배율을 추가하지 않음 |
| 감전 Shock | **미정:** 부여원과 스킬 판정 연결 | **미정:** 정확한 발동 계기. ‘후속 직접 타격’은 이전 제안. **잠정:** 발동 시점 위치·그리드 점유로 범위 계산 | **확정:** 중심 및 적용 가능한 상하좌우 인접 유닛 각각 S 기본 번개 피해. 대각선·반감·분배·동일 유닛 중복 피해 없음 |

| 혼란 | **미정:** 반복 부여 시 병합·갱신·예약 처리 | **확정:** 다음 라운드 행동 대체. **미정:** 정확한 소모 시점, 그 라운드가 빙결로 차단될 때 소모 여부 | **미정:** 가능 여부·제거 단위·행동 대체 예약 해제 범위 |

### 3-3 행동 불가와 사망 및 종료

공통 기존 처리: HP가 0이 되면 서버가 즉시 사망을 반영하고 발동 전 자기 행동을 취소한다. 사망 유닛의 점유 칸은 즉시 해제된다. 이미 발사된 투사체와 그 밖의 유효한 잔여 작업을 정리한 뒤 라운드 결과를 확인한다. 상태 인스턴스의 사망 시 제거·전투 간 유지·정화 순서는 아직 채택되지 않았다.

| 상태 | 행동 불가 중 처리 | 사망·전투 종료와의 순서 및 남은 경계 |
|---|---|---|
| 화상 | **미정:** 선택될 주기가 행동 불가 라운드에도 발동하는지. 행동 취소 콜백 때문에 예정된 발동이 우연히 누락되는 구조는 피해야 함 | **확정:** 현재 B 피해 → 다음 수치 계산. 치명 피해는 기존 즉시 사망 경로 사용. **미정:** 사망한 대상 상태의 정리와 동일 시각 다른 효과의 순서 |
| 중독 | **미정:** 행동 불가 중 발동 정책. 행동 실행 성공 여부에 무조건 종속시키지 않음 | **확정:** 현재 P 피해 → 수치 1 감소. 치명 피해는 기존 즉시 사망 경로 사용. **미정:** 사망 후 상태 정리·동시 효과 순서 |
| 출혈 | **확정:** 행동 차단 여부와 별개로 실제 강제 전술 이동이 성립하면 칸마다 발동 | **확정:** 피해로 사망하면 자기 미발동 행동 취소. **미정:** 진행 중인 외부 강제 이동의 나머지 구간·후속 효과를 중단하는 범위 |
| 냉각 | **미정:** 행동 불가 중 지속시간 경과·해제·다음 시각표 반영 방식 | **미정:** 상태 수명·전투 종료 정리. 현재 사망·결과 권위는 유지 |
| 빙결 | **확정:** 선택한 현재 또는 다음 라운드 행동 차단. **미정:** 다른 제어와 중복·진행 중 행동 취소 범위 | **확정:** 완료된 공격과 발사된 투사체를 소급 취소하지 않음. 생존 유닛의 적 진영 잔류 불가 계약 유지. **미정:** 제어 중 복귀의 상세 시점 |
| 스턴 | **확정:** 현재 잔여 행동 차단만 수행. **미정:** 다른 제어와 중복·진행 중 행동 취소 범위 | **확정:** 다음 라운드 차단 없음. 완료된 공격과 발사된 투사체 보존. **미정:** 제어 중 복귀의 상세 시점 |
| 혼란 | **미정:** 다음 라운드 빙결과 겹칠 때 우선순위·소모 처리 | **확정:** 이미 끝난 현재 행동을 변경하지 않음. **미정:** 대상 사망·전투 종료 시 예약 폐기와 전투 간 유지 |
| 감전 | **미정:** 발동 계기와의 관계. 대상이 행동 불가라는 이유만으로 발동·면제를 추가하지 않음 | **확정:** 발동 대상별 피해 후 원래 감전 제거. 한 대상 사망만으로 나머지 적용 대상 피해를 생략하지 않음. **미정:** 발동 계기인 타격으로 HP가 0이 될 때 발동 자격·중심 위치 보존 시점 |

지속 중인 상태나 다음 라운드 차단 예약이 존재한다는 사실만으로 현재 라운드 종료를 계속 막아서는 안 된다. 구현 시 **현재 라운드에서 정리할 유효 효과**와 **다음 라운드로 이어질 상태**를 구분해야 한다. 어떤 상태 피해가 어느 쪽에 속하는지는 발동 주기 결정 후 정의한다.

## 4 핵심 규칙 상세

### 4-1 화상과 중독의 피해 후 감소

화상은 다음 순서가 확정이다.

1. B가 0이면 피해 이벤트 없이 종료한다.
2. 현재 B만큼 기본 피해를 준다.
3. 선택한 감소 공식으로 다음 화상 수치를 계산한다.
4. 다음 수치가 0이면 상태를 제거한다.

| 수치 | A안: 절반 내림 | B안: 절반 내림 후 추가 1 감소 |
|---|---|---|
| 공식 | `NextBurn = floor(B / 2)` | `NextBurn = max(0, floor(B / 2) - 1)` |
| 9 | 9 피해 → 4 피해 → 2 피해 → 1 피해 → 제거 | 9 피해 → 3 피해 → 제거 |
| 1 | 1 피해 → 제거 | 1 피해 → 제거 |
| 0 | 피해 이벤트 없음 | 피해 이벤트 없음 |
| 채택 상태 | 비교 후보, 미확정 | 최근 사용자 언급에 따른 잠정안, 최종 미확정 |

홀수라는 이유로 피해 전에 수치를 줄이지 않는다. 화상 1의 정상 발동을 위해 추가 `-1`은 필요하지 않다. 방어로 실제 잃은 HP가 줄거나 0이 되어도 다음 화상 수치는 현재 B로 계산한다. 두 안은 피해 횟수·누적 기본 피해가 다르므로 하나의 공식으로 취급하지 않는다.

중독은 `P == 0`에서 이벤트 없이 종료하고, 현재 P 피해를 적용한 뒤 `max(0, P - 1)`로 변경한다. P=3이면 3 → 2 → 1 피해 후 제거한다. 실제 HP 감소량을 중독 수치로 재사용하거나 화상의 절반 감소를 적용하지 않는다. 보호막 우회·방어 무시는 확정되지 않았다.

### 4-2 출혈의 이동 단위

출혈은 실제 통과한 **전술 칸 이동의 순서**를 기준으로 한다. 세 칸을 실제 이동하면 세 번, 세 칸을 요청했지만 두 칸만 이동하면 두 번이다. 이동에 실패한 구간은 세지 않는다. 유닛 길막은 기존 기획에 없으므로 ‘막힘’ 검증은 이동 불가 지형·경계 등 실제 이동 실패 조건을 사용한다.

자발 이동과 강제 이동을 동일하게 계산하되 근접 공격을 위한 접근·복귀와 구분한다. 이동 공격에 실제 전술 위치 변경이 포함되면 그 변경 구간은 출혈 대상이다. 공격 연출용 접근·복귀를 자동으로 전술 이동으로 계산하지 않는다.

여러 프레임·콜백이 같은 칸 이동을 보고해도 한 번만 처리한다. 빠른 이동에서 여러 칸을 통과한 사실을 최종 `SetCurrentTile()` 한 번으로 축약하지 않는다. 왕복 경로·중간 칸·진영 간 간격이 있으므로 시작·끝 좌표 거리만으로 통과 횟수를 대신할 수 없다. 순간이동, 대각선·연속 공간 이동의 전술 칸 경계 정의는 해당 이동 방식 채택 시 별도 확인한다.

### 4-3 빙결과 스턴의 적용 대상 라운드

| 실제 적중 직전 대상 상태 | 빙결 1회 | 스턴 1회 |
|---|---|---|
| 현재 유효 행동이 아직 남음 | 현재 남은 행동 차단. 같은 부여로 다음 라운드까지 차단하지 않음 | 현재 남은 행동 차단 |
| 현재 행동을 모두 마침 | 다음 라운드 행동 차단 | 막을 현재 행동이 없으므로 행동 차단 없음. 이월 없음 |
| 일부 완료, 유효 행동 일부 남음 | 완료분 유지, 현재 잔여분 차단 | 완료분 유지, 현재 잔여분 차단 |

빙결은 **적중 직전 상태를 한 번 읽어 현재·다음 중 적용 대상을 정한 뒤** 차단한다. 현재 행동을 취소한 결과 잔여 행동이 0이 됐다는 이유로 다음 라운드 빙결을 추가 예약하지 않는다.

진행 중인 접근·시전까지 차단하는지는 미정이다. 이 경계의 선택이 끝나기 전에는 해당 사례의 결과를 임의로 현재 차단 또는 다음 차단으로 확정하지 않는다. 생존 유닛의 행동을 취소하더라도 기존 적 진영 잔류 불가·복귀 계약을 충족해야 한다. 이미 완료된 공격·발사된 투사체의 취소는 제어 효과에 추가하지 않는다.

### 4-4 혼란의 합법 행동

혼란은 다음 라운드 정상 선택을 무작위 행동으로 대체한다. 먼저 해당 유닛이 사용할 수 있는 행동·스킬·대상·목적지 후보를 구성해야 한다. 존재하지 않는 스킬이나 이동 불가 칸을 무작위로 뽑고 오류로 끝나는 것은 기대 동작이 아니다.

현재 서버의 스킬 보유·생존·비용·대상·목적지 검증은 재사용할 수 있다. 다만 현재 공격은 적 대상, 지원은 아군 대상이며 혼란에 의한 아군 공격·적 지원은 결정되지 않았다. 아이템과 소모품 소비도 자동으로 포함하지 않는다. 후보가 없는 경우의 행동은 허용 행동 범위와 함께 결정한다.

무작위 결정 시점은 미정이다. 계획 시점 선택이면 기존 잠금 흐름에 연결하고, 실행 시점 선택이면 잠긴 명령과 실행 직전 유효성의 관계를 추가로 정의해야 한다. 어느 경우에도 서버 권위·원래 소유권을 유지하고 적이 인간의 비공개 초안에 대응하는 규칙으로 바꾸지 않는다.

### 4-5 감전의 단일 발동

| 요소 | 규칙 |
|---|---|
| 중심 피해 | 감전 대상 자신에게 S 기본 번개 피해 |
| 인접 피해 | 상하좌우의 적용 가능한 각 유닛에게 S 기본 번개 피해 |
| 제외 | 대각선, 대상 수에 따른 피해 분배, 인접 반감, 한 유닛 중복 적용 |
| 제거 | 발동한 원래 감전 상태 제거 |
| 범위 시점 | 발동 시점의 위치·점유 기준을 우선 검토. 잠정안 |
| 발동 계기 | 미정. 후속 직접 타격 발동은 제안이며 즉시·주기 발동도 채택하지 않음 |
| 진영 | 중심은 자신 포함 확정. 인접 유닛의 진영 조건은 미정 |
| 다른 감전 | 전도 피해로 다른 감전을 재귀 발동시키는 연쇄는 추가하지 않음 |

S=10이고 중심과 상하좌우 네 칸 모두 적용 대상이면 다섯 유닛 각각 기본 피해 10이다. 대각선에는 피해가 없다. 범위 밖·빈 칸 때문에 남은 대상 피해가 증가하거나 감소하지 않는다.

현재 근접 접근 중 실제 월드 위치와 예약 점유 칸은 일치하지 않을 수 있다. 따라서 ‘발동 시점 위치·그리드 점유’ 안을 채택하려면 중심 칸과 인접 유닛을 **예약 점유로 판정할지 실제 전술 위치로 판정할지** 명확히 해야 한다. 이동 비충돌 규칙을 바꾸거나 새 칸 점유 정책을 여기서 확정하지 않는다.

발동이 성립했다면 첫 대상의 사망 때문에 나머지 고유 대상의 피해가 사라져서는 안 된다. 구현 시 중심·대상 목록을 보존하고 그 발동의 피해와 상태 소모를 끝낸 후 결과를 판단할 필요가 있다. 이는 확정 범위 피해를 충족하기 위한 연결 요구이며, 발동 계기나 진영을 확정한 것이 아니다.

## 5 남은 결정

이미 결정된 속도 0.1초 공식, 한 명령, 실제 피격, 사망 전 발동 취소, 발사 후 투사체 유지, 적 계획 고정, 일반 복귀 규칙은 다시 결정할 대상이 아니다. 아래 항목만 추가 결정이 필요하다.

| 항목 | 결정할 내용 | 영향 |
|---|---|---|
| 공통 부여·수명·정화 | 부여원과 효과 연결 시점, 상태별 재부여 방식, 별도 만료 시간, 정화 가능 여부·단위, 사망·전투 종료 시 상태와 예약 정리 | 상태 데이터·이벤트 경계. 원작 참조의 지속·정화 정책을 자동 적용할 수 없음 |
| 화상 | A안 또는 잠정 B안의 최종 선택 | 총 피해량·발동 횟수 |
| 화상·중독 주기 | 최초 및 반복 피해 시점, 행동 불가 라운드 처리, 같은 경계의 피해·감소·다른 상태 처리 순서 | 취소된 행동 때문에 피해 누락 또는 중복 발동하는 문제 방지 |
| 출혈 | 칸당 피해와 수치 관계, 발동 시 소비, 제거 조건, 순간이동 처리, 별도 주기 피해 유무 | 이동 비용과 지속성. 강제 이동 도중 사망 시 남은 이동·외부 후속 효과 중단 범위도 필요 |
| 냉각 | 구체적인 효과·수치·중첩·수명과 시각표 반영 시점 | 현재 계획 시작 고정 시각표에 단순 속도 변경만 하면 실행 중 이번 행동은 늦어지지 않음. 기존 시작 지연 공식은 유지 |
| 빙결·스턴 | 진행 중 접근·시전의 취소 범위, 제어 중 복귀 시점, 반복 적용·상호 중복 처리 | 적중 시 잔여 행동과 차단 대상 라운드를 일관되게 판정 |
| 같은 시각의 효과 | 공격 발동·상태 부여·사망의 동일 시각 우선순위 | 현재 배열 순서의 즉시 처리만으로 최종 동시 판정 정책을 대신할 수 없음 |
| 혼란 | 이동·공격·지원의 허용 범위, 아군 공격·적 지원, 아이템 소비, 무작위 결정 시점·유효 후보 없음 처리 | 합법 행동 선택 및 기존 계획 잠금과의 연결 |
| 빙결과 혼란 | 같은 다음 라운드에 예약되면 어떤 순서로 처리하고 혼란을 소모하는지 | 차단된 라운드에서 혼란을 잃는지 이후로 남기는지 |
| 감전 | 발동 계기, 인접 진영 조건, 실제 위치·예약 점유의 범위 기준, 재부여·미발동 만료 | 적용 대상과 발동 횟수. 후속 직접 타격 안을 채택할 경우 치명 직접 타격과 감전의 선후·발동 자격도 필요 |

새로운 상태이상, 방어 시스템, 감전 재귀 연쇄, 순차 전투 복원은 결정 목록에 추가하지 않는다.

## 6 기존 구현과의 차이 및 충돌 위험

8종의 완성된 구현끼리 충돌하는 상태는 아니다. 현재 기본 라운드 실행 경로에는 상태 수치·지속·주기·제어 적용이 없으므로, 아래는 **추후 연결 시 기존 함수를 그대로 사용하면 생길 차이**다. Blueprint 바이너리 내부의 상태 구현 여부와 실제 작동은 이번 검토에서 확인하지 않았다.

| 구분 | 현재 근거 | 검토 결과 |
|---|---|---|
| 상태 처리 기반 | `FCombatRoundUnitView`, `UAS_Unit`, `UGE_Damage`; `Status.Stunned` 태그 선언 | HP·행동 단계와 즉시 피해는 있으나 8종 처리 경로 없음. 태그 선언만으로 스턴 동작이 결정되거나 구현된 것은 아님 |
| 잔여 행동 | `LockPlans()` 비용 차감, `AdvanceAction()` 단계, `bReleased`·`bFailed` | AP=0인 대기 행동을 놓치거나 복귀 중 유닛을 미발동 상태로 오인할 위험. 취소 직전 잔여 유효 행동 판정 필요 |
| 생존 유닛 취소 | `AUnitBase::CancelCurrentAction()`은 이동·AI·GAS 정지, 조정자 명령 상태는 직접 변경하지 않음 | 이 함수만 호출하면 조정자가 다음 간격에 이동·시전을 계속할 수 있음. 제어 취소는 조정자 명령과 복귀 계약에 연결해야 함 |
| 출혈 칸 이동 | `MoveUnitToward()`는 월드 위치 이동. 성공한 잔류 이동의 `StartReturn()`에서 최종 `SetCurrentTile()` | 실제 전술 칸 통과 이벤트·밀치기·당기기 실행은 없음. 마지막 위치 변경 횟수나 전체 Actor 이동량만으로 출혈을 계산할 수 없음 |
| 냉각 시각표 | `BeginPlanning()`에서 속도·시작 지연 고정 | 런타임 속도만 바꾸면 이미 예약한 지연은 그대로다. 냉각의 적용 시점 결정 필요 |
| 주기·라운드 종료 | `FinishRoundIfSettled()`는 명령 종료와 투사체 목록 확인 | 화상·중독의 독립 주기 처리와 해당 라운드에 남은 상태 피해 추적은 없음. 행동 차단 시 누락과 조기 라운드 종료를 검토해야 함 |
| 감전 인접 칸 | `GetAdjacentTiles()`는 대각선 포함 8방향 | 그대로 사용하면 대각선 제외 규칙 위반. 상하좌우만 선택 필요 |
| 감전 피해 대상 | 조정자 `ApplyHit()`은 같은 팀 거절. `ApplyDamageToUnits()`는 피해 Source 자신 제외 | 중심 대상을 Source로 쓰면 중심 피해가 누락될 수 있음. 인접 진영 정책과 피해 원인자를 구분해야 하며 현 필터를 감전 정책으로 확정하지 않음 |
| 감전 도중 사망 | `PostGameplayEffectExecute()` → `Die()`에서 즉시 `CurrentTile` 해제 | 중심 사망 뒤 범위를 새로 찾으면 나머지 피해가 누락될 수 있음. 발동 성립 시 필요한 중심·대상 보존 경계가 필요 |
| 번개 피해 | 현재 `UGE_Damage`는 공통 `Data.Damage`의 즉시 HP 감소 | 감전의 기본 번개 피해 분류 연결은 미구현. 새 원소 방어·저항 체계를 의미하지 않음 |
| 혼란 명령 | `BeginPlanning()`의 AI 계획은 첫 유효 공격과 가까운 적 선택. `ValidateCommand()`·`LockPlans()`에서 합법성·비용 검사 | 기존 AI 선택은 무작위 혼란 구현이 아님. 무작위 후보 생성과 확정 시각을 기존 검증에 연결해야 함 |

### 7-1 준비와 기록 원칙

**아래는 검증 계획이며 전부 미실행이다.** 관련 상태 처리와 미정 정책이 확정·구현된 이후 사용자가 실행한다. 현재 상태에서 통과 가능한 기능 목록이나 자동화 테스트 코드를 제공하는 것이 아니다.

준비 조건은 대상 커밋, 채택한 화상 공식·주기·피해 필터·제어 경계, 유닛의 HP·속도·명령·그리드 좌표·상태 수치를 고정하는 것이다. 서버 시각과 라운드 번호, 실제 칸 이동 식별, 상태 발동 전후 수치, 기본 피해·실제 HP 변화, 명령 단계, 차단 예약, 사망·라운드 전환 순서를 기록한다. 남은 확인은 [TODO](TODO.md#5-디자인-확정-후-구현할-일), 완료 결과는 [HISTORY](HISTORY.md)에 짧게 기록한다.

미정 항목이 포함된 행은 조건별 기대 결과를 확정한 후 실행한다. 문서의 미정 항목을 테스트 작성 과정에서 기본값으로 확정하지 않는다.
