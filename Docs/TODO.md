2. **T14-8 서비스 준비**: Steam App ID·PlayFab Title 미준비. [서비스 준비](MULTIPLAYER.md#t14-8-서비스-준비)와 [준비 보고서](TEST_REPORT.md#4-t14-8-서비스-준비-보고서) 기준.

## T14-7 검증 범위

- 3명 중 최초 Host 불참 → 2번 Host·3번 Client·1번 AI.
- 4명 중 최초 Host 불참 → 2번 Host·3/4번 Client·1번 AI.
- 4번 단독 재개 → 4번 Host·나머지 AI, 다음 전투에서도 AI 유지.
- 각 Client의 서버 발급 바인딩과 원래 계정·자기 캐릭터 조작권, 실제 요청 승인, 동일 전투 상태 확인.
- 메뉴 이동 실패 후 같은 저장으로 재시도, 종료된 실행 권한·오래된 요청·이미 AI인 계정의 인간 복귀 거절 확인.

기존 개발 fixture가 관리 Run의 호출자·대상을 설정한다. 새 개발용 협동 UI는 비관리 방을 생성하며 서버가 참가 번호를 발급한다. 관리 Run의 수동 협동 재개·승계 화면은 아직 없고 개발용 새 방 UI의 검증도 별도다. 세부 실행 방법·기대 결과·기록란은 [TEST_REPORT](TEST_REPORT.md)에 둔다.

## 8 시간차 자동 전투 후속 결정

기준 규칙은 [GAME_DESIGN 8절](GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)에 통합한다. 속도 차당 0.1초, 상대 진영 공격 접근, 유닛 간 비충돌, 일반 복귀·자기 진영 이동 공격, 발동 전 사망 취소·발사체 존속, 실시간 피격, 속도순 지원, 잔여 공격까지 정리한 라운드 종료, 인간 초안 이전 적 계획 고정은 확정 방향이다. 아래는 미결정 계약이며 권장안은 사용자 확정을 대신하지 않는다.

### 8-1 구현 전 결정

| 우선순위 | 항목 | 선택과 영향 |

### 8-2 후속 조정과 구현 단계

속도에 따른 이동·시전·투사체 속도 보정, 최고·최저 비율 정규화·대기 상한, 부분 공개·위치 협공·복잡한 상태효과는 후속 조정이다. 초기에는 고정 시험값을 명시하며 사용자 결정 없이 속도 보정을 추가하지 않는다. 아이템 클론의 턴당 효과·Speed는 새 전투에 별도 변환한다.

- [ ] 8-1의 첫 실험 대상 스킬·시각표·피격·종료 계약 확정.
- [ ] 기존 전투와 분리된 값 기반 계획/명령·서버 실행 상태와 2 대 2 진입 설계. 인원은 배열로 처리.
- [ ] 유닛/타일 접근·복귀·근접 피격·발사체 존속·지원 시각과 결과 표시 구현.
