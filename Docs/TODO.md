# 남은 작업과 미결정 제안

아직 구현하지 않은 작업과 결정이 필요한 제안만 관리한다. 구현을 마친 항목은 삭제하고 완료 내용은 커밋 본문에 남긴다. 검수·작동 확인 항목은 두지 않는다. 제안의 선택 체크는 구현 완료를 뜻하지 않으며, 절·제안 번호는 다시 매기거나 재사용하지 않는다. [문서 관리 규칙](../AGENTS.md#문서-관리)

## 4 온라인 협동과 경쟁

Steam·PlayFab 계정, 서비스 ID, 무료 사용 조건이 준비되어야 진행할 수 있다. 준비 전에는 온라인 SDK 활성화나 인증·저장 성공을 가정하는 연결을 추가하지 않고, 유료 리소스를 활성화하지 않는다. 비용·소유권·저장 권위는 [멀티플레이 계약](MULTIPLAYER.md)을 따른다.

### 4-1 서비스 준비

#### 4-1-1 제안 9 개발 ID와 무료 시험 조건

현재: Steam 480 개발 연결 시제품만 있다. 자체 App ID·PlayFab Title·시험 PC 2대는 미준비다. [Steam 예제](https://partner.steamgames.com/doc/sdk/api/example?l=english) · [PlayFab 개발 모드](https://learn.microsoft.com/en-us/xbox/playfab/pricing/development-mode) · [Foundation 조건](https://learn.microsoft.com/en-us/xbox/playfab/get-started/foundation-onboarding)

- [ ] 선택 1: 자체 App ID·Title ID와 무료 개발 모드 한도로 실제 Steam 인증·P2P·PlayFab 연동을 진행한다.
- [x] 선택 2: 480 개발 설정으로 Steam 세션·P2P 연결 시제품만 먼저 만든다. 자체 앱 인증·PlayFab은 ID와 무료 조건 준비 후 진행한다.

남은 작업: ID·권한·한도·시험 계정 준비 후 UE 5.8 지원 SDK/API를 고정하고 자체 앱 인증을 연결한다. 출시 운영비 조건은 별도로 정한다. [준비 절차](MULTIPLAYER.md#10-t14-8-서비스-준비)

#### 4-1-2 제안 10 초대·재접속·관전

현재: Steam 480 개발 모드의 비공개 세션 생성·검색·친구 초대 참가·나가기는 구현했다.

- [x] 선택 1: 비공개 Steam 친구 초대로 새 Run에 참가하고 원래 참가자는 관리 Run 목록에서 재접속한다. AI 전환된 원래 소유자는 읽기 전용 관전을 허용한다.
- [ ] 선택 2: 비공개 참가 코드로 참가하고 같은 코드로 관리 Run을 조회한다. AI 전환된 소유자의 관전은 허용하지 않는다.

남은 작업: 중앙 정본 저장(제안 11) 연결 후 온라인 관리 Run 목록·원래 참가자 재접속·Host 승계 UI·AI 전환 후 읽기 전용 관전을 구현한다. 대체 참가는 거절하고 참가 번호 1~4를 보존하며, 관전자는 계획·Ready·구매·Continue를 바꾸지 못한다.

### 4-2 서비스 구현

#### 4-2-1 제안 11 정본 저장과 동시 승계

현재: 같은 PC의 파일·OS lease 개발 어댑터만 있다.

- [x] 선택 1: PlayFab을 쓰는 신뢰 서비스가 Run 본문·원래 소유권·revision/epoch·lease를 함께 승인하고 최신 본문을 제공한다.
- [ ] 선택 2: 서비스는 revision/epoch·lease·본문 해시만 승인하고 본문은 별도 객체 저장소에 둔다.

남은 작업: 조건부 갱신·원자 처리와 무료 범위를 확인하고 계정 인증·멱등 요청·Ready 경계 복구를 연결한다. 이전 Host 파일 없이 최신 본문을 복구하고, 동시 승계는 한 명만 승인하며, stale revision/epoch 요청은 거절해야 한다. [복구 계약](MULTIPLAYER.md#6-준비-완료-경계와-파일-저장)

#### 4-2-2 제안 12 온라인 Snapshot과 상대 선정

현재: 로컬 Snapshot 검증과 GameplayTagQuery 조건의 균등 후보 선택 API가 있으나 기본 Run·온라인 공급자와 연결되지 않았다. 장비·전술은 빈 값만 지원한다.

- [x] 선택 1: 현재 지원 범위의 생존 상대·저장 HP·스킬·배치를 먼저 게시하고, 같은 콘텐츠 버전·진행 단계의 태그 조건 후보 중 균등 추첨한다.
- [ ] 선택 2: 장비·소모품·성장·속도·전술과 AI 규칙을 먼저 완성하고 평점 구간으로 후보를 좁힌다.

남은 작업: 게시 시점·보존 기간·중복 상대·버전 변경 처리를 정하고 온라인 게시·보존·매칭·이중 소모 방지·소모품 AI를 구현한다.

#### 4-2-3 제안 13 MMR 집계

- [x] 선택 1: 공격 Run의 PvP 승패를 합산해 파티 공통 변동량을 계산하고 현재 Human에게 동일 적용한다. Snapshot 방어 결과는 통계만 보존한다.
- [ ] 선택 2: 공격 PvP마다 Human별 평점 비교 변동량을 기록하고 Run 종료에 합산한다.

남은 작업: 계산식·초기 평점·동률·중도 패배·미확정 결과·이탈 악용 대응을 정하고 서비스 정산을 구현한다. AI·불참자·Snapshot 원소유자에게는 MMR 변동을 주지 않는다.

#### 4-2-4 제안 14 결과 검증과 재실행 방지

현재: Listen Host의 전투 권위와 로컬 Ready 저장만 있다.

- [x] 선택 1: 신뢰 서비스가 확정 명령·시드·콘텐츠 버전·판정 입력을 저장하고 전투 종료 후 결과를 재검증한다. 미검증 결과는 MMR에서 제외한다.
- [ ] 선택 2: 라운드마다 중앙 서비스가 검증하고 승인된 경계만 다음 라운드와 정산에 연결한다.

남은 작업: 서버 재현 가능한 판정 범위·실패/이탈·미확정 Attempt 처리를 정하고 구현한다. 같은 Attempt의 중복 제출과 변조·오래된 버전 결과는 정산에서 제외해야 한다.

## 6 신규 에셋 선정과 도입

새로 구입·교체할 콘텐츠와 범위는 미정이다.

- [ ] 구입 대상의 이름·버전·원본 경로와 사용 범위(캐릭터/적·장비·애니메이션·VFX·아이콘/UI)를 기록하고, 기존 항목을 유지·교체·미사용으로 구분한다. 참조가 바뀌는 교체 대상은 ID·기존 저장 처리 정책을 함께 정한다.
- [ ] 채택한 에셋의 UE 5.8 로드·Skeleton/리타깃·소켓/배율·FX 방향 호환을 맞추고 안정 ID·표시명·태그·실행 프로필·카탈로그를 갱신한다. GameplayTag 조건·GAS·서버 피해 권위는 유지한다.
- [ ] 프리뷰·공격/피격·장비·UI·저장·원격 표현에 적용하고, 교체 후 미사용 에셋은 참조·저장 호환을 확인해 Unreal 기능으로 정리한다.

## 26 표현 개선

- [ ] 투사체 발사 FX가 골반 높이에서 시작하는 문제를 개선한다. 서버 충돌·스폰·GAS는 유지하고 데이터 기반 시각 소켓 또는 별도 FX 부착점을 쓴다.
- [ ] 통합 Gameplay 중 난이도 전투장 바닥의 회색 체크무늬를 독립 DungeonStone 맵과 같은 표현으로 고친다.

## 30 데이터 구조

### 30-1 제안 20 런타임 CSV와 DataTable

현재: `DataCatalogs/*.csv`를 런타임에 읽고 한글 헤더를 문자열로 비교하며, 행마다 `TryLoad`를 동기 호출한다. 고정 행 수 검사는 등급 수 기반으로 바꿨다(이전 Claude 제안 4 선택 1).

- [ ] 선택 1: CSV 런타임 로드를 유지한다.
- [ ] 선택 2: CSV를 원본으로 두고 에디터에서 `UDataTable`로 임포트·검증해 쿠킹한다. 런타임은 DataTable만 읽는다.
- [ ] 선택 3: 기존 DataAsset 구조에 값을 통합하고 CSV는 내보내기 용도로만 둔다.

권장: 선택 2. 타입 검사·쿠킹·비동기 로드를 엔진 기능으로 얻고 CSV 편집 흐름을 유지한다. CSV 로더 8개와 저장된 Run의 재현 경로를 함께 바꿔야 하며, 기존 Run 저장의 수치는 그대로 로드되어야 한다.

## 31 핵심 재미와 밸런스

사용자가 직접 진행한다. 요청 전에는 밸런스 수치나 난이도 곡선을 임의로 조정하지 않는다. 측정 도구는 [PROJECT_PLAN 7-1](PROJECT_PLAN.md#7-1-밸런스-측정-commandlet)을 따른다.

- [ ] 정상 80단계 완주가 가능하도록 후반 난이도·회복 부담을 조정하고 [난이도 규칙](PROJECT_PLAN.md#5-1-목표-run과-회복-시험-데이터)을 확정한다.
