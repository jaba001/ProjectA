# 남은 작업

**지금은 전투·UI 작동 확인과 알려진 오류 수정이 우선이다.** 새 콘텐츠는 게임 규칙과 디자인을 확정한 뒤 구현한다.

갱신일: 2026-09-16. 완료 이력은 [HISTORY](HISTORY.md), 현재 구현은 [PROJECT_PLAN](PROJECT_PLAN.md), 상세 검증 절차는 [TEST_REPORT](TEST_REPORT.md)에서 확인한다.

작업 우선순위·구현 방식·코드 검토·컴파일·문서 정리·커밋과 push는 Codex가 맡는다. 개별 코드 변경마다 사용자 지시나 검수를 기다리지 않는다. 미정 기획은 기존 확정 방향을 유지하는 최소 기능의 기본안을 기준 문서에 기록한 뒤 구현하며, 원래 소유권·비용 제한·명시적으로 보류한 랭크 정책은 유지한다. 기존 시험값을 검증된 최종 밸런스로 기록하지 않는다.

진행 순서는 오류 수정과 데이터 사전 검사 → 전투·아이템·Run 규칙의 기본안 → 최소 아이템·직업·상점 기능 → 상태이상·AI·표현 → 실제 서비스 연동이다. 외부 계정·비용 또는 사용자 실행 결과가 필요한 항목은 의존하는 작업만 대기한다. 작동 확인은 아래 통합 순서로 묶으며, 상세 회귀 항목을 매 변경마다 모두 수동 수행할 필요는 없다.

## 1 사용자 작동 확인

**아래 항목은 실제 실행 결과가 필요하다.** 작동 테스트는 사용자가 수행하며, Codex 실행은 명시적으로 요청한 경우에만 진행한다.

- [ ] **전투 계획과 AI 행동을 확인한다.** 공격·엄호 대상 선택, AP 부족 안내, 사망 후 초안 유지, 준비 완료, 장착 타일 공격 AI를 확인한다. [검증 8항목·회귀 테스트 4건](TEST_REPORT.md#17-계획-입력-검사와-장착-tile-공격-ai)
- [ ] **싱글플레이 한 Run을 끝까지 진행한다.** 새 게임 → 첫 전투 → 결과 → 상점 선택·진입·퇴장 → 두 번째 전투를 확인한다. 상점 선택 저장·Host 진행 권한과 비전투 이어하기도 확인한다. [전투](TEST_REPORT.md#12-시간차-자동-전투-기획-검토) · [상점](TEST_REPORT.md#10-상점-인카운터)
- [ ] **협동은 2인부터 확인하고 4인으로 확대한다.** 방 생성·주소 참가·준비·이탈, 동시 계획 수정, 본인 캐릭터 조작, 서버 피격·결과 일치를 확인한다. 이후 인간/AI 조합을 검증한다. [협동 UI](TEST_REPORT.md#9-개발용-협동-ui)
- [ ] **화면 설정과 UI를 확인한다.** 해상도 변경·복원, 테마 가독성, 화면 비율별 배치와 입력을 확인한다. [설정](TEST_REPORT.md#14-시작-메뉴-화면그래픽-설정) · [테마](TEST_REPORT.md#15-demonicui-공통-테마) · [배율](TEST_REPORT.md#16-공통-dpi와-전투-화면-배치)

최초 통합 확인은 **싱글 한 Run과 설정 변경·복원 → 2인 협동 → 4인 확대** 순서로 진행한다. 문제가 발생하면 해당 구간의 첫 오류·로그·재현 절차를 기준으로 Codex가 원인과 회귀 범위를 좁힌다. 세부 항목의 미실행 상태는 실제 결과를 받기 전까지 유지한다.

## 2 오류 수정 후 확인

### 2-1 GameplayCue 설정과 경고

- [ ] **전투 효과 검색 경로 보완을 실행에서 확인한다.** `DeveloperSettings`와 함께 UE 5.7이 합산하는 `AbilitySystemGlobals` 설정에 제작 경로를 추가했다. 빈 배열의 최초 원인은 미확정이며 실제 경고 해소는 확인 대기다. 메뉴·일반 2인/4인 전투에서 HUD·Cue 경고를 확인하고 종료 시 NavMesh·Editor 초기화 로그도 추적한다. [문제와 확인 절차](TEST_REPORT.md#8-hudgameplaycue-경고-수정)

### 2-2 전투 준비 취소와 저장 실패

- [ ] **저장 실패 후 준비 취소 재시도를 확인한다.** `FailPreparation`의 취소 대기와 `AbortEncounter`의 저장 실패 복구를 연결했다. 기존 저장 다시 시도 버튼으로 반복 실패 후 복귀하고, 준비 오류를 보존하며 중복 스폰하지 않는지 확인한다. [복구와 데이터 검사](TEST_REPORT.md#18-준비-취소-복구와-파티-데이터-사전-검사)
- [ ] **파티 데이터의 에디터 사전 검사를 확인한다.** 직업 클래스·능력치·시작 스킬 오류와 기존 fallback 수용을 검사한다. 검사 통과를 실제 전투 성공으로 대체하지 않는다. [검증 절차](TEST_REPORT.md#18-준비-취소-복구와-파티-데이터-사전-검사)

## 3 게임 규칙 결정

**이 절은 구현 전에 결정할 기획이다.** 시간차 전투와 집중 자원 제외를 유지하며, 집중 효과를 AP 회복이나 추가 행동으로 자동 치환하지 않는다. 현재 시험값을 최종 규칙으로 간주하지 않는다.

### 3-1 전투 규칙

- [ ] **이동 후 다른 유닛의 칸에 남을 수 있는지 정한다.** 현재는 다른 생존 유닛의 복귀 칸이나 예약 목적지와 겹치면 계획 잠금을 거절한다. 복귀 칸 예약과 최종 배치 규칙을 확정한다.
- [ ] **같은 시각의 공격을 처리할 순서를 정한다.** 서버 순서대로 피해·사망을 즉시 적용할지, 동률 공격을 함께 성립시킬지 결정한다.
- [ ] **계획 수정 시 누구의 준비를 해제할지 정한다.** 현재는 인간 팀원 전원의 준비를 해제하고, 잠금 전 준비 취소를 허용한다.
- [ ] **양 팀이 전멸했을 때 결과와 보상을 정한다.** 현재는 전투를 중단한다. 승패·무승부·재전투 중 처리 방식을 결정한다.
- [ ] **행동 비용과 속도 보정의 최종 규칙을 정한다.** AP/보조 AP의 계획 시작 초기화·잠금 시 차감·불발 시 미환불을 검토한다. 이동·시전·투사체 속도 보정, 속도 비율 정규화와 대기 시간 상한은 후속 기획으로 둔다.
- [ ] **엄호와 상태이상의 처리 경계를 정한다.** 엄호의 중첩·지속·전열 보호, 해로운 상태이상 8종의 발동·감소·해제와 이동·피격·동시 처리 시점을 확정한다. [상태별 미정 사항](STATUS_EFFECTS.md)
- [ ] **AI 전술과 적 의도의 공개 범위를 정한다.** 지원 대상·우선순위, 자기 진영에 남을 이동 좌표와 예약 충돌, Guard·MoveShot·GroundStrike의 AI 후보 편입 여부를 결정한다. 부분 공개·위치 협공은 후속 기획으로 둔다. 인간 초안 이전 AI 계획 고정은 유지한다.
- [ ] **라운드 중단 후 복구할 시점과 데이터를 정한다.** 시전·좌표·투사체·지연 피해·난수·이미 적용한 결과의 복구 범위와 재실행 악용 방지 규칙을 설계한다. 이전 순차 전투의 저장·복구 경로는 재도입하지 않는다.

현재 규칙과 시험값의 상세는 [전투 기획](GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)을 따른다.

### 3-2 아이템과 직업

- [ ] **첫 구현에 사용할 아이템과 직업 스킬을 고른다.** 후보 묶음, 직업별 시작 스킬·효과·피해/회복량·시전/비행/접근 수치·AP/보조 AP 비용을 확정한다. 원작 수치와 ProjectA 수치를 구분한다. [직업 제안](GAME_DESIGN.md#6-1-직업-역할-보충-제안) · [도입 순서 제안](GAME_DESIGN.md#7-10-조합-예시와-도입-순서)
- [ ] **공격 성공 판정 방식을 고른다.** 원작의 슬롯별 성공 판정(완전 성공 효과 포함)을 사용할지, 단순 명중과 별도 효과 조건으로 구성할지 결정한다.
- [ ] **장비 슬롯과 무기 교체 규칙을 정한다.** 손 장비 포함 여부·양손 무기 점유, 무기 스킬과 직업 스킬의 대체/병존을 결정한다. 장착·교체·거래 가능 시점, 전투 중 비용, 출처별 스킬 부여·회수 기준도 정한다.
- [ ] **회복 모델과 파이프 효과를 정한다.** C01 고정량 또는 C02 비율형 회복을 선택한다. 파이프·재질의 발동 조건·효과 소유자·중첩 규칙을 정한다.
- [ ] **아이템·재화의 소유와 거래 권한을 정한다.** 개인/공동 재고·재화, 장비 배분과 구매 권한을 결정한다. 아이템 소유와 캐릭터의 원래 소유권을 구분한다.
- [ ] **상점 상품과 보상 생성 규칙을 정한다.** 상점별 역할·수량·가격, 필수 보급과 역할 보완 여부, 후보 가중치·출현 조건·중복·새로고침 규칙을 결정한다.
- [ ] **Run 동안 유지할 성장과 지급 범위를 정한다.** 장비·스킬·보상·사탕·파이프·소모품을 누적할지 전투마다 재지급할지 정한다. 계정 영구 성장으로 자동 확대하지 않는다.
- [ ] **참조 아이템의 미확인 수치를 대조한다.** 설치본 Build `24247341`의 도감·카드로 피해·가격·재장전·지속/중첩·면역·정화·파이프 발동을 확인한다. A05~A07은 FTK1 기준 아이템과 수치를 지정하며 FTK2 동명 항목으로 대체하지 않는다. [참조 근거](GAME_DESIGN.md#7-11-ftk2-설치본-근거와-해석-범위) · [대조 절차](TEST_REPORT.md#11-아이템-클론-기획-검토)

### 3-3 Run 진행

- [ ] **패배와 사망 후 진행 방식을 정한다.** 즉시 Run 종료를 유지할지, 패배 횟수나 Run 생명력을 둘지 결정한다. 패배 보상, 누적 HP·사망·회복·소모품과 저장 시점도 함께 정한다.
- [ ] **인원별 캐릭터 배정과 Run 길이를 정한다.** 1인당 캐릭터 수·부족 시 배정, 라운드 수·목표 플레이 시간·마지막 인카운터를 결정한다.

## 4 온라인 협동과 경쟁

**T14는 Steam·PlayFab 서비스 준비와 실제 연동이 필요하다.** 비용·소유권·저장 권위의 기준은 [멀티플레이 계약](MULTIPLAYER.md)을 따른다.

### 4-1 서비스 준비

- [ ] **Steam App ID와 PlayFab Title을 준비한다(T14-8).** 실제 인증·연결에 사용할 개발 환경을 정한다. 공용 Steam ID 480 시험안은 채택·실행 전이다. [준비 항목](MULTIPLAYER.md#t14-8-서비스-준비) · [준비 보고서](TEST_REPORT.md#4-t14-8-서비스-준비-보고서)
- [ ] **무료 개발 시험 범위와 출시 비용 조건을 정한다.** 무료 한도 내 시험과 출시 후 운영비를 구분한다. 유료 리소스는 임의로 활성화하지 않는다.
- [ ] **초대·재접속·관전 흐름을 정한다.** Lobby/Invite, 재접속 후 준비 과정, AI로 전환된 캐릭터 소유자의 관전 허용 여부를 결정한다.

### 4-2 서비스 구현과 검증

- [ ] **Steam 인증·P2P 접속과 협동 화면을 연결한다.** 실제 계정과 원래 참가자를 확인하고 초대·참가·관리 Run 재개·Host 승계 화면을 구현한다. 개발용 새 방 UI와 관리 Run 재개를 구분한다.
- [ ] **여러 PC에서 같은 Run을 안전하게 저장한다.** 정본 저장 위치와 인증 방식을 정하고, 중복 실행·동시 승계를 한 번만 승인하도록 처리한다. 라운드 복구는 [3-1절](#3-1-전투-규칙)의 결정 후 연결한다.
- [ ] **상대 전투 데이터의 온라인 저장·매칭을 구현한다.** Snapshot에 포함할 장비·소모품·성장·속도·전술과 콘텐츠 버전을 정한다. AI 사용량·소모 반영, 전송·보존·버전 변환과 데이터 검증을 설계한다.
- [ ] **경쟁 점수와 결과 검증을 설계한다.** MMR 반영 대상 확정 시점·계산/정산 단위·공격/방어 결과를 정한다. 고의 이탈·턴 반복·중복 결과·위변조를 막을 책임과 방식을 결정한다.
- [ ] **T14의 실제 서비스 수용 조건을 검증한다.** 저장된 상대 Snapshot으로 새 라운드 전투를 실행하고, 최소 2인에서 소유권·계획·행동 시작 시각·실제 위치·HP/AP·사망·결과가 일치하는지 확인한다. 로컬 모의 저장소나 같은 PC의 PIE 결과를 서비스 연동 검증으로 대체하지 않는다.

P2P 연결과 중앙 저장·계정 인증·MMR 검증은 각각 필요하다. 이전 Combat 저장 복원은 지원 범위에 포함하지 않는다.

## 5 디자인 확정 후 구현할 일

**아래 작업은 필요한 기획·시각 디자인이 확정될 때까지 보류한다.** 각 항목의 선행 조건을 충족한 뒤 구현한다.

- [ ] **아이템 데이터와 거래 기능을 구현한다.** [3-2절](#3-2-아이템과-직업)의 슬롯·회복·소유·장착·가격 규칙을 먼저 확정한다. 정적 정의·Run 인스턴스·성장 상태·명령·Snapshot 필드를 설계하고 기존 DataAsset·USTRUCT·USaveGame·GAS를 확장한 뒤 사용자 작동 검증을 진행한다.
- [ ] **직업별 실제 스킬 프로필을 연결한다.** 스킬 목록·수치와 시작 데이터를 먼저 확정한다. 기존 공격 변환이 처리하지 못하는 회복·버프·몽타주 효과는 명시 프로필로 연결한다.
- [ ] **상태이상과 지원·이동 AI 전술을 구현한다.** [3-1절](#3-1-전투-규칙)의 발동·중첩·이동 경계와 선택 우선순위, 검증할 기대 결과를 먼저 확정한다.
- [ ] **아이콘·모델·애니메이션·VFX를 제작한다.** 직업/스킬별 표현 목록과 제작 사본 경로, 서버의 타격·발사·복귀 시점에 연결할 방법을 먼저 확정한다. 애니메이션 알림에 피해 권위를 넘기지 않는다.
- [ ] **최종 UI 디자인을 적용한다.** 계획·대상·비용·오류·적 의도의 정보 우선순위와 선택/비활성 표시, 화면 비율별 배치 시안을 먼저 확정한다. 기존 입력·소유권·공통 DPI 기준을 유지한다.
