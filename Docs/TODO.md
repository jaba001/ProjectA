## T14-7 검증 범위

이 절은 ff22940 순차 전투 검증 이력이다. 확정 턴 복원과 턴 종료 RPC는 현재 실행 경로가 아니며 새 라운드 재검증에 사용하지 않는다.

- 3명 중 최초 Host 불참 → 2번 Host·3번 Client·1번 AI.
- 4명 중 최초 Host 불참 → 2번 Host·3/4번 Client·1번 AI.
- 4번 단독 재개 → 4번 Host·나머지 AI, 다음 전투에서도 AI 유지.
- 각 Client의 서버 발급 바인딩과 원래 계정·자기 캐릭터 조작권, 실제 요청 승인, 동일 전투 상태 확인.
- 메뉴 이동 실패 후 같은 저장으로 재시도, 종료된 실행 권한·오래된 요청·이미 AI인 계정의 인간 복귀 거절 확인.

과거 개발 fixture는 관리 Run의 호출자·대상을 설정했다. 순차 전투·Combat 승계 PIE fixture는 현재 소스에서 제거했으며 Git 이력에서 조회한다. 새 개발용 협동 UI는 비관리 방을 생성하며 서버가 참가 번호를 발급한다. 관리 Run의 수동 협동 재개·승계 화면은 아직 없고 개발용 새 방 UI의 검증도 별도다. 세부 실행 방법·기대 결과·기록란은 [TEST_REPORT](TEST_REPORT.md)에 둔다.

## 8 시간차 자동 전투 후속 결정

기준 규칙은 [GAME_DESIGN 8절](GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)에 통합한다. 속도 차당 0.1초, 상대 진영 공격 접근, 유닛 간 비충돌, 일반 복귀·자기 진영 이동 공격, 발동 전 사망 취소·발사체 존속, 실시간 피격, 속도순 지원, 잔여 공격까지 정리한 라운드 종료, 인간 초안 이전 적 계획 고정은 확정 방향이다. 아래는 미결정 계약이며 권장안은 사용자 확정을 대신하지 않는다.

### 8-1 확인 대기와 구현 기본값

| 우선순위 | 항목 | 현재 구현과 필요한 결정 |
|---|---|---|
| 높음 | 복귀 칸·최종 배치 | 접근 중 Home 칸 예약, 다른 생존 유닛 Home/최종 목적지에 잔류하려면 잠금 거절. 임시 정책이며 사용자 확인 필요 |
| 높음 | 같은 시각의 타격 | 같은 예정 시각에도 서버 처리 순서로 피해·사망 즉시 적용. 동률 공격 상호 성립을 보장하지 않는 임시 정책이며 사용자 확인 필요 |
| 높음 | 계획 수정 | 인간 계획 수정 시 인간 팀원 전원 Ready 해제. 잠금 전 준비 취소 허용. 임시 정책이며 사용자 확인 필요 |
| 높음 | 동시 전멸 | 양 팀 전멸은 현재 Suspended, 결과·보상 미확정. 승패/무승부/재전투 정책 필요 |
| 높음 | 장착 스킬 변환 | 명시 RoundDefinition 미지정 시 지원되는 EnemyUnit 단일/대상 주변 공격만 초기 변환. 기타 능력은 명시 프로필 필요 오류. 회복·버프·기존 몽타주 효과의 완전 변환 아님. 직업별 명시 프로필과 시험 밸런스 필요 |
| 중간 | 준비 취소 저장 실패 | 기존 관리 Run의 `FailPreparation`이 `AbortEncounter` 저장 실패를 처리하지 않으면 액터 없이 Preparing/Combat에 남을 수 있음. 오류 전달·취소 재시도 경로 보완 필요 |
| 중간 | 지원·상태 | 초기 Guard는 강한 값으로 갱신, 피격 시 소비, 다음 라운드 초기화. 정식 중첩·지속·전열·상태효과 정책 필요 |
| 중간 | AI·공개 | 적/아군 AI는 초안 전에 기존 스킬 순서·가까운 적 기준으로 단일 명령 고정, UI 전체 공개. 장착된 복귀형 Tile 공격의 목표/접근은 연결. 지원·잔류 이동 전술과 최종 공개 수준은 미결정 |
| 통합 전 | 복구·저장·경쟁 | 이전 Combat 로드·재개 거절, 비전투 저장만 재개. 새 라운드 복구 경계·재실행 악용·Snapshot Speed/콘텐츠 버전 정책 필요 |

속도 시작값은 양 팀 생존자의 라운드 시작 `CombatSpeed`로 고정한다. AP/SubAP는 계획 시작 초기화·명령 잠금 차감·불발 미환불의 초기 구현값이다. 스킬별 접근/목표 상실/비행 정책은 `RoundDefinition`에 명시할 수 있다. 위 임시 구현값은 사용자 확정을 대신하지 않는다.
