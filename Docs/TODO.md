# 남은 기획과 확장 준비

현재 10전투·9상점 시험 Run과 로컬 협동의 구현·UE 5.7 자동화 검증 이력은 [현재 구조](PROJECT_PLAN.md)와 [검증 이력](HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 이 문서는 목표 Run의 세부 규칙, 온라인 서비스, 신규 에셋의 선행 결정과 그 뒤의 구현 및 UE 5.8 사용자 작동 확인을 기록한다. 시험 Run의 완료 범위와 정상 난이도·사용자 직접 조작·서비스 검증 범위를 혼동하지 않는다.

## 3-3 Run 진행

2026-09-22 사용자 확정: 목표 플레이 시간은 고정하지 않는다. **인카운터 3회 → 몬스터 PvE 1회 → 인카운터 3회 → Async PvP 1회**를 10회 반복한다. 정상 완주 시 인카운터 60회·PvE 10회·PvP 10회이며, 각 인카운터의 후보 3개 중 하나 선택 규칙을 유지한다. 목표 순서·횟수는 확정했지만 단계별 풀·편성·성장/보상·PvP 연결 규칙이 미정이므로 전체 Run 구현은 대기다. 현재 10전투·상점 9회의 시험 Run과 구분한다. [목표 Run](GAME_DESIGN.md#2-목표-run과-현재-구현)

- [ ] **Run 내 사망·회복·소모품의 세부 규칙을 정한다.** 양 팀 전멸은 패배·Run 종료·승리 보상 없음으로 확정했다. Run 중 누적 HP·사망·소모품의 처리와 추후 회복·부활 인카운터의 연결을 결정한다. Run 종료 후 성장·재화·아이템 보상은 없으며 MMR의 패배·이탈 계산은 별도 기획이다.
- [ ] **협동 인원별 캐릭터 배정을 정한다.** 1인당 캐릭터 수·부족 슬롯 배정을 결정한다. 일반 싱글의 직접 조작 1명·나머지 동료 AI 정책은 유지한다.
- [ ] **기획 확정 후 목표 Run 구성을 구현한다.** 단계별 인카운터 풀·PvE 편성·난이도·성장/보상과 PvP 연결 규칙을 결정한 뒤 진행·저장·UI에 연결한다. 수용 조건은 새 Run이 인카운터부터 시작하고 정상 완주 시 정해진 순서와 횟수를 충족하며, 재개 후에도 진행 위치와 이미 확정한 선택을 유지하는 것이다. 현재 구현은 10전투·상점 9회의 시험 Run이다.

## 4 온라인 협동과 경쟁

**T14는 Steam·PlayFab 서비스 준비와 실제 연동이 필요하다.** 계정·서비스 ID·비용 조건과 온라인 권위 정책이 준비되지 않은 항목은 외부 준비/결정 대기다. 로컬 코드·문서 점검은 독립적으로 진행하되 서비스 활성화·실제 연결 완료로 기록하지 않는다. 비용·소유권·저장 권위의 기준은 [멀티플레이 계약](MULTIPLAYER.md)을 따른다.

### 4-1 서비스 준비

- [ ] **Steam App ID와 PlayFab Title을 준비한다(T14-8).** 실제 인증·연결에 사용할 개발 환경을 정한다. 공용 Steam ID 480 시험안은 채택·실행 전이다. [준비 항목](MULTIPLAYER.md#t14-8-서비스-준비)
- [ ] **무료 개발 시험 범위와 출시 비용 조건을 정한다.** 무료 한도 내 시험과 출시 후 운영비를 구분한다. 유료 리소스는 임의로 활성화하지 않는다.
- [ ] **초대·재접속·관전 흐름을 정한다.** Lobby/Invite, 재접속 후 준비 과정, AI로 전환된 캐릭터 소유자의 관전 허용 여부를 결정한다.

### 4-2 서비스 구현과 검증

- [ ] **Steam 인증·P2P 접속과 협동 화면을 연결한다.** 실제 계정과 원래 참가자를 확인하고 초대·참가·관리 Run 재개·Host 승계 화면을 구현한다. 개발용 새 방 UI와 관리 Run 재개를 구분한다.
- [ ] **여러 PC에서 같은 Run을 안전하게 저장한다.** 정본 저장 위치와 인증 방식을 정하고, 중복 실행·동시 승계를 한 번만 승인하도록 처리한다. [준비 완료 복구 계약](MULTIPLAYER.md#준비-완료-경계와-파일-저장)을 온라인 정본 저장에 연결한다.
- [ ] **상대 전투 데이터의 온라인 저장·매칭을 구현한다.** Snapshot에 포함할 장비·소모품·성장·속도·전술과 콘텐츠 버전을 정한다. AI 사용량·소모 반영, 전송·보존·버전 변환과 데이터 검증을 설계한다.
- [ ] **경쟁 점수와 결과 검증을 설계한다.** Run 종료 시 MMR만 반영하는 방향은 확정했다. 반영 대상 확정 기준·시점, 계산식·개별 PvP 결과의 합산 방식·공격/방어 결과 반영을 정한다. 고의 이탈·턴 반복·중복 결과·위변조를 막을 책임과 방식을 결정한다.

P2P 연결과 중앙 저장·계정 인증·MMR 검증은 각각 필요하다. 이전 Combat 저장 복원은 지원 범위에 포함하지 않는다.
