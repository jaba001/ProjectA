| 번호 | 상태 | 범위와 완료 조건 |
|---|---|---|
| 1 | 완료 | Run·원래 참가자·캐릭터 소유권 데이터, 저장 왕복·v1 호환 |

기본 수용 조건은 저장된 상대 Snapshot의 Combat 실행과 최소 2개 PIE의 소유권·Turn·Grid·HP/AP·사망·결과 일치다. 승인된 승계·AI 재개·실서비스 범위까지 완료하려면 7·8번의 잔여 조건을 충족해야 한다.

## T14-7 검증 범위

- 3명 중 최초 Host 불참 → 2번 Host·3번 Client·1번 AI.
- 4명 중 최초 Host 불참 → 2번 Host·3/4번 Client·1번 AI.
- 4번 단독 재개 → 4번 Host·나머지 AI, 다음 전투에서도 AI 유지.
- 각 Client의 서버 발급 바인딩과 원래 계정·자기 캐릭터 조작권, 실제 요청 승인, 동일 전투 상태 확인.
- 메뉴 이동 실패 후 같은 저장으로 재시도, 종료된 실행 권한·오래된 요청·이미 AI인 계정의 인간 복귀 거절 확인.

기존 개발 fixture가 관리 Run의 호출자·대상을 설정한다. 일반 새 게임 화면만으로 협동 Run을 만들거나 번호를 선택할 수 있는 기능은 아직 없다. 세부 실행 방법·기대 결과·기록란은 [TEST_REPORT](TEST_REPORT.md)에 둔다.

## T14-8 준비·결정 사항

| 항목 | 확정한 범위 | 아직 필요한 정보·결정 |
|---|---|---|
| 연결·비용 | Steam P2P + Unreal Listen Server 우선, Steam+PlayFab 선택, 운영비 회피 | App ID·개발 Title 준비 여부, 무료 개발 한도 내 시험 범위, 출시 운영비 허용 범위 |
| 세션 | 원래 참가자만 조작, 최대 4인 | Lobby/Invite UX, 재접속·Ready 흐름, AI 소유자 관전 허용 |
| 저장 권위 | 로컬 lease/CAS 계약과 영구 인간 참가 목록 | PC 간 정본 저장, 인증된 원래 참가자 확인, 중복 실행·승계 경쟁 원자 처리 |
| 상대 Snapshot | 로컬 v1·미지원 버전 거절 | 온라인 저장/전송·매칭·보존·마이그레이션, 빌드/장비/전술 데이터 검증 |
| MMR | AI 전환 후 현재 인간 참가자만 반영 | 대상 확정 시점, 계산·정산 단위, 공격/방어 결과, 고의 이탈·턴 반복·중복 결과 방지 |
| 결과 검증 | Host가 전투 상태를 확정 | 경쟁 결과의 위변조 검증 책임과 구현 방식 |

P2P만으로 원격 공유 저장·계정 인증·MMR 검증이 해결되지는 않는다. 로컬 모의 저장소, 테스트 계정 식별자, 일부 복제 선언이나 같은 PC의 PIE 성공을 실제 서비스 완료로 기록하지 않는다.
