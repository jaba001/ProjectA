## 3-3 Run 진행

2026-09-22 확정한 **인카운터 3회 → 몬스터 PvE 1회 → 인카운터 3회 → Async PvP 1회**의 10회 반복을 새 싱글 Run에 구현했다. 각 선택의 후보는 3개이며 총 60선택·10PvE·10로컬 Snapshot 경로다. 온라인 PvP는 서비스 준비 후 연결한다. 기존 2/10전투 저장과 개발 협동은 원래 경로를 보존한다. [목표 Run](GAME_DESIGN.md#2-목표-run과-현재-구현)

2026-10-04 사용자 선택: 제안 9는 선택 2, 제안 6~8·10~14는 선택 1을 채택했다. 아래 선택 체크는 구현 완료를 뜻하지 않는다. 양 팀 전멸은 패배·Run 종료·승리 보상 없음, 회복·부활 인카운터 추가와 Run 종료 후 MMR만 반영하는 방향은 유지한다. 성장·재화·아이템·스킬·소모품은 다음 Run에 이월하지 않는다.

- [x] 선택 1: 누적 HP와 사망 슬롯을 Run 동안 유지하고 생존한 본인 캐릭터가 전투에서 회복 소모품을 사용한다. 사망자는 부활 인카운터에서만 복귀한다.
- [ ] 선택 2: 누적 HP·사망 보존은 같고 소모품은 비전투 인카운터에서만 사용한다. 전투 중 회복 수단은 스킬로 제한한다.

권장: 선택 1. 소모품을 전투 선택에 연결하되 서버의 소유권·생존·사용량 검증이 추가된다. 선택 후 사용 비용·회복량·부활 상태를 데이터로 정의하고, 사용과 수량·HP 저장을 함께 확정한다. 수용 조건은 중복 요청의 중복 소모 방지, 저장 실패 시 원상 유지, 재개 후 HP·사망·잔여 수량 일치다.

### 3-3-2 제안 7 협동 캐릭터 배정

- [ ] 선택 2: 협동도 1인 1캐릭터를 직접 조작하고 부족 슬롯은 동료 AI로 채워 4캐릭터를 유지한다. 동료의 원래 소유자는 Run 생성 전에 지정한다.

권장: 선택 1. 추가 AI의 비전투 장비·보상 결정권을 정하기 전에 원래 소유권과 2/4인 흐름을 확인할 수 있다. 선택 후 생성·편성·저장 UI를 연결한다. 수용 조건은 각 인간의 자기 캐릭터 조작과 초기 소유권 보존이며 참가 번호 1·2·3·4와 캐릭터 슬롯을 혼동하지 않는 것이다. Host 승계·AI 전환·복귀로 소유권을 이전하지 않는다.
