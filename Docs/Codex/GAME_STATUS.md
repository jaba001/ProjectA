## 1 게임 개요

파티 빌드를 성장시키며 상대 Party Snapshot과 Grid 전술 전투를 치르는 로그라이트다. 라운드마다 행동을 계획하고 속도 차에 따른 시간차 자동 전투로 해결한다. 목표는 Async PvP와 최대 4인 Co-op이며, 기본 Run은 싱글플레이다.

| 영역 | 현재 상태 |
|---|---|
| 싱글 Run | 목표 경로 80단계 구현. PvP 자리는 로컬 Snapshot 상대 |
| 전투 | 라운드 계획·SAP 이동·속도 기반 시간차 실행·서버 충돌 판정·상태이상 8종 |
| 성장·경제 | PvE 승리 성장·휴식·아이템 3택1·공통 골드, 상점 구매·판매·리롤 |
| 협동 | 같은 PC Listen Server 2·4인 개발 협동, Steam 480 개발 연결 시제품 |
| 온라인 | 계정·PlayFab·중앙 저장·MMR 정산·온라인 Snapshot 미구현 |

## 2 Run 진행

```text
파티 생성 → Run 시작
→ [인카운터 ×3 → 하·중·상 선택 → 몬스터 PvE → 인카운터 ×3 → 로컬 Snapshot 전투] × 10
→ Run 결과
```

- 정상 완주 기준 인카운터 60회·PvE 10회·Snapshot 10회다. 각 인카운터는 후보 3개 중 하나를 고른다.
- PvE 직전에 좌회전·하, 직진·중, 우회전·상 중 하나를 고른다. 하·중·상은 각각 초원·석조 던전·얼음 성채에서 진행하며 같은 편성에 체력·속도·골드 배율을 적용한다([PVE_DIFFICULTIES](../../DataCatalogs/PVE_DIFFICULTIES.csv)).
- 지역은 숲 1~2·늪 3~4·동굴 5~6·설원 7~8·최종 9~10묶음이며 7묶음은 적 수를 줄인 재정비 구간이다. 기준 HP는 첫 몬스터 50·100·150, 마지막 골렘 1000·1500·3000이다([PVE_HEALTH_CURVE](../../DataCatalogs/PVE_HEALTH_CURVE.csv)).
- 편성·HP·골드·성장 수치는 Run 생성 시 CSV에서 읽어 저장한다. CSV 수정은 이후 새 Run에만 반영된다.
- PvE 승리: 최대 HP +5·속도 +1, 생존자 휴식 HP 20~40(사망자 부활 없음), 아이템 3개 중 1개, 공통 골드(첫 묶음 3~5G ~ 마지막 8~15G). 아이템은 가방에 추가하며 자동 장착하지 않는다.
- Snapshot 전투와 패배에는 성장·아이템·골드·휴식이 없다. 양 팀 전멸은 패배이며 Run이 종료된다.
- 회복·부활: 회복약 HP 25/AP 1/시작 1개/1G, 회복의 샘물 HP 25/1G, 부활소 최대 HP 25%/1G.
- Run 종료 시 MMR만 반영하는 정책이며 성장·골드·장비·스킬은 이월하지 않는다. MMR 계산·정산은 미구현이다.
- 싱글 새 게임은 1~4명을 만들고 직접 조작할 1명을 고른다. 나머지는 서버 AI가 조작하며 직접 조작 캐릭터가 죽어도 생존 동료가 있으면 전투를 계속한다. 시작 골드는 직접 조작 캐릭터 10G이고 AI 동료에게는 골드를 주지 않는다.

## 3 장비와 무기 스킬

| 부위 | 슬롯 |
|---|---|
| 무기 | 2 (양손 무기는 2칸 점유) |
| 투구·장갑·신발·갑옷·목걸이 | 각 1 |

- 시작 장비: 전사 한손검+방패, 궁수 활, 마법사 스태프, 도적 단검. 장착 상태로 지급한다.
- 장착 변경은 본인 생존 Human이 상점 단계에서 드래그 앤 드롭으로 하며 골드를 쓰지 않는다.
- 장착 지원 원본은 49개(단검 20·방패 15·활 11·한손/양손검 2·시작 스태프 1)이며 상점·보상 후보도 이 범위로 제한한다([WEAPON_ASSETS](../../DataCatalogs/WEAPON_ASSETS.csv)).
- 스킬은 스킬상점이 아니라 장착 무기에서 얻는다. 비무장 기본 공격 + 장착 무기 사본의 확정 스킬을 쓰며 총 스킬 수 상한은 없다.
- 무기 사본은 생성 시 카탈로그 등급을 적용하고 GameplayTagQuery로 맞는 스킬 1개를 추첨해 고정한다. 재장착·Continue로 재추첨하지 않는다.
- 스킬 후보: 근접 무기→근접·참격, 활→정밀 화살·화염 화살비, 석궁→석궁 공격, 지팡이·마법서→마법 47종, 방패→수호 7종(`Skill.Effect.Shield`). 탄약·기타는 등급만 부여한다.

## 4 상점과 인카운터

인카운터는 같은 Gameplay 레벨의 지하 미로로 표현한다. 사각 선택 방의 앞벽 문 3개가 후보 0·1·2(좌·직진·우)에 대응하며, Host가 고르면 선택한 문으로 이동해 NPC를 만난다. 미로 배치는 RunId 기반 시드로 고정하며, 8개 변형의 벽·바닥·천장은 `BP_EncounterMaze_V0~V7` Blueprint로 저장되어 에디터에서 직접 고칠 수 있다. 상세 구성은 [PROJECT_PLAN 4-13](PROJECT_PLAN.md#4-13-통합-gameplay와-npc-상점)을 따른다.

| 그룹 | 그룹 가중치 | 변형 |
|---|---:|---|
| 기본상점 | 40 | 1 |
| 등급별상점 | 20 | 흰 50·초록 30·파랑 15·보라 4 |
| 태그별상점 | 20 | 검·단검·활·지팡이·방패 각 1 |
| 회복의 샘물 | 10 | 1 |
| 소모품상점 | 7 | 1 |
| 부활소 | 3 | 1 |

- 그룹을 먼저 뽑고 변형을 뽑는다. 한 회차에 같은 ID는 중복되지 않는다([ENCOUNTER_POOL](../../DataCatalogs/ENCOUNTER_POOL.csv), 활성 13개).
- 기본상점은 상품 5개, 전문 상점은 적격 상품 최대 5개를 진열한다. 가격·리롤 1G.
- 판매: 미장착 보유품을 저장 가격의 절반(최소 1G)에 판다. 서비스·소모품 판매와 되사기는 없다.
- 직업별 NPC(검 제작자·도적·궁수·마법사·방패 기사)를 배치하며 회복의 샘물은 NPC 없이 수반으로 표현한다.
- 협동에서는 본인 소유의 생존 Human만 구매·리롤하며 상점 선택·퇴장은 Host가 결정한다.
- 기존 저장·명시적 prototype·개발 협동 경로는 이전 스킬상점 규칙(10전투·9상점)을 유지한다.

## 6 라운드 전투

```text
적 계획 고정 → 인간 계획(대상 클릭 → 장착 스킬 선택, 선택적으로 SAP 이동 예약) → 준비 완료(저장 성공 후 확정)
→ 전원 준비·저장 → 명령 잠금·AP/SAP 차감 → SAP 이동 전체 실행 → AP 시계 0초부터 속도순 행동
→ 모든 행동·복귀·투사체·상태 피해 정리 → 결과 확인 또는 다음 라운드
```

- 스킬 없이 준비하면 그 유닛은 AP 행동을 건너뛴다. SAP 이동만 예약하면 SAP 1만 쓴다.
- 잠금 전에는 준비를 취소할 수 있으며 계획을 고친 소유자의 준비만 해제한다. 선택 제한시간은 없다.
- SAP 이동: 8방향 빈칸 BFS·아군 진영 내 목적지 1개, 비용 SAP 1, 고정 속도 350cm/s. 도착 칸이 새 복귀점이다.
- 시작 지연(초) = (라운드 시작 생존자 최고 속도 − 유닛 속도) × 0.1. Planning에서 고정하며 실행 중 변경은 다음 라운드에 반영한다.
- 근접 접근·복귀 속도 = min(MoveSpeed × (0.25 + Speed / 40), 100000). 유닛 간 이동 충돌은 없고 상대 진영에 남는 결과는 허용하지 않는다.
- 적중은 서버의 실제 충돌로 판정한다. 근접은 전방 sphere sweep, 지점 공격은 벽 차폐를 적용한 sphere overlap, 투사체는 첫 적 또는 벽에서 종료한다. 명중 확률은 없다.
- 발동 전 시전자가 죽으면 공격을 취소하고, 이미 발사된 투사체는 유지한다. 발동 전 대상이 죽으면 가장 가까운 유효 적으로 재선택한다.
- 비용은 잠금 시 한 번 차감하며 불발·사망에도 환불하지 않는다.
- 준비 완료 시점마다 체크포인트를 저장하고, 강제 종료 후 마지막 준비 완료 상태로 복구한다.
- 준비 확정 후 본인 캐릭터의 오른쪽 숄더뷰로 전환하고, 근접은 복귀 시작, 원거리·마법은 최초 피격 또는 불발 종료에 0.45초 블렌드로 전술뷰로 돌아온다.
- 적 AI는 기존 스킬 순서와 가까운 적 기준으로 계획한다.

## 7 상태이상

스킬의 `RoundDefinition.StatusApplications`(태그 + 수치)로 부여하며, 성공한 피격 후 대상이 살아 있으면 적용한다. 수치형은 재부여 시 합산한다. 사망·전투 종료 시 모두 제거하고 전투 사이에 이어지지 않으며 정화는 없다. 조정값은 `Config/DefaultGame.ini`의 `[/Script/ProjectA.ProjectAStatusEffectSettings]`에 있다.

| 상태 | 규칙 |
|---|---|
| 화상 `Status.Burning` | 라운드 종료 시 B 피해 후 `max(0, floor(B/2)-1)`로 감소 |
| 중독 `Status.Poisoned` | 화상 다음에 P 피해 후 1 감소 |
| 출혈 `Status.Bleeding` | SAP 이동 한 칸마다 수치만큼 피해. 2라운드 뒤 제거 |
| 냉각 `Status.Chilled` | 다음 라운드부터 2라운드 동안 속도 −수치(최소 1) |
| 빙결 `Status.Frozen` | 대기 중 행동이 남았으면 취소, 아니면 다음 라운드 행동·이동 차단 |
| 스턴 `Status.Stunned` | 대기 중 행동이 남았으면 취소. 이월 없음 |
| 혼란 `Status.Confused` | 다음 라운드 명령을 합법적인 무작위 명령으로 대체. 빙결이 우선 |
| 감전 `Status.Shocked` | 다음 피해 스킬 피격 시 대상과 같은 진영 상하좌우 유닛에 S 번개 피해 후 제거. 2라운드 뒤 만료 |

공격 스킬 43개에 속성별 잠정 상태이상을 배정했다([SKILL_STATUS_EFFECTS](../../DataCatalogs/SKILL_STATUS_EFFECTS.csv)): 불→화상, 냉기→냉각(보라 이상 빙결 추가), 번개→감전, 카오스→중독, 물리 참격→출혈, 바위 계열→스턴.

## 8 협동과 PvP 범위

- 협동은 최대 4인, 인간 1명당 캐릭터 1개다. 원래 소유자만 자기 캐릭터를 조작하며 참가 번호(Host 1번, 이후 합류 순)는 고정이다. 세부 정책은 [AGENTS.md](../../AGENTS.md#데이터와-멀티플레이-확장-원칙)와 [MULTIPLAYER](MULTIPLAYER.md)를 따른다.
- 현재 같은 PC Listen Server 개발 협동과 Steam 480 개발 연결 시제품만 있다. 실제 2PC·PlayFab·중앙 저장은 준비 대기다.
- PvP는 로컬 Snapshot 고정 상대와 싸운다. 장비·전술 ID는 빈 값만 지원하며 온라인 게시·매칭·결과 검증은 미구현이다.
