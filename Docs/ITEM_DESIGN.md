# 아이템 기획

무기·방어구·액세서리와 상점 가격에 관한 미구현 작업과 미결정 제안을 둔다. 운영 규칙은 [TODO](TODO.md)와 같다. 구현을 마친 항목은 삭제하고, 선택 체크는 채택 결과이며 구현 완료가 아니다. 제안 번호는 TODO와 공유하며 다시 매기거나 재사용하지 않는다. 검수 항목은 [REVIEW](REVIEW.md)에 둔다.

- 설계 방향과 수치 원칙은 [TODO 32절](TODO.md#32-기획-폴리싱)을 따른다. 수치는 구조 예시이며 최종 값은 사용자가 정한다.
- 제안 31·32는 사용자가 재기획할 러프 초안이다(2026-10-17).
- 사용자 결정(2026-10-21): 초록을 삭제하고 흰·파랑·보라·주황 4등급으로 전환한다. 흰색은 일반(Common), 보라는 희귀(Rare), 주황은 고유(Unique)로 부른다. 고유의 색은 주황을 유지한다. 파랑의 이름은 미정이며 고급(Uncommon)을 권장한다. 구현은 현재 5등급이다.
- 아이템 효과와 무기 스킬·속성은 아이템 정의에 고정하며 PoE식 접두·접미 랜덤 옵션과 사본별 스킬 추첨을 쓰지 않는다. 20전투 Run에서 옵션 비교 피로도와 빌드 축 희석을 피하기 위함이다.
- 새 아이템 목록은 에셋과 무관하게 먼저 확정하고 외형 에셋은 그 뒤에 배정한다(2026-10-25 사용자 결정). 초안은 [3절](#3-새-아이템-목록-초안)의 CSV다.

## 1 방어구·액세서리 도입

ROG Modular Medieval Accessories and Robes(`Content/ROG_Modular_Armor/Accessories_Robes`)로 빈 슬롯의 아이템을 만든다. 슬롯 개편(액세서리 1칸 통합)과 몸체 포즈 추종 착용, 디버그 전투 시범 6종은 구현했다. 사용자 결정: 망토는 액세서리, 팔목 보호대는 장갑 분류, 어깨 보호대는 상의와 섞은 특정 장비로 나중에 추가한다.

- [ ] 시범 착용 결과([REVIEW 1](REVIEW.md#1-rog-방어구-시범-착용-3e54746e))를 보고 전체 도입 여부를 정한다. 체형이 맞지 않으면 의상 보정 또는 몸체 교체를 먼저 정한다.
- [ ] 여자 몸체에 Quinn용 메시를 쓸지 정한다. 같은 아이템이 몸체별 메시를 갖는 데이터 구조가 필요하다.
- [ ] 로브 16·장갑 15·팔목 보호대 22·망토 26종으로 ARMOR_ASSETS 카탈로그를 확장한다. 팔목 보호대는 좌우 메시 2개를 한 아이템으로 묶는 표시 구조가 필요하다.
- [ ] 방어구·액세서리를 상점·보상 후보에 연결한다. 현재 판매 카탈로그 검증은 `Item.Weapon` 태그를 전제하므로 저장 호환을 유지하며 일반화한다.
- [ ] 아이템 효과는 제안 24(태그 패시브) 선택 후 연결한다. 효과 연결 전 상점 노출 여부는 사용자가 정한다.
- [ ] 아이콘이 팩에 없다. 에디터 도구로 썸네일을 렌더링해 에셋으로 저장한다.
- [ ] 어깨 보호대 35종을 상의와 섞은 특정 장비로 추가한다. 투구·신발은 Armor_Cloth 각 1종뿐이라 별도 원본이 필요하다.
- 수용 조건: 착용 의상은 서버 판정·충돌에 관여하지 않고, 협동 클라이언트와 Snapshot에도 같게 보이며, 기존 Run 저장의 무기 장착이 유지된다.

## 2 제안

### 2-1 제안 24 방어구·장신구 태그 패시브

- 현재: 상점·보상의 장착 원본은 무기 49개뿐이고 투구·장갑·신발·갑옷·액세서리 5칸은 비어 있다. ROG 시범 의상 6종은 디버그 전투에만 있다([1절](#1-방어구액세서리-도입)). 장비 능력치 연결은 없어 빌드 축이 무기 스킬 하나다.

- [ ] 선택 1: 방어구·장신구에 GameplayTag 조건 패시브를 붙인다(예: 화상 대상에게 피해 증가, 감전 연쇄 대상 증가, 출혈 대상 이동 피해 증가). GAS GameplayEffect로 적용한다.
- [ ] 선택 2: 최대 HP·속도 같은 고정 능력치만 부여한다.
- [ ] 선택 3: 방어구 대신 무기 사본에 보조 옵션을 추가한다.

- 권장: 선택 1. 상태이상 8종과 속성 태그가 이미 있어 데이터만으로 "화상 빌드", "감전 빌드" 같은 방향을 만들 수 있다. 체력 보존 방향에 맞춰 피해 감소·휴식 회복 증가 같은 방어 패시브도 같은 구조로 넣을 수 있다.
- 영향: 상점·보상 후보 범위, Snapshot 게시 범위(제안 12의 장비 빈 값), 장착 UI 슬롯 표시를 함께 바꾼다.
- 수용 조건: 패시브 조건은 GameplayTagQuery로 판정하고 이름·클래스 하드코딩을 쓰지 않는다. 후보는 기존 등급 추첨 공통 로직을 재사용한다. 장착 해제 시 효과가 제거되고 저장·복원 후에도 같다.

- 현재: 상품·리롤 가격이 모두 1G라 무엇을 살지보다 살 수 있는지만 따진다.

- [ ] 선택 1: 등급별로 가격을 차등한다.
- [ ] 선택 2: 등급별 가격에 보유 골드 이자를 더한다.

### 2-3 제안 31 아이템 효과 구조와 방어구·액세서리 초안

### 2-4 제안 32 무기 재설계와 4등급제 초안

에셋과 무관한 러프 초안이며 사용자가 이를 토대로 재기획한다(2026-10-17).

- 진행 순서(2026-10-25 사용자 결정): 새 아이템 목록(스킬·속성·등급)을 에셋과 무관하게 먼저 확정하고 외형 에셋은 그 뒤에 배정한다. 현재 무기 원본 49개는 아이템 목록이 아니라 배정 후보 메시다. 목록 초안은 [3절](#3-새-아이템-목록-초안)이다.
- 현재: 5등급(흰·초록·파랑·보라·주황)이며 무기 사본마다 장비 등급 × 스킬 등급 가중치로 스킬 1개를 추첨한다([3절 규칙](GAME_STATUS.md#3-장비와-무기-스킬)). 스킬 62종이 형태·속성 조합별로 따로 만들어져 있다.
- 구조: 무기 = 종류(스킬 형태) × 속성 태그(상태이상) × 등급(스킬 단계·패시브). 스킬은 속성 중립 형태로 만들고 아이템 정의(카탈로그 행)에 고정하며 사본 생성 시 추첨하지 않는다. 속성 태그도 아이템 정의에 고정한다(2026-10-21 사용자 결정). 상태 연결은 기존 [SKILL_STATUS_EFFECTS](../DataCatalogs/SKILL_STATUS_EFFECTS.csv) 규칙(불→화상, 냉기→냉각, 번개→감전, 카오스→중독, 물리 참격→출혈, 바위 계열→스턴)을 따르고 새 무기의 타격·방패 강타는 스턴으로 둔다.
- 4등급 전환안: 초록 삭제와 일반·희귀·고유의 명칭은 사용자 결정이며 파랑의 명칭은 미정이다. 확률은 초록 삭제에 맞춰 다시 정한다. 아래 가격·효과는 기존 러프 초안이며 확정값이 아니다.

## 3 새 아이템 목록 초안

[ITEM_DESIGN_DRAFT.csv](../DataCatalogs/ITEM_DESIGN_DRAFT.csv)는 위 결정(4등급, 효과·스킬·속성 고정, 에셋 후배정)에 따라 사용자가 새로 기획하는 아이템 목록이다. 런타임은 읽지 않으며 게임·저장에 반영되지 않는다.

- 2026-10-25 사용자 요청으로 제안 31·32에서 옮긴 초안 80종을 삭제하고 기준 아이템 1개부터 다시 작성한다. 삭제한 초안은 커밋 `7bb35462`에서 조회한다.
- 기준 아이템: 롱소드(한손·흰색·물리, 스킬 근접 공격, 공격력 10). 다른 아이템 수치의 기준점이다.
- 고급 기준 아이템: 그레이트소드(두손·파랑·물리, 스킬 근접 공격, 공격력 40, 특수 능력 없음). 일반 한손검+방패와 양손검 사이의 첫 선택지이며 사용자 요청으로 CSV에 추가했다(2026-10-31 사용자 결정).
- 열: `아이템 ID,게임 내 이름,분류,장비 종류,슬롯,손,등급,속성,상태이상,스킬 단계,스킬,공격력,효과,단점,빌드 축,가격(G),획득 경로,외형 에셋,상태,비고`. UTF-8 BOM·전체 인용·CRLF로 기존 CSV 형식을 따른다. `등급`은 현재 CSV와 같은 색 이름(흰색·파란색·보라색·주황색)을 쓴다.
- 가격 1G는 제안 32 초안값이다. `외형 에셋`은 `미배정`, `상태`는 `초안`이다. GameplayTag 배정·스킬 DataAsset 연결은 구현 시 정한다.
