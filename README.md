# ProjectA

Unreal Engine 5.7 기반의 파티·Grid 턴제 전투 프로젝트. UI 중심의 Run 진행, 파티 빌드 성장, 상대 Snapshot을 활용한 Async PvP와 최대 4인 Co-op을 목표로 한다.

목표 Run은 **인카운터 3회 → 몬스터 PvE → 인카운터 3회 → Async PvP**를 10회 반복한다. 정상 완주 기준 인카운터 60회·PvE 10회·PvP 10회이며 목표 플레이 시간은 고정하지 않는다. 각 인카운터는 후보 3개 중 하나를 선택한다. 기획 확정·구현 대기이며 현재 기본 Run은 두 전투 시험 구성이다. [목표와 현재 구현](Docs/GAME_DESIGN.md#2-목표-run과-현재-구현)

성장·재화 획득 경로는 **PvE 보상과 인카운터**이며 회복·부활은 추후 인카운터로 추가한다. **Run 종료 시 MMR만 반영**하고 성장·재화·장비·스킬·소모품은 다음 Run에 이월하지 않는다. 현재는 기획 문서에만 반영한 상태다. [성장·경제·보상 정책](Docs/GAME_DESIGN.md#2-1-성장경제보상과-run-종료)

장비는 **무기 2칸·투구·장갑·신발·갑옷·목걸이 각 1칸·반지 2칸**으로 구성한다. 직업별 시작 무기·방패를 장착하고 상점 페이즈에서 인벤토리와 장비창 사이에 드래그하여 교체한다. 양손 무기는 두 손을 점유하며 능력치·장비 부여 스킬은 후속 구현이다. [장비 슬롯과 스킬](Docs/GAME_DESIGN.md#2-2-장비-슬롯과-장비-부여-스킬)

기본 전투는 [라운드 계획·시간차 자동 전투](Docs/GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)다. 전투 속도는 현재 민첩과 1:1이며 각 라운드의 행동을 함께 계획하고 속도 1 차이당 0.1초 후 실행한다. 실제 접근·복귀, 유닛 이동 비충돌, [서버의 공격 충돌 판정](Docs/GAME_DESIGN.md#8-5-발동과-피격)을 사용한다. 공격은 실제 피격체에 닿아야 하며 별도 명중 확률·성공 슬롯 판정을 사용하지 않는다. 기존 순차 턴 실행은 제거했으며 기존 Blueprint 참조용 클래스·프로퍼티만 남긴다. [확정 전투 규칙과 Ready 복구](Docs/TODO.md#2-14-확정-전투-규칙과-준비-완료-복구)는 구현·컴파일 완료, 사용자 작동 확인 대기다.

메인메뉴의 **게임 시작 → 싱글플레이**는 기존 캐릭터 생성으로, **게임 시작 → 멀티플레이**는 같은 PC·LAN의 2~4인 개발용 방으로 연결한다. 기존 첫 화면의 별도 개발용 협동 버튼은 제거했다. 멀티는 IPv4 주소 참가·준비·Host 시작과 참가자마다 궁수 한 명 배정을 유지하며 Unreal Listen Server를 사용한다. Shipping에서는 비활성이고 Steam 초대·로그인·관리 Run 재개 UI는 별도다.

캐릭터 생성은 **전사 → 마법사 → 궁수 → 도적** 순서이며 현재 시작 능력치는 모두 HP 100·힘/민첩/지능 각 10이다. 직업별 최종 밸런스·공격 스킬은 별도로 작성한다. 이전 테스트 직업이 들어 있는 저장은 원본을 보존하고 거절하며 임의로 새 직업에 대응하지 않는다. DA 폴더 이동의 경로 호환과 직업 콘텐츠 호환은 별개다.

기본 아군은 민첩 10·전투 속도 10, 일반 테스트 적은 힘/민첩/지능 각 5·속도 5다. 적 HP 150·AP 2와 0.5초의 행동 시작 차이는 유지한다. 근접 접근·복귀는 [초기 민첩 튜닝](Docs/GAME_DESIGN.md#8-4-공격-접근과-복귀)으로 기본 아군 350·적 262.5cm/s를 사용한다(`MoveSpeed=700` 기준). 비근접 스킬·시전·투사체 속도는 유지하며 Snapshot과 소수 민첩도 같은 규칙을 적용한다.

네 직업의 **생성/수정**에서 ◀·▶ 버튼으로 **남자·여자** 몸체를 선택한다. 남자는 원본 `SKM_Primitive_Charater_01_Body`, 여자는 `SKM_Primitive_02_Body`를 사용하며 기본값은 남자다. 미리보기 영역을 **우클릭한 채 좌우로 드래그**하면 캐릭터가 회전한다. 실시간 미리보기·초기화·저장·취소를 지원하고 선택은 전투·이어하기에 유지된다. ROG 의상 선택·착용과 마법사의 기본 스태프 표시는 제거하고 103개 의상 항목·스태프 원본은 향후 아이템용으로 보존한다. 기존 래그돌은 유지하며 모델·텍스처는 복제하지 않는다. 현재 검증 상태는 [외형 UI 확인](Docs/TODO.md#2-30-rog-의상-커스터마이징)을 따른다.

캐릭터 생성 화면의 기본 카메라 X는 `-500`, 네 슬롯 앵커 Yaw는 `90°`다. 직업·몸체 선택과 상세 편집 종료 후에도 같은 정면 방향을 사용한다. 엔진 Details에서 거리·방향을 조절하는 위치는 [프리뷰 설정](Docs/UI_README.md#화면프리뷰)을 따른다.

## 실행

일반 싱글 새 게임은 생성한 카드의 **직접 조작** 버튼으로 한 명을 선택해야 시작한다. 나머지 생성 동료는 서버 AI가 계획·실행하며 원래 소유자는 바뀌지 않는다. 선택은 저장·이어하기·다음 전투에서 유지하고, 선택한 캐릭터가 사망하면 생존 AI가 자동으로 전투를 계속한다. 선택한 카드를 삭제하면 다시 선택해야 한다. 기존 저장의 호환 범위는 [저장과 멀티플레이 연결 경계](Docs/PROJECT_PLAN.md#저장과-멀티플레이-연결-경계)를 따른다.

1. UE 5.7에서 `ProjectA.uproject`와 `/Game/User_JeHoon/LEVEL/MainMenu`를 연다.
2. 게임 시작 → 싱글플레이 → 캐릭터 1~4명 생성 → 직접 조작할 1명 선택 → Start Game → 첫 Combat 노드를 선택한다.
3. 전장에서 **적 한 번 클릭 → 하단의 장착 스킬 버튼 클릭 → 준비 완료** 순서로 행동한다. 스킬 버튼을 누르면 해당 계획이 적용된다. **스킬을 선택하지 않고 준비 완료하면 행동 비용 없이 턴을 넘긴다.** 선택한 스킬은 **스킬 선택 취소**로 해제할 수 있다. 위치를 바꾸려면 **이동 예약 · SAP 1 → 강조된 아군 빈칸 한 번 클릭**으로 예약한다. 스킬 없이 이동만 예약할 수 있으며 이때 SAP 1만 소모한다. 준비 전까지 이동·자원 소모는 없다. 모두 준비하면 SAP 이동을 먼저 끝내고 선택한 AP 행동을 실행한다. AI 동료의 계획은 서버가 결정하며 직접 조작 캐릭터가 사망하면 생존 AI만으로 자동 진행한다.
4. Victory → 5~15G 골드 보상 3개 중 1개 선택 → Continue → 스킬상점·아이템상점·상점3 중 하나 선택 → 나가기 → 두 번째 전투로 진행한다. 마지막 Victory도 보상 선택 뒤 Continue로 Run을 종료하며 패배에는 보상을 지급하지 않는다.

승리 보상은 각 선택지를 독립 추첨하므로 같은 금액이 나올 수 있다. 본인 직접 조작 캐릭터에게 한 번만 지급하고 골드와 수령을 함께 저장한다. 이어하기에서 선택지를 다시 뽑지 않으며 협동에서는 각자 선택한 뒤 Host가 계속한다. 기존 스킬 상점 저장은 다음 승리부터 적용하고 과거 결과·상점 도입 전 저장에는 소급 보상을 만들지 않는다. [사용자 확인](Docs/TODO.md#2-24-전투-승리-골드-보상)

유닛 대상 공격은 발동 전에 대상이 죽으면 공격자의 현재 위치에서 가장 가까운 살아 있는 적으로 전환한다. 유닛 접근형 공격은 새 대상에게 접근·재시전하며 비용은 추가 차감하지 않는다. 후보가 없으면 불발 후 복귀한다. 지점 공격의 좌표와 이미 발사한 투사체는 유지한다. [사용자 확인](Docs/TODO.md#2-23-대상-사망-시-가까운-적-재선택)

기존 상점1은 **스킬상점**, 상점2는 **아이템상점**으로 명명하고 각각 인카운터 정의로 관리한다. 상점3은 기존 시험용 인카운터로 유지한다. [인카운터 관리](Docs/PROJECT_PLAN.md#상점-인카운터)

**스킬상점·상점3**은 기존 검·원거리·AOE·휩쓸기와 HP 전체 회복을 각각 1G에 판매한다. 직접 조작 캐릭터는 개인 10G로 시작하며 본인 생존 Human만 구매한다. 같은 스킬의 중복 구매와 만피 회복은 막고, 골드와 스킬·HP 변경을 함께 저장한다. 협동의 인카운터 선택·퇴장은 Host가 결정한다. [스킬상점 확인](Docs/TODO.md#2-19-비무장-시작과-스킬-상점)

새 Run의 **아이템상점**은 [무기 CSV](Docs/WEAPON_ASSETS.csv) 전체 295개에서 중복 없이 5개를 제시하는 시험 인카운터다. 방패·탄환·화살·기타도 포함하며 원본 에셋 이름과 CSV의 `가격(G)`을 표시한다. 현재 상품 가격과 리롤 비용은 모두 **1G**다. 구매한 슬롯은 판매 완료로 바뀌고 아이템은 개인 Run 인벤토리에 저장한다. 리롤은 5칸을 새로 추첨하며 이전에 등장한 상품도 다시 나올 수 있다. 잔액·보유 수량·진열 상태는 저장 후 함께 반영하고 이어하기에서 복원한다. 아이템상점 데이터가 없는 이전 저장(schema 0)은 새 Run으로 시험하며, 데이터가 있는 기존 저장(schema 1)은 이어하기로 계속 사용할 수 있다. [아이템상점 확인](Docs/TODO.md#2-31-아이템상점-시험)

상점에 진입하면 **왼쪽 현재 장비·가운데 상품·오른쪽 인벤토리**를 함께 표시한다. 새 Run은 전사 한손검+방패·궁수 양손 활·마법사 양손 스태프·도적 단검을 장착하고 `I` 창에서도 확인한다. 본인 생존 Human은 상점 페이즈에서 보유 아이템과 장비 슬롯을 드래그하여 장착·교체·해제하며 저장 뒤 실제 원본 메시를 반영한다. 같은 종류 여러 개는 개별 사본으로 구분한다. 현재 분류가 확정된 49개는 장착 가능하고 나머지 246개는 보관만 가능하다. 이전 저장에는 시작 아이템을 소급 지급하지 않는다. [장비 확인과 남은 분류](Docs/TODO.md#2-33-시작-장비와-상점-드래그-장착)

C++·리플렉션·프로젝트 설정 변경 반영을 위해 빌드 후 UE를 재시작한다. 기존 Gameplay 맵·GameMode·Root UI를 사용하며 새 에셋 생성은 필요하지 않다.

장착한 스킬의 기존 `AbilityClass → AttackMontage`는 시전 시작 시 재생한다. `bUseRoundDefinition`을 사용하는 DA는 `RoundDefinition.CastMontage`로 재생할 몽타주를 우선 지정할 수 있다. 일반 피해·발사는 `WindupSeconds` 뒤 서버 충돌로 처리하고 검 공격은 지정 활성 구간의 칼날 궤적으로 최초 적 한 명에게 한 번 적용한다. 복귀는 서버의 실제 몽타주 인스턴스가 블렌드 아웃까지 끝난 뒤 시작한다. 서버에서 표현을 갱신하지 못하면 에셋 길이·속도·블렌드 시간을 사용하며 시전 시작 기준 최대 60초의 대기 제한으로 반복·종료 누락을 정리한다. 메시·AnimBP의 Skeleton/Slot 연결이 필요하다.

새 Run의 네 직업은 **비무장 공격 스킬**만 가지며 시작 장비나 아이템 교체로 스킬·능력치를 변경하지 않는다. 장비가 표시되는 새 Run에서도 검 공격 구매 시 기존 숨긴 검 판정 컴포넌트로 서버 칼날 궤적을 유지한다. 이전 저장·기본 적·Snapshot의 스킬 기반 외형은 보존한다. 검 공격은 피해 50·AP 1, 활성 0.23~0.43초의 서버 칼날 소켓 궤적 판정을 사용한다. 실제 직업별 구매·타격 확인은 [TODO](Docs/TODO.md#2-19-비무장-시작과-스킬-상점)에 남긴다.

`BPDA_SweepingStrike`는 근접 접근 후 전방 박스 충돌로 여러 적을 타격한다. `MeleeAreaHalfExtent`로 범위를 조절하며 피해 10·AP 1·몽타주 종료 후 복귀를 유지한다. 이전 `DA_SweepingStrike` 경로·PrimaryAssetId는 리디렉션하고 기존 타일 범위 코드는 보존한다. 외부 에셋은 원본을 직접 참조하며 `User_JeHoon`에 편의상 복제하지 않는다. 새 프로젝트 에셋·필수 리타깃 결과만 해당 폴더에 작성한다. 중복 정리는 원본에서 `User_JeHoon`으로 복사한 사본에 한정하며 외부 팩끼리는 비교하지 않는다. 실제 플레이는 [사용자 확인](Docs/TODO.md#2-15-전사와-검-공격-콘텐츠) 대기다. [스킬 정의](Docs/GAME_DESIGN.md#8-7-기본-전투-전환과-스킬-데이터) · [에셋 구성](Docs/PROJECT_PLAN.md#gameplay-에셋과-배치)

Paragon AnimSequence 5,385개를 원본의 32개 캐릭터 폴더 구조대로 `/Game/User_JeHoon/ParagonAnimationsRetargetedToManny`에 저장했다. 이는 원본 FBX를 엔진용으로 임포트한 결과이며 단순 복사본이 아니다. 기존 애니메이션과 신규 임포트 모두 원본 Manny 뼈대·프리뷰 메시를 직접 참조한다. 메시·뼈대 복사본 6개를 통합해 Content 용량을 34.01MiB 줄였다. Animation Editor의 실제 재생 확인은 대기이며 Kwang 검 공격 연결은 별도로 관리한다. [복사본 정리와 사용자 확인](Docs/TODO.md#2-26-user_jehoon-복사본-정리)

SAP 이동은 캐릭터마다 목적지 하나를 예약하며 민첩·`MaxWalkSpeed`와 무관하게 **350cm/s의 고정 속도**로 실행한다. 준비 전에는 변경·취소할 수 있고 실제 위치·자원은 바뀌지 않는다. Ready Phase 종료 시 이동 SAP 1과 공격 비용을 합산하여 AP/SAP를 즉시 한 번 차감하며 불발에도 환불하지 않는다. 모든 예약 이동 완료 후 기존 속도차에 따라 AP 행동을 시작하며 도착 위치가 새 복귀 칸이 된다. 다른 유닛의 복귀·예약 칸 이동과 자리 교환을 막고 이동 실패 시 출발점으로 복원한다.

계획·이동 예약 수정은 해당 소유자의 준비만 해제한다. 피해·사망은 서버 처리 순서대로 즉시 반영하며 먼저 사망한 유닛의 미발동 공격은 취소한다. 잔여 공격 정리 후 양 팀이 전멸하면 패배로 Run을 종료하고 승리 보상은 지급하지 않는다. 엄호는 제거하며 상태이상은 후순위, 비근접 시전·이동·투사체 속도 추가 구현은 별도 보류다. [확정 규칙과 남은 확인](Docs/TODO.md#2-14-확정-전투-규칙과-준비-완료-복구)

복귀형 공격은 정상 복귀·시간 초과 복원·제자리 완료 후 행동 전 방향으로 돌아선다. SAP 이동·AP 접근/복귀는 기존 AnimBP에 속도·가속도 입력을 전달하고, 정지·시전·중단·사망에서는 입력을 초기화한다.

아군·기본 적·Snapshot 상대 모두 기존 래그돌·사망 충격량을 사용한다. 사망 애니메이션 분기는 제거하며 서버의 타일 해제·행동 취소·사망 복제는 유지한다. [사용자 확인](Docs/TODO.md#2-28-전체-래그돌-복구)

처음 실행한 MainMenu의 Options에서 화면과 그래픽을 설정한다. 항목 선택 후 적용하며, 해상도·화면 모드가 바뀌면 15초 안에 확인해야 저장된다. 취소·시간 초과·확인 전 화면 닫기는 적용 전 상태로 복원한다. 테두리 없는 전체 화면은 바탕 화면 해상도를 사용한다. 품질·VSync만 바꾸면 적용 시 바로 저장한다. 상세는 [설정 UI](Docs/UI_README.md#8-시작-메뉴-설정)를 따른다.

Gameplay 좌측 상단에는 현재 개인 보유 골드를 표시하며 구매·회복·리롤 저장 후 갱신한다. `I`는 장비 슬롯·개인 골드·보유 스킬·아이템 목록과 수량을 함께 열고 닫으며, `Esc`는 설정을 연다. 설정에서 다시 `Esc`를 누르면 닫고 화면 변경 확인 중에는 먼저 복구한다. 창이 열린 동안 배경 전장 입력을 막는다. 단축키 확인은 독립 게임 창에서 진행한다. 기본 PIE의 `Esc`는 에디터 실행 종료가 우선한다. [단축키 상세](Docs/UI_README.md#8-2-gameplay-인벤토리와-설정-단축키)

공통 외형은 native `UDemonicUITheme`이 기존 `/Game/DemonicUI` 텍스처를 참조하여 적용한다. C++ 빌드 후 UE를 재시작하면 기존 Designer 위젯과 native 컨트롤에 반영되며 WBP·JSON 재생성은 필요하지 않다. 원본 에셋은 수정하지 않는다. 적용 범위는 [UI_README 9절](Docs/UI_README.md#9-demonicui-공통-테마)을 따른다.

UI는 1920×1080을 기준으로 뷰포트에 맞춰 같은 비율로 확대·축소한다. 전투는 상단 라운드 요약·우측 대상 정보·좌하단 파티 카드·하단 중앙 장착 스킬·우하단 이동/준비로 나누고 중앙 전장에서 유닛·타일을 직접 선택한다. 카메라는 고정 16:9 검은 띠를 만들지 않는다. 배율과 패널 크기는 [UI_README 10절](Docs/UI_README.md#10-공통-dpi와-전투-화면-배치)을 따른다.

일반 Continue는 지원되는 비전투 저장과 새 Ready 경계 저장을 복구한다. 준비 완료는 계획·전투 복구 상태를 저장한 뒤 확정하며 저장 실패 시 준비 완료·전투 시작을 막는다. 강제 종료 후에는 마지막 저장 계획·Ready·유닛·자원·배치에서 다시 진행하고 비용을 중복 차감하지 않는다. 시전·투사체의 중간 시점 복원은 지원하지 않는다. 이전 순차 Combat 저장은 파일을 보존하고 거절하며 협동·관리 저장은 명시적 재개 절차를 사용한다. [저장 계약](Docs/PROJECT_PLAN.md#저장과-멀티플레이-연결-경계)

이어하기 옆 **항복하기**는 현재 이어갈 수 있는 일반 싱글 저장에만 활성화한다. 확인창의 기본 선택은 돌아가기이며 취소 시 변경하지 않는다. 확인 후 해당 저장을 삭제하면 이어하기가 비활성화된다. 저장 변경·삭제 실패 시 원본과 현재 Run을 보존한다. 협동·관리 저장·랭크 항복은 지원하지 않는다.

전투 준비 취소 중 저장이 실패하면 Host의 **저장 다시 시도**로 Map 복귀를 재시도한다. 기존 확정 저장을 보존하고 준비·저장 오류를 함께 표시한다. 실제 전투가 정리된 뒤 화면 갱신이 입력을 다시 켜지 않으며, Map 전환 통지 중에도 새 전투를 중복 생성하지 않는다. 파티 설정은 Content Browser의 제작 파티 에셋에서 **Validate Assets**로 미리 검사할 수 있다.

개발용 협동: 독립 게임 창 2개에서 **MainMenu → 게임 시작 → 멀티플레이**를 연다. 첫 창은 2인 방 생성, 두 번째는 `127.0.0.1:7777`로 참가한다. 각자 준비 완료 후 Host가 시작하고 첫 전투 노드를 선택한다. 창 실행 명령은 [멀티플레이 개발 실행 참조](Docs/MULTIPLAYER.md#개발-실행-참조)를 따른다.

## 작업 규칙

아이템·적 유닛·스킬·효과 확장은 GAS·GameplayTag 기반 분류와 데이터 기반 확률 가중치를 원칙으로 한다. 라운드 계획·AI·발동·피격의 태그 조건과 GAS 효과 실행을 연결하며 콘텐츠 가중치 확장·최종 태그 계층·수치는 별도 기획 대상이다. 세부 기준은 [AGENTS.md](AGENTS.md)의 데이터 확장 원칙을 따른다.

[AGENTS.md](AGENTS.md)를 기준으로 한다. 작동 테스트는 사용자 수행이 원칙이며 명시적 실행 요청에 한해 Codex가 수행한다. Visual Studio는 자동 실행하지 않는다. 커밋 시 이번 작업 외의 기존 추가·수정·삭제도 함께 검토·검증하여 `[codex]` 제목과 한글 본문으로 커밋·push한다. 사용자가 명시적으로 제외한 항목과 Git이 무시하는 생성물은 포함하지 않는다. 완료 후 미커밋 변경 여부를 확인하고 결과·문제·남은 확인 사항을 간략히 안내한다.

TODO의 우선순위·구현·코드 검토·컴파일·문서·커밋/push는 Codex가 일괄 담당한다. [TODO](Docs/TODO.md)의 제안은 번호가 있는 체크박스에서 하나를 선택하고, 선택 결과를 로컬 파일에 저장한 뒤 `TODO 진행해줘`로 요청한다. 선택 체크와 구현·작동 검증 완료는 구분한다. 사용하는 편집기와 관계없이 로컬 파일의 체크를 기준으로 하며, Notion 복사본과 원본의 자동 동기화는 가정하지 않는다. 추가 확인은 TODO의 남은 항목과 발견한 문제를 기준으로 진행한다.
