# ProjectA

Unreal Engine 5.8 기반의 파티·Grid 턴제 전투 프로젝트. UI 중심의 Run 진행, 파티 빌드 성장, 상대 Snapshot을 활용한 Async PvP와 최대 4인 Co-op을 목표로 한다.

실제 Run은 하나의 큰 `Gameplay` 레벨을 사용한다. 인카운터는 **지하 미로의 좌회전·직진·우회전 갈림길**에서 선택하며 화면 하단의 세 카드가 후보 순서와 대응한다. 새 Run은 별도 시드로 8개 통로 변형과 전체 방문의 후보 ID 순서를 고정·저장하고 현재·다음 구간만 최대 2개 Actor로 재사용한다. 선택이 저장된 뒤 2.8초 동안 NPC에게 이동하고 오른쪽 구매 패널을 연다. 이어하기는 저장된 배치를 복원하며 이전 저장은 고정 배치를 유지한다. 기존 Gameplay·전투장·원본 에셋은 보존하고 로컬 장식으로 미로를 구성한다. [공간 구성](Docs/PROJECT_PLAN.md#4-13-통합-gameplay와-npc-상점) · [이번 변경과 검증 상태](Docs/HISTORY.md#9-36-2026-10-09-시드별-미로-계획과-구간-재사용)

신규 2~4인 협동은 인간별 캐릭터 1명으로 생성하며 최초 저장 성공 후 시작 상태를 공개한다. 저장 거절 시 사유를 표시하고 기존 진행을 보존한다. 로컬 Snapshot 후보 슬롯을 태그·진행 단계로 선정하는 API를 제공하며 소모품은 일반 Snapshot 스킬로 등록할 수 없다. 기본 Run의 고정 상대와 온라인 공급자는 별도 범위다. [위임 판단과 실행 검수](Docs/EXECUTION_DECISIONS.md)

새 싱글플레이 Run은 **인카운터 3회 → 몬스터 PvE → 인카운터 3회 → 로컬 Snapshot 전투**를 10회 반복한다. 정상 완주 기준 인카운터 60회·PvE 10회·Snapshot 10회이며 각 인카운터는 후보 3개 중 하나를 선택한다. 새 기본 Run은 각 PvE 진입 직전에 **좌회전·하 / 직진·중 / 우회전·상** 중 하나를 선택한다. 전투 선택은 80단계 안에 포함하며 별도 방문으로 계산하지 않는다. CSV의 숲·늪·동굴·설원·최종 구간과 시작 파티 인원에 따라 몬스터를 태그·가중치로 선정하고 편성·스탯·성장·보상을 저장한다. 기존 Run과 명시적인 맞춤 정의·개발 협동은 원래 정책을 유지한다. 온라인 Async PvP 연결과 최종 난이도 검증은 후속 작업이다. [목표와 현재 구현](Docs/GAME_DESIGN.md#2-목표-run과-현재-구현) · [난이도 규칙](Docs/PROJECT_PLAN.md#5-1-목표-run과-회복-시험-데이터)

성장·재화 획득 경로는 **PvE 보상과 인카운터**다. 새 싱글 Run에 회복소·부활소·소모품상점을 연결하고 전투 중 본인 생존 캐릭터의 회복 소모품을 지원한다. **Run 종료 시 MMR만 반영**하는 정책이며 실제 온라인 정산은 미구현이다. 성장·재화·장비·스킬·소모품은 다음 Run에 이월하지 않는다. [성장·경제·보상 정책](Docs/GAME_DESIGN.md#2-1-성장경제보상과-run-종료)

장비는 **무기 2칸·투구·장갑·신발·갑옷·목걸이 각 1칸·반지 2칸**으로 구성한다. 직업별 시작 무기·방패를 장착하고 상점 페이즈에서 인벤토리와 장비창 사이에 드래그하여 교체한다. 양손 무기는 두 손을 점유한다. [장비 슬롯과 스킬](Docs/GAME_DESIGN.md#2-2-장비-슬롯과-장비-부여-스킬)

2026-10-06 제안 15~19의 선택 1과 추가 결정 위임에 따라 **새 일반 Run의 스킬상점을 제거하고 무기에 스킬을 부여하며 장착한 무기의 스킬만 사용**하도록 변경했다. 비무장 기본 공격은 유지하고 시작 무기도 생성 시 부여한다. **흰색·초록색·파란색·보라색·주황색** 5등급은 무기 CSV의 에셋별 등급으로 고정하며, 해당 등급과 무기 태그에 맞는 스킬 1개를 추첨한다. 새 일반 Run의 아이템상점·전투 보상 등장 기본 가중치는 **50·30·15·4·1**로 별도 CSV에서 관리한다. 현재 장착 지원 49개에는 주황색이 없어 **50:30:15:4**를 남은 후보에 재정규화하며 가격은 1G다. 새 Run의 무기 스킬 62종은 별도 CSV의 고유 등급·위력과 장비별 스킬 등급 가중치를 사용한다. 가능한 스킬 등급을 먼저 선택하고 그 안에서 기본 가중치로 추첨하므로 높은 장비 등급에서 높은 스킬 등급이 더 자주 등장한다. 사본별 결과를 저장하고 재장착·Continue로 재추첨하지 않으며 동일 스킬은 출처를 유지한 버튼 하나로 합친다. 기존 저장의 카탈로그·보유 사본·등급·스킬·이미 확정된 보상은 보존한다. 이후 새 진열·리롤·보상 후보는 장착 지원품으로 제한하고 기존 미지원 진열은 숨기며 서버도 구매를 거절한다. 무기 스킬 도입 전 Run·명시적 prototype·개발 협동은 당시 상점·습득 스킬을 유지한다. 총 스킬 소지 상한은 제거했고 기본상점 진열 5개·전문 상점 최대 5개·소모품 종류 5개를 사용한다. [최신 구현·검증 상태](Docs/HISTORY.md#9-37-2026-10-09-스킬-수치등급과-장비별-추첨) · [무기 규칙](Docs/GAME_DESIGN.md#2-4-무기-랜덤-스킬과-아이템-등급) · [사용자 확인](Docs/TODO.md#29-무기-랜덤-스킬과-아이템-등급-기획)

기본 전투는 [라운드 계획·시간차 자동 전투](Docs/GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)다. 전투 속도는 독립 GAS `Speed` 값이며 각 라운드의 행동을 함께 계획하고 속도 1 차이당 0.1초 후 실행한다. 실제 접근·복귀, 유닛 이동 비충돌, [서버의 공격 충돌 판정](Docs/GAME_DESIGN.md#8-5-발동과-피격)을 사용한다. 공격은 실제 피격체에 닿아야 하며 별도 명중 확률·성공 슬롯 판정을 사용하지 않는다. 기존 순차 턴 실행은 제거했으며 기존 Blueprint 참조용 클래스·프로퍼티만 남긴다. 확정 전투 규칙과 Ready 경계 저장·복구 데이터는 구현했으며 자동화 검증 범위는 [재검증 이력](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 강제 종료 후 전투 Actor·화면 재구성은 당시 검증 범위에 포함되지 않았다.

저항 시스템 기획은 2026-10-06 사용자 결정으로 폐기했다. 기존 스킬 속성 태그·피해·보호막과 후순위 상태이상 기획은 유지한다. [전투 기획 기준](Docs/GAME_DESIGN.md#8-7-기본-전투-전환과-스킬-데이터)

무기 스킬 획득 버전 1의 일반 Target Run은 **PvE 승리에서 아이템 3개 중 1개와 공통 골드**를 함께 받는다. 선택한 아이템은 자동 장착 없이 가방에 추가하며 해당 Run의 카탈로그·등급 확률·스킬 규칙을 사용한다. 새 기본 Run의 중 난이도 골드는 첫 묶음 3~5G에서 마지막 8~15G이며 하·중·상의 적 HP/속도/골드 배율은 각각 80/90/75%·100/100/100%·130/110/150%다. [PvE 난이도 CSV](DataCatalogs/PVE_DIFFICULTIES.csv)에 수치를 관리하고 선택 시 실제 적 수·HP·골드 범위를 표시한다. 아이템 등급 확률은 동일하다. PvE 승리마다 생존 파티에 휴식 HP 20~40을 성장 후 최대 HP까지 회복한다. 사망자는 부활하지 않으며 Snapshot·패배에는 성장·보상·휴식이 없다. 기존 Run의 저장된 보상·골드 범위·회복 정책은 유지한다. 2026-10-06 무기 스킬·새 Run 전환의 최종 Development Editor / Win64 컴파일·링크는 8개 작업·18.74초로 성공했다. 회귀 소스까지 컴파일했으며 게임·PIE·자동화 테스트는 실행하지 않았다. 에셋 작성 근거는 [HISTORY 9-24](Docs/HISTORY.md#9-24-2026-10-06-무기-스킬과-새-run-전환), 실제 장착·등급·6개 이상 스킬의 화면/선택·메뉴 Continue는 [사용자 확인](Docs/TODO.md#29-무기-랜덤-스킬과-아이템-등급-기획)을 따른다. 앞선 상한 제거 컴파일 41.96초는 해당 단계의 이력으로 보존한다.

캐릭터 생성 버튼은 슬롯의 기본 직업·남자 몸체·자동 이름으로 즉시 생성하고 파티 화면을 유지한다. 이름·직업·몸체의 상세 편집은 생성된 카드의 **Edit**에서 연다. 직업은 **전사 → 마법사 → 궁수 → 도적** 순서이며 현재 시작 능력치는 모두 HP 100·속도 10이다. 직업별 최종 밸런스·공격 스킬은 별도로 작성한다. 이전 테스트 직업이 들어 있는 저장은 원본을 보존하고 거절하며 임의로 새 직업에 대응하지 않는다. DA 폴더 이동의 경로 호환과 직업 콘텐츠 호환은 별개다.

스탯은 **속도 하나**이며 힘·민첩·지능은 제거했다. HP·AP·SAP·보호막은 전투 자원으로 유지한다. 기본 아군 속도는 10이며 클래스 기본 테스트 적은 HP 150·AP 2·속도 5를 유지한다. 새 기본 Run의 몬스터 HP·속도는 저장된 난이도 값을 사용한다. 근접 접근·복귀는 [기존 속도 튜닝](Docs/GAME_DESIGN.md#8-4-공격-접근과-복귀)을 따르며 속도 10/5·`MoveSpeed=700`일 때 아군 350·적 262.5cm/s다. Snapshot과 소수 속도도 같은 규칙을 적용하며 이전 저장의 민첩 값은 속도로 이관한다. 투사체는 속도 스탯과 별도로 공통 비행 배율 `projecta.Combat.ProjectileSpeedScale=0.5`를 적용하며 기본 700→350cm/s로 감속한다. 수명은 역비례 보정하여 최대 이동 거리를 유지한다.

네 직업의 **Edit 편집창**에서 ◀·▶ 버튼으로 **남자·여자** 몸체를 선택한다. 남자는 원본 `SKM_Primitive_Charater_01_Body`, 여자는 `SKM_Primitive_02_Body`를 사용하며 기본값은 남자다. 미리보기 영역을 **우클릭한 채 좌우로 드래그**하면 캐릭터가 회전한다. 실시간 미리보기·초기화·저장·취소를 지원하고 선택은 전투·이어하기에 유지된다. ROG 의상 선택·착용과 마법사의 기본 스태프 표시는 제거하고 103개 의상 항목·스태프 원본은 향후 아이템용으로 보존한다. 기존 래그돌은 유지하며 모델·텍스처는 복제하지 않는다. 현재 화면·입력 검수는 [최신 실행 이력](Docs/HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)을 따른다.

캐릭터 생성 화면의 초기 카메라 X는 `-500`, 네 슬롯 앵커 Yaw는 `90°`다. 실제 화면 투영으로 네 몸체의 가로 여백을 확보하고 화면 크기·파티·외형 변경 시 초기 카메라 기준에서 다시 맞춘다. 상세 편집은 선택한 몸체를 확대하며 종료 후 파티 구도를 복원한다. 엔진 Details 설정은 [프리뷰 설정](Docs/UI_README.md#4-화면프리뷰)을 따른다.

앞선 UE 5.7 자동화 166개·1/2/4인 10전투·9상점과 메뉴 버튼·실제 Quit·Continue 검증은 [재검증 이력](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 당시 최종 저장 값 비교 보완 후 컴파일과 대상 저장 검사 에디터 7개·게임 6개·실제 Continue가 통과했으며 전체 166개는 다시 실행하지 않았다. 메뉴 버튼 검증은 `-ProjectAFlowOnly`로 프리뷰 애니메이션·캡처를 제외했다. 전체 메뉴의 idle 루프 경계 4건 실패와 미검증 화면은 [당시 실행 기록](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)에 남겼다. 새 에셋·온라인 서비스는 [후속 기획](Docs/TODO.md)에 둔다. 사용자 지시로 스킬·VFX·아이템 장비의 추가 실행은 제외했고 당시 `SavedSkillLoadout` fixture는 컴파일만 확인했다.

## 실행

전투 바닥은 중앙 PineRidge의 흑백 잔점을 낮은 대비의 흙색으로 바꾸고, 환경 표면 9개의 큰 무늬·색조·노멀 강도를 조정했다. 전투 타일은 평상시 옅게 표시하고 이동·스킬 대상을 강조한다. 기본 전투 카메라의 채도를 완화하며 기존 카메라 재정의·전투 좌표·충돌은 유지한다. [변경 범위·검증 상태](Docs/HISTORY.md#9-40-2026-10-09-전투장-바닥과-표시-폴리싱)

레벨은 `LEVEL/Core`(메뉴·게임), `Development`(전투 디버그), `Environment/<테마>`(비교 14맵)로 분류한다. 2026-10-06 기존 사용자 변경인 `Legacy/WorldMap` 삭제를 반영하여 현재 맵은 17개다. 앞선 18맵 이동·Redirector 2개 정리·옛 경로 20개 호환 검사는 삭제 전 이력이다. 새 경로와 검증 범위는 [레벨 폴더 기준](Docs/PROJECT_PLAN.md#4-10-레벨-폴더와-이전-경로-호환), 이동 후 사용자 위임 새 게임·이어하기 검수는 [목표 Run 검증 이력](Docs/HISTORY.md#9-18-2026-10-04-목표-run과-위임-후속-검수)을 따른다.

일반 싱글 새 게임은 생성한 카드의 **직접 조작** 버튼으로 한 명을 선택해야 시작한다. 나머지 생성 동료는 서버 AI가 계획·실행하며 원래 소유자는 바뀌지 않는다. 선택은 저장·이어하기·다음 전투에서 유지하고, 선택한 캐릭터가 사망하면 생존 AI가 자동으로 전투를 계속한다. 선택한 카드를 삭제하면 다시 선택해야 한다. 기존 저장의 호환 범위는 [저장과 멀티플레이 연결 경계](Docs/PROJECT_PLAN.md#5-저장과-멀티플레이-연결-경계)를 따른다.

1. UE 5.8에서 `ProjectA.uproject`와 `/Game/User_JeHoon/LEVEL/Core/MainMenu`를 연다.
2. 게임 시작 → 싱글플레이 → 캐릭터 1~4명 생성 → 직접 조작할 1명 선택 → Start Game → 첫 Combat 노드를 선택한다.
3. 전장에서 **적 한 번 클릭 → 하단의 장착 스킬 버튼 클릭 → 준비 완료** 순서로 행동한다. 스킬 버튼을 누르면 해당 계획이 적용된다. **스킬을 선택하지 않고 준비 완료하면 행동 비용 없이 턴을 넘긴다.** 선택한 스킬은 **스킬 선택 취소**로 해제할 수 있다. 위치를 바꾸려면 **이동 예약 · SAP 1 → 강조된 아군 빈칸 한 번 클릭**으로 예약한다. 스킬 없이 이동만 예약할 수 있으며 이때 SAP 1만 소모한다. 준비 전까지 이동·자원 소모는 없다. 모두 준비하면 SAP 이동을 먼저 끝내고 선택한 AP 행동을 실행한다. AI 동료의 계획은 서버가 결정하며 직접 조작 캐릭터가 사망하면 생존 AI만으로 자동 진행한다.
4. 1~9번째 Victory마다 5~15G 골드 보상 3개 중 1개 선택 → Continue → 스킬상점·아이템상점·상점3 중 하나 선택 → 나가기 → 다음 전투로 진행한다. 10번째 Victory는 보상 선택 뒤 Continue로 Run을 완료하며 패배에는 보상을 지급하지 않는다. 지도는 완료 수/10과 스크롤 가능한 노드 목록을 표시한다.

승리 보상은 각 선택지를 독립 추첨하므로 같은 금액이 나올 수 있다. 본인 직접 조작 캐릭터에게 한 번만 지급하고 골드와 수령을 함께 저장한다. 이어하기에서 선택지를 다시 뽑지 않으며 협동에서는 각자 선택한 뒤 Host가 계속한다. 기존 스킬 상점 저장은 다음 승리부터 적용하고 과거 결과·상점 도입 전 저장에는 소급 보상을 만들지 않는다. [보상 검증 범위](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)

전투 종료 시 최종 HP·결과·보상·진행을 함께 저장한 뒤 Run 상태에 반영한다. 저장 실패 시 기존 파티 HP·골드·스킬·진행과 원본 파일을 유지하고 같은 결과를 재시도한다. 전체 상태 보존·저장 후 공개 회귀는 [재검증 이력](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 강제 종료 후 화면·Actor 재구성은 해당 회귀의 검증 범위 밖이었다.

처음 실행한 MainMenu의 Options에서 화면과 그래픽을 설정한다. 항목 선택 후 적용하며, 해상도·화면 모드가 바뀌면 15초 안에 확인해야 저장된다. 취소·시간 초과·확인 전 화면 닫기는 적용 전 상태로 복원한다. 테두리 없는 전체 화면은 바탕 화면 해상도를 사용한다. 품질·VSync만 바꾸면 적용 시 바로 저장한다. 상세는 [설정 UI](Docs/UI_README.md#8-시작-메뉴-설정)를 따른다.

Gameplay 좌측 상단에는 현재 개인 보유 골드를 표시하며 구매·회복·리롤 저장 후 갱신한다. `I`는 장비 슬롯·개인 골드·보유 스킬·아이템 목록과 수량을 함께 열고 닫으며, `Esc` 또는 `O`는 설정을 연다. 설정에서 다시 `Esc` 또는 `O`를 누르면 닫고 화면 변경 확인 중에는 먼저 복구한다. 창이 열린 동안 배경 전장 입력을 막는다. 단축키 확인은 독립 게임 창에서 진행한다. 기본 PIE의 `Esc`는 에디터 실행 종료가 우선한다. [단축키 상세](Docs/UI_README.md#8-2-gameplay-인벤토리와-설정-단축키)

공통 외형은 native `UDemonicUITheme`이 기존 `/Game/DemonicUI` 텍스처를 참조하여 적용한다. C++ 빌드 후 UE를 재시작하면 기존 Designer 위젯과 native 컨트롤에 반영되며 WBP·JSON 재생성은 필요하지 않다. 원본 에셋은 수정하지 않는다. 적용 범위는 [UI_README 9절](Docs/UI_README.md#9-demonicui-공통-테마)을 따른다.

UI는 1920×1080을 기준으로 뷰포트에 맞춰 같은 비율로 확대·축소한다. 전투는 상단 라운드 요약·우측 대상 정보·좌하단 파티 카드·하단 중앙 장착 스킬·우하단 이동/준비로 나누고 중앙 전장에서 유닛·타일을 직접 선택한다. 카메라는 고정 16:9 검은 띠를 만들지 않는다. 배율과 패널 크기는 [UI_README 10절](Docs/UI_README.md#10-공통-dpi와-전투-화면-배치)을 따른다.

일반 Continue는 지원되는 비전투 저장과 새 Ready 경계 저장을 복구한다. 준비 완료는 계획·전투 복구 상태를 저장한 뒤 확정하며 저장 실패 시 준비 완료·전투 시작을 막는다. 강제 종료 후에는 마지막 저장 계획·Ready·유닛·자원·배치에서 다시 진행하고 비용을 중복 차감하지 않는다. 시전·투사체의 중간 시점 복원은 지원하지 않는다. 이전 순차 Combat 저장은 파일을 보존하고 거절하며 협동·관리 저장은 명시적 재개 절차를 사용한다. [저장 계약](Docs/PROJECT_PLAN.md#5-저장과-멀티플레이-연결-경계)

이어하기 옆 **항복하기**는 현재 이어갈 수 있는 일반 싱글 저장에만 활성화한다. 확인창의 기본 선택은 돌아가기이며 취소 시 변경하지 않는다. 확인 후 해당 저장을 삭제하면 이어하기가 비활성화된다. 저장 변경·삭제 실패 시 원본과 현재 Run을 보존한다. 협동·관리 저장·랭크 항복은 지원하지 않는다.

전투 준비 취소 중 저장이 실패하면 Host의 **저장 다시 시도**로 Map 복귀를 재시도한다. 기존 확정 저장을 보존하고 준비·저장 오류를 함께 표시한다. 실제 전투가 정리된 뒤 화면 갱신이 입력을 다시 켜지 않으며, Map 전환 통지 중에도 새 전투를 중복 생성하지 않는다. 파티 설정은 Content Browser의 제작 파티 에셋에서 **Validate Assets**로 미리 검사할 수 있다.

개발용 협동: 독립 게임 창 2개에서 **MainMenu → 게임 시작 → 멀티플레이**를 연다. 첫 창은 2인 방 생성, 두 번째는 `127.0.0.1:7777`로 참가한다. 각자 준비 완료 후 Host가 시작하고 첫 전투 노드를 선택한다. 창 실행 명령은 [멀티플레이 개발 실행 참조](Docs/MULTIPLAYER.md#11-개발-실행-참조)를 따른다.

별도 Steam 480 개발 모드의 방 검색은 Steam 친구별 세션을 조회한다. 실제 2대 PC 접속·인증은 준비 대기다. Snapshot에는 같은 버전·진행 단계·태그 조건의 균등 후보 선택 API를 추가했으며 기존 Run의 고정 상대는 유지한다. 온라인 게시·정본 저장·MMR은 미연결이다. [구현·검증 범위](Docs/HISTORY.md#9-25-2026-10-07-todo-권장안의-로컬-구현)

## 개발 환경

- 엔진: Unreal Engine 5.8 (설치 확인: 5.8.3), C++, GAS, CommonUI, UMG. 게임·Editor 타깃은 `BuildSettingsVersion.V7`·`EngineIncludeOrderVersion.Unreal5_8`을 사용한다.
- 모듈: `Source/ProjectA`는 런타임, `Source/ProjectAEditor`는 에셋 도구·에디터 테스트. Editor 의존성은 런타임 모듈에 추가하지 않는다.

- UI: [에셋 도구](Source/ProjectAEditor/Scripts/README.md), [위젯·JSON 명세](Docs/UI_README.md).

## 작업 규칙

아이템·적 유닛·스킬·효과 확장은 GAS·GameplayTag 기반 분류와 데이터 기반 확률 가중치를 원칙으로 한다. 라운드 계획·AI·발동·피격의 태그 조건과 GAS 효과 실행을 연결하며 콘텐츠 가중치 확장·최종 태그 계층·수치는 별도 기획 대상이다. 세부 기준은 [AGENTS.md](AGENTS.md)의 데이터 확장 원칙을 따른다.

[AGENTS.md](AGENTS.md)를 기준으로 한다. 작동 테스트는 사용자 수행이 원칙이며 명시적 실행 요청에 한해 Codex가 수행한다. Visual Studio는 자동 실행하지 않는다. 커밋 시 이번 작업 외의 기존 추가·수정·삭제도 함께 검토·검증하여 `[codex]` 제목과 한글 본문으로 커밋·push한다. 사용자가 명시적으로 제외한 항목과 Git이 무시하는 생성물은 포함하지 않는다. 완료 후 미커밋 변경 여부를 확인하고 결과·문제·남은 확인 사항을 간략히 안내한다.

TODO의 우선순위·구현·코드 검토·컴파일·문서·커밋/push는 Codex가 일괄 담당한다. [TODO](Docs/TODO.md)의 미정 정책은 사용자가 확정한 뒤 구현하며, 선택 체크와 구현·작동 검증 완료는 구분한다. 로컬 파일의 내용만 작업 범위로 읽고 별도 복사본과 원본의 자동 동기화는 가정하지 않는다.
