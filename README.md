# ProjectA

Unreal Engine 5.8 기반의 파티·Grid 턴제 전투 프로젝트. UI 중심의 Run 진행, 파티 빌드 성장, 상대 Snapshot을 활용한 Async PvP와 최대 4인 Co-op을 목표로 한다.

기본 콘텐츠 교체의 적용 범위·기존 에셋 매핑은 미정이며 도입 계획은 [TODO 6절](Docs/TODO.md#6-신규-에셋-선정과-도입)을 따른다. 기본 Run은 유지하고 보유 팩으로 [지하 던전](Docs/PROJECT_PLAN.md#4-3-지하-던전-비교-레벨)과 [초원·숲·사막·얼음·여름 환경](Docs/PROJECT_PLAN.md#4-4-환경-비교-레벨)의 별도 비교 맵을 구성한다.

새 싱글플레이 Run은 **인카운터 3회 → 몬스터 PvE → 인카운터 3회 → 로컬 Snapshot 전투**를 10회 반복한다. 정상 완주 기준 인카운터 60회·PvE 10회·Snapshot 10회이며 각 인카운터는 후보 3개 중 하나를 선택한다. 고정 편성·성장·보상은 조정 가능한 개발 시험값을 사용한다. 기존 2/10전투 저장과 개발 협동의 10전투·9상점 경로는 유지한다. 온라인 Async PvP 연결은 후속 작업이다. [목표와 현재 구현](Docs/GAME_DESIGN.md#2-목표-run과-현재-구현)

성장·재화 획득 경로는 **PvE 보상과 인카운터**다. 새 싱글 Run에 회복소·부활소·소모품상점을 연결하고 전투 중 본인 생존 캐릭터의 회복 소모품을 지원한다. **Run 종료 시 MMR만 반영**하는 정책이며 실제 온라인 정산은 미구현이다. 성장·재화·장비·스킬·소모품은 다음 Run에 이월하지 않는다. [성장·경제·보상 정책](Docs/GAME_DESIGN.md#2-1-성장경제보상과-run-종료)

장비는 **무기 2칸·투구·장갑·신발·갑옷·목걸이 각 1칸·반지 2칸**으로 구성한다. 직업별 시작 무기·방패를 장착하고 상점 페이즈에서 인벤토리와 장비창 사이에 드래그하여 교체한다. 양손 무기는 두 손을 점유하며 능력치·장비 부여 스킬은 후속 구현이다. [장비 슬롯과 스킬](Docs/GAME_DESIGN.md#2-2-장비-슬롯과-장비-부여-스킬)

기본 전투는 [라운드 계획·시간차 자동 전투](Docs/GAME_DESIGN.md#8-라운드-계획과-시간차-자동-전투)다. 전투 속도는 현재 민첩과 1:1이며 각 라운드의 행동을 함께 계획하고 속도 1 차이당 0.1초 후 실행한다. 실제 접근·복귀, 유닛 이동 비충돌, [서버의 공격 충돌 판정](Docs/GAME_DESIGN.md#8-5-발동과-피격)을 사용한다. 공격은 실제 피격체에 닿아야 하며 별도 명중 확률·성공 슬롯 판정을 사용하지 않는다. 기존 순차 턴 실행은 제거했으며 기존 Blueprint 참조용 클래스·프로퍼티만 남긴다. 확정 전투 규칙과 Ready 경계 저장·복구 데이터는 구현했으며 자동화 검증 범위는 [재검증 이력](Docs/HISTORY.md#9-15-2026-10-01-todo-재검증과-구현-이관)을 따른다. 강제 종료 후 전투 Actor·화면 재구성은 당시 검증 범위에 포함되지 않았다.

메인메뉴의 **게임 시작 → 싱글플레이**는 캐릭터 생성 후 새 목표 Run으로, **게임 시작 → 멀티플레이**는 같은 PC·LAN의 2~4인 개발용 방으로 연결한다. 기본 멀티는 IPv4 주소 참가·준비·Host 시작과 참가자별 궁수 한 명 배정을 유지한다. Win64 Development 게임에서 `-CustomConfig=SteamDev -ProjectASteamDev`를 함께 지정하면 별도 Steam 480 연결 확인 패널을 사용한다. 기본 설정은 Steam 비활성이며 이 시제품을 온라인 Run·중앙 저장·관전·MMR 완료로 취급하지 않는다. 실제 2PC 검수는 준비 대기다. [실행 조건](Docs/MULTIPLAYER.md#11-개발-실행-참조)

캐릭터 생성 버튼은 슬롯의 기본 직업·남자 몸체·자동 이름으로 즉시 생성하고 파티 화면을 유지한다. 이름·직업·몸체의 상세 편집은 생성된 카드의 **Edit**에서 연다. 직업은 **전사 → 마법사 → 궁수 → 도적** 순서이며 현재 시작 능력치는 모두 HP 100·힘/민첩/지능 각 10이다. 직업별 최종 밸런스·공격 스킬은 별도로 작성한다. 이전 테스트 직업이 들어 있는 저장은 원본을 보존하고 거절하며 임의로 새 직업에 대응하지 않는다. DA 폴더 이동의 경로 호환과 직업 콘텐츠 호환은 별개다.

기본 아군은 민첩 10·전투 속도 10, 일반 테스트 적은 힘/민첩/지능 각 5·속도 5다. 적 HP 150·AP 2와 0.5초의 행동 시작 차이는 유지한다. 근접 접근·복귀는 [초기 민첩 튜닝](Docs/GAME_DESIGN.md#8-4-공격-접근과-복귀)으로 기본 아군 350·적 262.5cm/s를 사용한다(`MoveSpeed=700` 기준). Snapshot과 소수 민첩도 같은 규칙을 적용한다. 투사체는 민첩과 별도로 공통 비행 배율 `projecta.Combat.ProjectileSpeedScale=0.5`를 적용하며 기본 700→350cm/s로 감속한다. 수명은 역비례 보정하여 최대 이동 거리를 유지한다.

네 직업의 **Edit 편집창**에서 ◀·▶ 버튼으로 **남자·여자** 몸체를 선택한다. 남자는 원본 `SKM_Primitive_Charater_01_Body`, 여자는 `SKM_Primitive_02_Body`를 사용하며 기본값은 남자다. 미리보기 영역을 **우클릭한 채 좌우로 드래그**하면 캐릭터가 회전한다. 실시간 미리보기·초기화·저장·취소를 지원하고 선택은 전투·이어하기에 유지된다. ROG 의상 선택·착용과 마법사의 기본 스태프 표시는 제거하고 103개 의상 항목·스태프 원본은 향후 아이템용으로 보존한다. 기존 래그돌은 유지하며 모델·텍스처는 복제하지 않는다. 현재 화면·입력 검수는 [최신 실행 이력](Docs/HISTORY.md#9-17-2026-10-04-ue-58-todo-실행-검수)을 따른다.

캐릭터 생성 화면의 초기 카메라 X는 `-500`, 네 슬롯 앵커 Yaw는 `90°`다. 실제 화면 투영으로 네 몸체의 가로 여백을 확보하고 화면 크기·파티·외형 변경 시 초기 카메라 기준에서 다시 맞춘다. 상세 편집은 선택한 몸체를 확대하며 종료 후 파티 구도를 복원한다. 엔진 Details 설정은 [프리뷰 설정](Docs/UI_README.md#4-화면프리뷰)을 따른다.

1. UE 5.8에서 `ProjectA.uproject`와 `/Game/User_JeHoon/LEVEL/Core/MainMenu`를 연다.
2. 게임 시작 → 싱글플레이 → 캐릭터 1~4명 생성 → 직접 조작할 1명 선택 → Start Game → 첫 Combat 노드를 선택한다.
3. 전장에서 **적 한 번 클릭 → 하단의 장착 스킬 버튼 클릭 → 준비 완료** 순서로 행동한다. 스킬 버튼을 누르면 해당 계획이 적용된다. **스킬을 선택하지 않고 준비 완료하면 행동 비용 없이 턴을 넘긴다.** 선택한 스킬은 **스킬 선택 취소**로 해제할 수 있다. 위치를 바꾸려면 **이동 예약 · SAP 1 → 강조된 아군 빈칸 한 번 클릭**으로 예약한다. 스킬 없이 이동만 예약할 수 있으며 이때 SAP 1만 소모한다. 준비 전까지 이동·자원 소모는 없다. 모두 준비하면 SAP 이동을 먼저 끝내고 선택한 AP 행동을 실행한다. AI 동료의 계획은 서버가 결정하며 직접 조작 캐릭터가 사망하면 생존 AI만으로 자동 진행한다.

아군·기본 적·Snapshot 상대 모두 기존 래그돌·사망 충격량을 사용한다. 사망 애니메이션 분기는 제거하며 서버의 타일 해제·행동 취소·사망 복제는 유지한다. [신규 에셋 도입](Docs/TODO.md#6-신규-에셋-선정과-도입)

처음 실행한 MainMenu의 Options에서 화면과 그래픽을 설정한다. 항목 선택 후 적용하며, 해상도·화면 모드가 바뀌면 15초 안에 확인해야 저장된다. 취소·시간 초과·확인 전 화면 닫기는 적용 전 상태로 복원한다. 테두리 없는 전체 화면은 바탕 화면 해상도를 사용한다. 품질·VSync만 바꾸면 적용 시 바로 저장한다. 상세는 [설정 UI](Docs/UI_README.md#8-시작-메뉴-설정)를 따른다.

Gameplay 좌측 상단에는 현재 개인 보유 골드를 표시하며 구매·회복·리롤 저장 후 갱신한다. `I`는 장비 슬롯·개인 골드·보유 스킬·아이템 목록과 수량을 함께 열고 닫으며, `Esc` 또는 `O`는 설정을 연다. 설정에서 다시 `Esc` 또는 `O`를 누르면 닫고 화면 변경 확인 중에는 먼저 복구한다. 창이 열린 동안 배경 전장 입력을 막는다. 단축키 확인은 독립 게임 창에서 진행한다. 기본 PIE의 `Esc`는 에디터 실행 종료가 우선한다. [단축키 상세](Docs/UI_README.md#8-2-gameplay-인벤토리와-설정-단축키)

공통 외형은 native `UDemonicUITheme`이 기존 `/Game/DemonicUI` 텍스처를 참조하여 적용한다. C++ 빌드 후 UE를 재시작하면 기존 Designer 위젯과 native 컨트롤에 반영되며 WBP·JSON 재생성은 필요하지 않다. 원본 에셋은 수정하지 않는다. 적용 범위는 [UI_README 9절](Docs/UI_README.md#9-demonicui-공통-테마)을 따른다.

UI는 1920×1080을 기준으로 뷰포트에 맞춰 같은 비율로 확대·축소한다. 전투는 상단 라운드 요약·우측 대상 정보·좌하단 파티 카드·하단 중앙 장착 스킬·우하단 이동/준비로 나누고 중앙 전장에서 유닛·타일을 직접 선택한다. 카메라는 고정 16:9 검은 띠를 만들지 않는다. 배율과 패널 크기는 [UI_README 10절](Docs/UI_README.md#10-공통-dpi와-전투-화면-배치)을 따른다.

일반 Continue는 지원되는 비전투 저장과 새 Ready 경계 저장을 복구한다. 준비 완료는 계획·전투 복구 상태를 저장한 뒤 확정하며 저장 실패 시 준비 완료·전투 시작을 막는다. 강제 종료 후에는 마지막 저장 계획·Ready·유닛·자원·배치에서 다시 진행하고 비용을 중복 차감하지 않는다. 시전·투사체의 중간 시점 복원은 지원하지 않는다. 이전 순차 Combat 저장은 파일을 보존하고 거절하며 협동·관리 저장은 명시적 재개 절차를 사용한다. [저장 계약](Docs/PROJECT_PLAN.md#5-저장과-멀티플레이-연결-경계)

이어하기 옆 **항복하기**는 현재 이어갈 수 있는 일반 싱글 저장에만 활성화한다. 확인창의 기본 선택은 돌아가기이며 취소 시 변경하지 않는다. 확인 후 해당 저장을 삭제하면 이어하기가 비활성화된다. 저장 변경·삭제 실패 시 원본과 현재 Run을 보존한다. 협동·관리 저장·랭크 항복은 지원하지 않는다.

전투 준비 취소 중 저장이 실패하면 Host의 **저장 다시 시도**로 Map 복귀를 재시도한다. 기존 확정 저장을 보존하고 준비·저장 오류를 함께 표시한다. 실제 전투가 정리된 뒤 화면 갱신이 입력을 다시 켜지 않으며, Map 전환 통지 중에도 새 전투를 중복 생성하지 않는다. 파티 설정은 Content Browser의 제작 파티 에셋에서 **Validate Assets**로 미리 검사할 수 있다.

개발용 협동: 독립 게임 창 2개에서 **MainMenu → 게임 시작 → 멀티플레이**를 연다. 첫 창은 2인 방 생성, 두 번째는 `127.0.0.1:7777`로 참가한다. 각자 준비 완료 후 Host가 시작하고 첫 전투 노드를 선택한다. 창 실행 명령은 [멀티플레이 개발 실행 참조](Docs/MULTIPLAYER.md#11-개발-실행-참조)를 따른다.

## 작업 규칙

아이템·적 유닛·스킬·효과 확장은 GAS·GameplayTag 기반 분류와 데이터 기반 확률 가중치를 원칙으로 한다. 라운드 계획·AI·발동·피격의 태그 조건과 GAS 효과 실행을 연결하며 콘텐츠 가중치 확장·최종 태그 계층·수치는 별도 기획 대상이다. 세부 기준은 [AGENTS.md](AGENTS.md)의 데이터 확장 원칙을 따른다.

[AGENTS.md](AGENTS.md)를 기준으로 한다. 작동 테스트는 사용자 수행이 원칙이며 명시적 실행 요청에 한해 Codex가 수행한다. Visual Studio는 자동 실행하지 않는다. 커밋 시 이번 작업 외의 기존 추가·수정·삭제도 함께 검토·검증하여 `[codex]` 제목과 한글 본문으로 커밋·push한다. 사용자가 명시적으로 제외한 항목과 Git이 무시하는 생성물은 포함하지 않는다. 완료 후 미커밋 변경 여부를 확인하고 결과·문제·남은 확인 사항을 간략히 안내한다.
